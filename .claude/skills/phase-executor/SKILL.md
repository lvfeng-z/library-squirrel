# Phase Executor Skill

## 触发时机

用户要求执行一份含「阶段清单」的计划（`../library-squirrel-docs/plan/<x>.md`）时。若计划缺阶段清单，先按 `../library-squirrel-docs/plan/_CONVENTIONS.md`「阶段清单」节补齐再执行。

## 核心原则

主会话是**编排者，不是执行者**。每个阶段的实施（读文件 / 改代码 / 跑验证）都发生在子代理自己的上下文里；**主会话绝不把阶段涉及文件 Read 进自己上下文**——这是防止上下文膨胀的第一铁律。

## kickoff 提示词（方案定稿时，方案会话产出）

方案会话在用户选择「执行」时不直接开工，而是输出实施会话启动提示词，交用户新开会话执行。模板与纪律：

- 第一行：`执行 ../library-squirrel-docs/plan/<方案名>.md 的阶段清单（/phase-executor）`
- 补充 ≤3 行**未落盘**的口头裁决（已写入方案「已裁决」段的不再重复）
- 总长 ≤10 行；凡方案文档已有的内容一律指向、不复制——复制即重建胖前缀，分会话收益归零

## 执行流程

### 1. 读取阶段清单

读计划「阶段清单」，解析每阶段的 目标 / 涉及文件 / 验证命令 / 退出标准 / 依赖 / 模型建议。构建执行序：依赖链串行、独立阶段并行。

### 2. 逐阶段委派子代理

对每个阶段用 Task 工具 spawn 子代理。任务提示**只含**：

- 阶段规格（目标 + 涉及文件 + 验证命令 + 退出标准）
- 上一阶段的交接摘要（来自返回结果或手记文件）
- 项目最小上下文（相关 `CLAUDE.md` / `.claude/rules/` 的**路径**，让子代理自取；禁止把大段文档复制进提示）

子代理提示末尾必须要求：

- 只读「涉及文件」列出的文件；需要探索时用 Grep 定位，**禁止整仓库扫描**
- 验证只用阶段指定的命令，**禁止全量构建**
- 结束时返回交接摘要（≤5 行：改了哪些文件 / 动了什么逻辑 / 遗留与风险 / 验证结果；**引用的代码符号须附 `file:line` 锚点——符号名≠锚点**，无锚点的符号引用视为未核验）

### 3. 核对与交接

子代理返回后：

- 核对退出标准；必要时主会话复跑**阶段指定的小范围验证命令**（禁止全量）
- 核对交接摘要的锚点完备性：摘要引用的代码符号缺 `file:line` 锚点时，视同未核验——不将无锚点论断传递给下游阶段或用户（对齐 `../library-squirrel-docs/plan/_CONVENTIONS.md` 审查摘要契约，将覆盖面从方案文档扩展到交接链）
- 把交接摘要压缩为 ≤3 行，写入主会话或阶段手记文件，供下阶段使用
- 主会话把交接摘要**加工为分析结论/裁决依据**输出前，必须读锚点片段核码验证语义，或在输出中显式标注「未核码推断」——防上下文膨胀的编排纪律不豁免裁决支持的核码义务（执行编排与分析支持的可靠性要求不同档；先例：命名与语义失配的谓词经摘要转述被放大为自洽错误叙事）
- 独立阶段：同时并行 spawn 多个子代理，各自独立上下文，互不污染

### 4. 汇总

全部阶段完成后，向用户汇总：各阶段结果 + 交接摘要 + 整体验证状态。有未满足退出标准的阶段，明确标出并停下询问，不自行继续。

## 防上下文膨胀铁律

- 主会话上下文只保留：计划路径、阶段清单索引、每阶段 ≤3 行交接摘要、总体状态；其余一律在子代理里。
- 禁止把子代理返回的大段 diff / 完整文件内容留在主会话——只要摘要。
- 子代理单阶段超过 ~200 轮仍未完成时，中止该阶段，提示用户该阶段过大、需按 `_CONVENTIONS.md` 重划。
- 「模型建议」为便宜模型/本地模型的阶段：在支持多模型路由的 harness（如 DeepSeek Harness）下绑定对应模型（如 MiniMax），不消耗主模型配额；Claude Code 下仍用当前模型，收益仅在上下文隔离。
