# 外部 AI 操作接口接入指南

本指南面向**在自己机器上部署了 AI 代理运行时**（harness，如 DSH）的用户：开启本软件的「外部接口」后，同机的智能体可以经本机回环 HTTP JSON 接口程序化操作本软件——查询作品库、创建与控制下载任务。人用图形界面、机用接口，两者汇入同一服务层。

接口只监听 `127.0.0.1`，不对局域网暴露；默认关闭，需在设置页显式开启。本软件只对接口的正确性负责，智能质量归 harness 与所用模型。

## 一、启用与关闭

在设置页找到「外部接口」区块（默认关）：

| 控件 | 作用 |
| --- | --- |
| 「外部接口」开关 | 开启 = 起回环监听 + 写发现文件；关闭 = 停监听 + 删发现文件 |
| 「接口 token」行 | 展示当前 token，可「复制」；「重置」生成新 token（旧 token 立即失效） |
| 「监听端口」 | 固定端口，填 `0` = 每次开启由系统随机分配；保存设置后即时换绑 |
| 「外部操作记录」 | 只读列表，分页查看智能体经接口调用本软件的问责记录（见第七节） |

- 开启成功后界面提示监听地址（形如 `127.0.0.1:52341`）；关闭后该地址立即不可达。
- 端口固定值被占用时监听启动失败：设置页以附注提示失败原因，开关保持开启态，改一个端口再保存即重试。
- 应用重启后按设置自动恢复：上次开着则启动即起监听并重写发现文件。

## 二、发现文件契约

接口开启期间，应用在**用户数据目录**下维护发现文件 `api-access.json`，外部智能体据此寻址与鉴权。文件即产品契约，含版本字段供后续演进。

**位置**（用户数据目录的解析优先级，高到低）：

1. 启动参数 `--data-dir <绝对路径>`；
2. 环境变量 `LS_DATA_DIR`；
3. Windows 默认 `%LOCALAPPDATA%\library-squirrel\`（非 Windows 平台无常量默认位置，须用上述参数或环境变量指定绝对路径）。

即默认路径为 `%LOCALAPPDATA%\library-squirrel\api-access.json`。

**内容**：

```json
{
  "enabled": true,
  "port": 52341,
  "token": "…（32 字节随机数的 URL 安全 base64，43 字符）",
  "version": "1"
}
```

| 字段 | 含义 |
| --- | --- |
| `enabled` | 恒为 `true`：接口未启用时文件不存在，而非写 `false` |
| `port` | 实际监听端口（端口设置 `0` 时为系统分配值） |
| `token` | 鉴权凭据（Bearer token），与设置页展示值一致 |
| `version` | 发现文件契约版本，用于向后兼容判定 |

**生命周期**：开关切换即写删文件；token 重置、固定端口换绑即重写文件。多个应用实例（不同数据目录）各自独立端口与 token，发现文件各归各的数据目录。

**读取建议**：每次会话开始时读一次，以文件为准寻址鉴权；不要把 token 长期写死进自己的配置文件（用户随时可能重置）。

## 三、鉴权

- 除 `GET /api/health` 外，全部端点都要求请求头 `Authorization: Bearer <token>`。
- 缺少 token、非 Bearer 形态、token 错误一律返回 `401`（响应体为同构失败信封，`msg` 为用户可读原因）。
- token 获取：设置页「接口 token」行复制，或读发现文件；重置：设置页「重置」按钮——**换新即旧 token 立即失效**，已接入的智能体需同步更新。
- 可选请求头 `X-Client-Label`: 调用方自报的归属名（如智能体名称），原样落进操作记录行，便于事后问责。它是**自报标识、非鉴别凭据**——token 才是鉴权凭据。

## 四、端点与响应信封

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 免鉴权探测：仅回启用态与应用版本 |
| `GET` | `/api/manifest` | 能力清单：操作目录 + 参数摘要（机器可读，接入的单一来源） |
| `POST` | `/api/op/{operationId}` | 统一操作调用：请求体为该操作的参数 JSON 对象 |
| `GET` | `/api/journal?cursor=&limit=` | 事件记账增量查询（游标消费领域变化史） |
| `GET` | `/api/oplog?cursor=&limit=` | 外部操作记录增量查询（问责账，见第七节） |

除探测端点外的全部响应复用同一信封（`success` / `msg` / `data`）：

```json
{ "success": true, "msg": "success", "data": { } }
```

- `success=false` 即**纯失败**：操作未达成，`msg` 为用户可读原因，`data` 无意义。
- 一切非失败的业务分支态（候选冲突、批量逐条结果等）住 `success=true` 的 `data` 载荷内，由载荷自带标志表达——**不要用 `msg` 做分支判定**，判定业务态一律看 `data` 中的标志字段。

HTTP 状态码语义：

| 状态码 | 含义 |
| --- | --- |
| `200` | 请求已被处理：操作成败由信封表达（失败也是 200 + 纯失败信封） |
| `401` | 鉴权失败（无 token、非 Bearer 形态、token 错误） |
| `404` | 操作标识缺失或未注册 |
| `413` | 请求体超过大小上限 |
| `503` | 分发层并发已达上限（快速失败，可稍后重试） |

请求防护：单请求体上限 1 MiB，同时进入操作调用的请求数有上限（超限快速失败），读/写超时按常规 HTTP 服务端设置。

**探活语义**：应用未运行或接口未开启时无监听，连接直接拒绝；请求能到达即说明接口已启用（`/api/health` 恒回 `enabled: true`）。因此外部侧的「接口不可用」判定 = 连接失败。

## 五、操作目录：以能力清单为单一来源

接入时先读 `GET /api/manifest`，按其中的操作标识、描述与参数摘要生成你的调用表——**不要手工抄录或硬编码操作清单**，产品迭代会新增操作与参数：

```bash
curl -s -H "Authorization: Bearer $LS_TOKEN" http://127.0.0.1:$LS_PORT/api/manifest
```

清单含三部分：

- `operations`：注册表内全部操作（`id` / `desc` / `params`），调用形态为 `POST /api/op/{id}`，请求体是该操作的参数 JSON 对象（`params` 逐项给出参数名、类型、是否必填与缺省语义）；
- `endpoints`：注册表外的固定端点（探测、清单自身、`/api/journal`、`/api/oplog`）；
- `operationEndpoint` / `version` / `appVersion`：调用端点的路径模板与契约版本。

当前操作面按族划分（**具体清单与参数一律以 manifest 为准**）：

- **只读**：作品搜索与详情、任务分页/详情/状态、任务运行态快照与树状态、插件分页/状态、存储位置（程序目录/用户数据目录/资源库目录的绝对路径，供需要读取作品文件的场景使用）、作品资源行（含各角色 store 的相对路径）、记账增量查询。
- **写入**：按 URL 创建任务、任务树启动/暂停/恢复/重试/强停、覆盖确认（单个与批量）。

调用示例：

```bash
curl -s -X POST "http://127.0.0.1:$LS_PORT/api/op/search.work" \
  -H "Authorization: Bearer $LS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Client-Label: my-agent" \
  -d '{"pageNumber":1,"pageSize":10,"conditions":[{"type":3,"value":"某作者"}]}'
```

## 六、消歧与覆盖确认：全部非阻塞

创建与控制任务是**非阻塞**的：每个调用立即返回结果或一个待处理态，不会占住连接等人操作；确认既可由用户在图形界面完成，也可由外部侧经 API 完成，两个入口等效，汇入同一套持久状态机。

前置提醒：`task.createByURL` 的**业务成败也住在 `data` 载荷内**——`HTTP 200` + `success=true` 只说明调用被处理了，建任务是否成功要看 `data.succeed`（失败时 `data.msg` 给出原因，如 URL 不受支持、所有插件均未成功），能否处理要看 `data.conflict`。外部侧需要识别两种分支态：

**1. 建任务消歧（最易踩的坑）**

一个 URL 可能被多个插件扩展点声明为可处理。此时 `task.createByURL` 返回 `success=true`、`data.conflict=true`，`data.conflictCandidates` 给出候选清单（**首位即默认选中项**，每项含 `pluginPublicId` / `pluginName` / `extensionId`），并且**没有调用任何插件**。外部侧应识别 `conflict` 后带显选键重发同一操作：

```json
{ "url": "…", "chosenPluginPublicId": "…", "chosenExtensionId": "…", "remember": true }
```

- `chosenPluginPublicId` + `chosenExtensionId` 两键联合定位一个候选（两键均空 = 未显选）；若给出的显选键不在本次候选集内，操作以**纯失败信封**（`success=false`）收口，需重新读候选清单；
- `remember=true` 时路由成功会落一条消歧记忆，同站点同候选组合的后续建任务静默直路由，不再返回冲突载荷。

**2. 覆盖确认（重复作品）**

建任务命中已入库的重复作品时，任务建成并**停留在等待确认态**（响应仍是成功信封）。外部侧经 `task.status` / `taskManager.treeState` / `taskManager.snapshot` 感知到该状态后，用覆盖确认操作解除：

```json
{ "taskId": 123, "action": "replace" }   // 或 "skip"，批量用 taskIds 数组
```

`action=replace` 表示替换重复作品继续执行，`skip` 表示跳过；不在等待确认态的任务不可确认（单个确认会报错，批量确认静默跳过）。图形界面的确认弹窗与这两个操作等价。

**3. 插件侧交互等待**

任务执行期插件可能弹出交互（如下载形态问答、扫码登录），任务停留于等待输入态。这不阻塞 HTTP 调用——外部侧经任务状态查询感知停留，等待用户在图形界面完成交互即可。

## 七、外部操作记录与问责

每次经操作分发层的外部调用都落一行记录（操作标识、脱敏参数摘要、成败、耗时、调用方自报标签），用于事后问责。它是**被动记录，没有任何事前把关职能**；把关时刻是任务状态机里的非阻塞确认态（第六节）。

- 机器查询：`GET /api/oplog?cursor=&limit=`，游标增量返回——信封 `data` 为 `Entries`（记录行，行内字段 `id` / `createTime` / `operation` / `params` / `success` / `clientLabel` / `durationMs`）、`NextCursor`、`HasMore`、`CursorExpired` 四个字段（注意是**大写开头的字段名**）；`cursor` 传上次的 `NextCursor` 即增量消费，`cursor=0` 从头消费，`CursorExpired=true` 表示消费位置已被轮转裁掉，需从留存起点（`cursor=0`）重读并接受缺口。`/api/journal` 返回同一套游标字段。
- 人查：设置页「外部操作记录」只读列表（最新在前，分页）。
- 脱敏：URL 类参数只落协议 + 主机 + 路径，查询串不落库（只记存在与字符数），防凭据类参数进入记录与界面展示；摘要超长截断。
- 保留：TTL 365 天、容量 20 万行，超出裁最旧——**记录不是永久档案**，长期留档请自行导出（游标休眠近一年不过期，即智能体可触及约一年的历史）。
- 落账口径：探测、能力清单、`/api/oplog` 这三个固定端点不落账；经操作分发的调用（含 `/api/journal` 与全部 `POST /api/op/{id}`）落账。

## 八、信任边界声明（token 防线定位）

**如实声明**：token 的定位是**防误触、防跨用户、提供归属标识**，不是防恶意进程的安全屏障。同一台机器上的同一用户进程可以读取发现文件并取到 token。请按以下边界使用：

- 接口只绑 `127.0.0.1`，局域网与互联网不可达；
- 接口能力以当前用户权限运行，与图形界面操作同权（包括删除、替换、强停等破坏性操作）；
- 调用方经 `X-Client-Label` 自报的标签只是归属提示，不是可鉴别身份；
- 不与他人共用系统账户运行本软件；不需要接口时关闭开关（同时删除发现文件，token 不再泄漏在磁盘上）；
- 怀疑 token 外泄时在设置页重置——旧 token 立即失效。

## 九、常见问题排查

| 现象 | 原因与处置 |
| --- | --- |
| 连接被拒绝 | 应用未运行，或设置页「外部接口」开关为关（关闭即停监听并删发现文件） |
| 找不到 `api-access.json` | 接口未开启；或应用以 `--data-dir` / `LS_DATA_DIR` 指定了别的数据目录 |
| `401` | token 缺失、非 Bearer 形态或已失效（被重置过）——重新读发现文件或设置页复制 |
| `404` | 操作标识写错或该操作在当前版本未注册——以 `GET /api/manifest` 为准 |
| `503` | 瞬时并发超过上限，稍后重试；确认自身没有在无节制地并发调用 |
| 调用成功但任务不动 | 任务可能停在等待确认态或等待插件交互（第六节），经任务状态查询确认 |
| 设置页记录列表为空 | 只统计经接口的调用；探测、清单、记录查询自身不落账 |
