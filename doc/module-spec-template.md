# 模块说明模板

> **用途**：每个**需文档化的模块**在其目录下维护 `README.md`（如 `backend/taskManager/README.md`），遵循本结构。
> **范围**：只写"是什么 / 提供什么 / 依赖谁"，**不写**编码规则（见 `.claude/rules/`）和变更历史（见 `../library-squirrel-docs/plan/`）。
> **篇幅**：单模块控制在 **80 行以内**，宁缺毋滥——能让人不读代码就判断"是否来对了地方"即可。

## 结构骨架

```
# {模块名} 模块说明

## 一句话职责
{1-2 句。开头即回答"这个模块解决什么问题"。}

## 边界（可选）
{与相邻模块的区别，回答"为什么不放到 X"。仅当模块易混淆时写，否则整节省略。}
- 与 {模块}：{区别}

## 对外接口（Handler）
{分组列出暴露给前端的 Wails Bind 方法，来自 handler.go。
 仅 repository、无 Handler 的模块改为说明"被谁调用"。}
| 方法 | 作用 |
| --- | --- |
| ... | ... |

## 核心概念
{内部关键类型 / 状态机 / 枚举，点到为止。}

## 依赖关系
- 依赖：{通过接口注入的依赖}
- 被依赖：{哪些模块 / 前端依赖本模块}

## 关键设计（可选）
{非显而易见的设计决策、约束、易踩坑点。没有则整节省略。}
```

## 填写要点

- **准确性优先**：接口表直接来自代码，模块行为改动后必须同步本文件。
- **命名渊源**：模块名无法望文生义时（缩写、前缀、自造词），在"一句话职责"或"边界"中解释。
- **避免重复**：编码规则归 `.claude/rules/`，变更记录归 `../library-squirrel-docs/plan/`，本文件只描述**当前状态**。
- **何时写**：核心复杂模块、命名不直观模块。简单 CRUD 模块（<300 行且职责单一）无需写。

## 维护机制

修改模块行为时，同步更新该模块 `README.md`。里程碑节点由 Claude 主动提示是否需要同步（见 `CLAUDE.md` 交互规则）。
