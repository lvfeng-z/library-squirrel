# 分享功能总体方案（远程托管分享 · P2P 盲转中继）

> 对应 todo#51「分享功能，考虑法律风险」。本文为总体思路与架构方案，含阶段清单，供审查与排期。
> 决策过程：2026-08-26 与用户多轮对齐——纠正两处根本误解（分享内容是**用户本地资源**而非原站链接；风险是**平台责任牵连**而非著作权侵权）；架构经历两次重定——初定「自托管优先·纯HTTP」被用户质疑「无人为分享自购服务器并部署服务」推翻，重定为「P2P·盲转中继」：**分享方 App 即内容源，作者只运营轻量盲转中继管道（不存内容）**。

**已定决策（2026-08-26 用户拍板）：**
- 决策1：**架构方向 = P2P·盲转中继**——分享方 App 即内容源（保持运行），经**出站隧道**连作者轻量盲转中继；作者**不存内容**，只做管道 + 会话 + 访问控制。推翻初版「自托管优先·纯HTTP」
- 决策2：**许可策略 = 分许可**——客户端维持 GPL-3.0，中继服务用 AGPL-3.0（若开源供社区自建中继分流，AGPL 保证改动披露，见第6节）
- 决策3：**收件人形态 = Web 落地页 + 页内拉起应用**——收件人是其他 LibrarySquirrel 用户；链接打开落地页（预览 + 来源 + 「打开应用」按钮）→ 拉起 App → 拉取 → 回灌导入
- 决策4：**访问控制 = 加密链接 + 可选密码/有效期 + 会话级溯源**（中继记录会话来源，不记内容）
- 决策12（方向已定）：**收件人拉取并入任务模块**——拉取建模为任务（source=中继+token、dest=回灌导入），复用 Pause/Resume/重试/断点续传；中断完整性由任务模型承接（部分拉取可断点续传，无需「中止清理/全部重来」）
- 决策10/16（方向已定）：**分享会话与收件人拉取均建模为任务（share-host / share-receive）**，具备任务模块全部标准能力（状态机/进度/Pause/Resume/断点续传/重试/面板）；**不要求自动重建**（用户确认为误读「续传」）——分享会话重启后按任务标准语义（Paused 停留待手动恢复/重新分享），续传仅覆盖传输中断场景
- 决策5（方向已定）：**回灌导入排期 = 分两期**——一期：阶段1 中继 + 阶段2 导入（含 ManifestIngestor 能力）+ 阶段3 分享方发布 + 阶段5 合规；二期：任务接入 + 阶段4 深链拉起 + 收件人拉取闭环。风险最高的任务模块手术（G）隔离到二期
- 决策6（方向已定）：**溯源形态 = 会话级 + 设备绑定实例 ID**——中继记录 token + instance_id + IP + 时间，不记内容；支持举报封禁实例；**溯源与身份解耦**（会话记录不含身份字段，将来上账号只需加列、不改分享流——可逆设计，对齐「执行面/控制面难拆」教训）
- 决策7（方向已定）：**有效期 = 默认 7 天 + 自定义（可无限期）**——**语义为分享方显式失效控制机制，非可用性承诺**：分享方离线链接即断（与有效期无关）；有效期到点则中继显式拒绝（kill-switch 定时器）
- 决策8（方向已定）：**V1 传输路径 = 中继为主 + 预留直连升级位**——会话模型预留候选地址字段，V2 直连优先只翻偏好序
- 决策9（方向已定）：**预览元数据最小化 + 砍掉封面**——封面最可能直接含 R18/违法信息，中继展示图像即内容责任面；落地页仅文字元数据（标题/作品数/来源），不展示任何图像
- 决策11（方向已定）：**中继运营合规 = 六节清单 + 补充「快速精准处置违法信息能力」**——全线停止（kill 会话）或精准封禁（按实例/IP），处置在举报后即时生效
- 决策14（方向已定）：**E2E 加密全力保证正确性**——这是「无明知/中立管道」叙事的支柱，实现错误即防线崩塌；选型 + 测试为阶段1/3 硬验收项
- 决策15（方向已定）：**导入查重键 = site_id+site_work_id 联合；标签/作者按名称 find-or-create（同名复用）**——同名是否同一实体的人工裁决归 todo#10 合并功能（事后处置）
- 决策13（方向已定）：**中继托管地域 = 境内**——ICP 备案 + 等级保护，通知-删除/处置直接适用 → 避风港成立；代价=备案挂作者身份，但配合「快速处置」是正面姿态

**待决策：全部已定（决策1-16）——方案可进入执行准备。**

**自曝风险：**
- 风险1：~~**深链可行性未核验**~~ **已消除（2026-08-27 spike 结论=可行，见七·阶段4「深链 spike 结论」）**——Wails 3 alpha.98 单实例+URL 事件+protocols 构建配置均内置，NSIS 注册/卸载链模板已就位；残留仅浏览器确认框摩擦与 argv 解析校验等实施细节
- 风险2：**盲转中继的「盲」必须落实**——中继不存内容、但见会话元数据；内容须**端到端加密**（分享方加密、中继只转密文）否则「盲转」名不副实、作者有「明知」风险
- 风险3：分享产物格式演进——manifest 已版本化，但落地页专属元数据（预览图/摘要）需同步版本纪律，避免与回灌导入格式分叉
- 风险4：**分享方在线约束**——链接有效期依赖分享方 App 运行，关 App 即失效；App 需「分享进行中」状态管理（与下载任务同层）
- 风险5：溯源数据合规——会话级溯源记录属个人信息，中继需声明用途与留存期限
- 风险6：**中继带宽成本**——作者运营盲转管道承担流量成本；中继软件开源供社区自建为延后分流手段
- 风险7：**落地页预览元数据对中继可见**——落地页由中继服务，标题/封面/计数等元数据天然为中继所知（文件内容经端到端加密（E2E）不可读）；预览元数据范围需最小化以减小作者知识面（待决策9）
- 风险8：**分享方本机安全边界**——内容源本机暴露给匿名入站流：需防路径穿越/恶意输入/资源耗尽（并发拉取放大）；E2E 隧道须与本地其他服务隔离
- 风险9：**密钥随链接分发的攻击面**——链接即访问凭证，密钥随链接分发时**链接泄露=内容泄露**；密钥走链接 vs 走 App 握手两形态泄露面不同（见四·端到端加密）
- 风险10：**链接二次传播不可控**——高熵 token 无账号，泄露后作者与分享方均不知扩散范围；会话级溯源仅事后定位、无法事前阻断
- 风险11：**中继自身 DoS/滥用面**——匿名拨号、会话风暴、带宽耗尽未登记（风险8 仅覆盖分享方本机）；中继侧需限流（单会话流量上限/并发会话数上限）

## 一、定位与边界

**分享 ≠ 导出**：导出是把库打包为可移植产物（ZIP + manifest），面向「另一份库」；分享是把这份产物**面向人交付**——分享方将本地作品/作品集注册为一个分享会话，经出站隧道连到盲转中继，生成加密链接；收件人打开链接、拉起应用、经中继从**分享方本机**拉取内容并回灌导入。

**边界：**
- 分享**复用导出的数据面**（收集 + manifest 契约）与传输格式（manifest + 源文件），不自建搬运格式
- 分享的**收件人侧 = 回灌导入**（导出阶段4，未实现）——本期最大依赖，见待决策5
- **作者不存储内容**：中继只做盲转管道（加密字节瞬时转发），内容始终在分享方与收件人本机之间流动
- **本地导出功能保持独立**——分享是它之上的外向化，不改变导出自身

## 二、数据范围（分享什么）

选择单位与导出一致（沿用导出方案决策2「选择即单位」）：
- 选作品 → 分享这些作品，标签/作者完整连带
- 选作品集 → 分享作品集 + 成员作品递归闭包
- **全库分享禁止**（责任面 + 中继带宽双重约束，作为规模限制的对治）

分享产物 = 复用 manifest 契约 + 源文件（与导出同构）；会话注册时附加**落地页元数据**（预览图、摘要、来源声明），见风险3。

## 三、系统形态

```
分享方 App（自身即内容源，保持运行）
  → 打包（复用 export 数据面：manifest + 源文件）
  → 与中继建立出站隧道 → 注册分享会话 → 拿 token → 生成链接
  → 隧道保持在线，作为下载源（内容端到端加密，中继不可读）

中继服务（作者运营，会合 + 盲转兜底，可剥离部件）
  会话注册 / 出站隧道汇聚 / 盲转加密字节（不落盘、不解密）
  落地页 + 预览元数据（标题/封面/计数/来源；不持有文件内容）
  访问控制（token 校验 / 可选密码 / 有效期）
  会话级溯源日志（来源 IP/实例标识 + token + 时间）
  撤销（分享方撤销或举报 → 会话立即终止）
  V1 全流量管道；V2 直连优先后缩为「会合 + 残余兜底」（见四）

收件人（同为 LibrarySquirrel 用户）
  浏览器打开落地页 → 预览/来源确认 → 「打开应用」→ 深链拉起
  → App 校验链接 → 经中继连到分享方 → 拉取 manifest + 文件 → 回灌导入
```

## 四、关键设计

### 出站隧道（CGNAT 正解，frp 模式）
- 分享方 App **主动向外**连接中继建立反向隧道——**天然穿过运营商大内网**（CGNAT，运营商级网络地址转换，家宽普遍无公网 IPv4），不依赖公网 IP、无需「打洞」（frp（反向代理内网穿透工具）/ngrok（同类隧道服务）成熟模式）
- 单条出站隧道**复用 N 条并发虚拟流**——收件人无论数量多少，各自经中继拨同一 token、按流分发（「未知身份、未知数量」场景成立）
- 链接有效期即隧道存活期；分享方关 App → 隧道断 → 链接失效（风险4）
- **本机安全边界（风险8）**：分享方 App 成为匿名入站内容源——隧道只暴露预定协议路径、拒绝任意路径访问（防路径穿越）、限制并发拉取数（防资源耗尽/反射放大）、隧道流量与本地其他服务隔离

### 直连升级路径（V2，IPv6 前提）
- 国内 IPv6 政府驱动、普及快，直连越来越可行；但「有 IPv6 ≠ 可入站」（家宽默认封入站、仍存纯 IPv4/双栈用户、地址漂移）——直连不可独撑，中继兜底保留
- **V2 直连优先**：会话注册携带分享方**候选地址**（IPv6 全局地址 → IPv4 打洞），收件人先试直连、失败回落中继（Tailscale（组网软件）/WebRTC（浏览器点对点实时通信协议）模式）
- **中继 = 可剥离部件**：会合/兜底与内容传输分离，V1 即预留候选地址字段，V2 只翻偏好序；未来纯直连可整体去掉中继
- 直连越多，中继带宽与责任面自然收缩（许可轨迹见六）

### 端到端加密（风险2 对治，「盲」的落实）
- 分享内容在分享方**加密**，中继只转发密文；收件人经链接/应用握手取得解密能力
- **加密与中继无关**：密钥走链接/App 间握手、不经中继 → 中继永不成为中间人（MITM）攻击点（可剥离部件的关键）
- 中继（作者）物理上无法读取内容 → 「中立管道（mere conduit，仅转发不存储的传输通道）」位置成立，作者无「明知」风险
- **密钥分发两形态（风险9）**：① 密钥随链接分发——链接即密钥，泄露=内容泄露，实现简单；② 密钥经 App 间握手——分享方对收件人 App 会话单独发钥，链接泄露不直接等于内容泄露，实现复杂。V1 建议①，风险9 登记此攻击面
- **全力保证正确性（决策14）**：E2E 实现正确是「无明知/中立管道」叙事的支柱，实现错误即防线崩塌——加密选型 + 正确性测试为阶段1/3 硬验收项

### 链接与访问控制（决策4/7）
- 落地页链接形如 `https://{relay}/s/{token}`；深链 `library-squirrel://share/{token}` 用于拉起 App
- token 为高熵随机串，不可猜测；可选密码
- **有效期（决策7）**：默认 7 天 + 自定义（可无限期）——语义为**分享方显式失效控制机制**（kill-switch 定时器，到点中继显式拒绝），**非可用性承诺**（分享方离线链接即断，与有效期无关）

### 深链拉起（风险1）
- 桌面端注册自定义协议 `library-squirrel://`（Wails 3 路径待核验）
- 落地页「打开应用」按钮触发深链；App 启动后解析 token → 进入拉取流程
- App 未安装/协议未注册时，落地页兜底提示下载
- **OS 副作用**：协议注册写注册表，需含卸载清理与协议冲突（与其他软件抢 `library-squirrel://`）处置，纳入风险1 spike 范围

### 落地页与预览元数据（流程成立的关键，决策9）
- 落地页由**中继**服务，分享方注册会话时上传预览元数据——收件人打开链接即有页面可看，**与分享方是否在线无关**
- **预览元数据最小化 + 砍掉封面（决策9）**：封面最可能直接含 R18/违法信息，中继展示图像即内容责任面——落地页**仅文字元数据（标题/作品数/来源），不展示任何图像**
- 链接自包含：`https://{relay}/s/{token}` 携带中继地址 + token；页面「打开应用」触发深链 `library-squirrel://share/{relay}/{token}` 拉起本地 App
- **中继持有元数据但不持有文件内容**（E2E）
- 兜底：App 未装 → 页面提示下载；分享方离线 → App 报「分享已失效」（页面在、传输断）

### 任务模块接入（决策10/12/16 的设计底座）
- 收件人「拉取分享」建模为任务：source=中继+token、dest=回灌导入；复用任务状态机/进度/Pause-Resume/断点续传/失败重试（决策12）
- 「拉取分享」任务下载完成后，经 app 注入的 **ManifestIngestor 能力**执行入库（与任务模块从插件拿创建记录能力对称；能力装配见阶段2）
- 分享方「分享会话」建模为任务（share-host 型）：维持出站隧道，具备任务全部标准能力；**不要求自动重建**（重启后按任务标准语义停留，续传仅覆盖传输中断场景，决策10/16）
- 中断完整性由任务模型承接：部分拉取断点续传，无需「中止清理/全部重来」（决策12）
- **依赖既有延后分支**：任务模块执行面剥离（ExecutionStrategy，把任务执行逻辑外提为可插拔策略接口）+ task type 字段（longops 方案方向锁C，即前述执行面剥离的既定方向 / 导出方案延后分支）——分享把它拉回本期范围，见七·阶段4 与延后分支

### 会话级溯源与撤销（决策6）
- 中继记录会话来源：token + **设备绑定持久实例 ID** + IP + 时间，**不记录内容**
- **举报封禁**：同一实例多次被举报 → 中继封禁该实例/IP 段
- **溯源与身份解耦**：会话记录不含身份字段，将来上账号只需加列、不改分享流（可逆设计）
- 落地页内「举报」入口 + 分享方撤销 → 会话立即终止（无需内容审查即可下架）

## 五、执行形态

分享发布沿用导出的**异步轻量壳**（后台 goroutine + 进度事件 + 可取消）；上传/拉取阶段按文件数/字节推进度。

### 部署形态（零部署，无服务器购买）

- **分享方：零部署**——App 即内容源，只需保持运行；「分享进行中」作为一等状态（与下载任务同层，见风险4）
- **作者：运营一个盲转中继**（非内容仓库）——纯管道成本（带宽 + 会话管理），无存储；中继软件开源后社区可自建分流（延后，见风险6）
- **CGNAT 无碍**——出站隧道天然穿过大内网，不需要公网 IP、不需要自购 VPS、不需要部署服务

## 六、法律风险与许可策略（todo「考虑法律风险」的落点）

### 责任边界分析
- **作者运营的是「中立管道」而非「内容托管平台」**：中继不存内容、内容端到端加密不可读、无公开检索目录、链接私密不可猜测 → 位置类同 VPN/隧道提供者，远强于内容托管平台
- **无「明知」风险**：作者物理上无法读取内容，工具内容中立；配合会话级溯源 + 快速撤销 + 配合执法，是「通知即处置」的可执行形态
- **非零风险**：作者仍需落实网络安全法基本义务——会话日志留存、配合执法、快速下架；提供 P2P 工具在国内有历史联想（盗版），但私密加密链接分享 ≠ 公开文件索引平台，本设计刻意规避后者

### 分许可策略（决策2）
| 组件 | 许可 | 理由 |
|---|---|---|
| 客户端（现有仓库） | GPL-3.0-or-later（已落地，见声明7） | 分发即触发开源义务；保住原选型「防闭源 fork + 生态零影响」 |
| 中继服务（新组件） | AGPL-3.0 | 若开源供社区自建中继分流，AGPL 第13条强制「修改后经网络提供服务须向交互用户提供源码」——防第三方中继者闭源篡改（改日志/改加解密） |

- 对作者自营的中继实例：披露义务不额外（作者即源码持有者）
- 对社区自建中继者：改动源码必须披露 → 可审计、可追责
- 技术增强层（可选，不进 V1）：客户端校验中继 provenance（源码提交哈希 + 构建指纹）

### 许可轨迹（跟随服务器角色分量）
- 中继是**可剥离部件**，许可随其角色演进而简化：V1 全流量盲转中继 → 中继 AGPL（必须）；V2 会合 + 兜底 → 中继 AGPL（角色收缩，仍持会合元数据）；**未来纯直连（无任何服务器）→ 全部 GPL、网络服务漏洞 moot**
- **纯直连下 GPL 漏洞可接受**：唯一「网络服务」是用户自己的客户端对等提供自己的内容——无集中运营者、无元数据集中、收件人信任面是「发链接的人」而非平台；GPL 的「分发即披露」对客户端仍生效。此结论**只对「真的无任何服务器」的边界状态成立，不豁免当前 V1**（中继存在 → 中继 AGPL）
- 架构含义：中继始终按「可剥离」设计（E2E 与中继无关、会合/兜底分离），未来掉头纯直连无许可障碍

### 合规机制清单
1. **端到端加密**（中继不可读 → 无「明知」）
2. 加密链接 + 可选密码/有效期（控制滥用面；**链接泄露=内容泄露**见风险9，密钥分发形态见四）
3. 会话级溯源日志（定位分享方，配合举报/下架/执法）
4. 落地页强制展示来源（站点/作者/原站链接）
5. 举报 + 快速撤销 + **快速精准处置（决策11 补充）**：全线停止（kill 会话）或精准封禁（按实例/IP），处置在举报后即时生效
6. 全库分享禁止 + 规模上限 + 会话日志留存期
7. ToS/免责声明（作者与中继置于合法位置）
8. AGPL 披露义务（防社区中继闭源篡改）
9. **中继运营合规（决策11）**：中继域名国内托管需 ICP 备案、落地页内容责任——官方中继运营时此义务落在作者
10. **分享方本机防护（风险8）**：隧道协议路径白名单、并发限流、与本地服务隔离

> **官方中继 = 处置面（社区中继并存）**：作者运营的官方中继是「配合执法」的抓手——保有举报/封禁/撤销/日志处置能力，是避风港「及时处置」要件的落点。中继软件开源供社区自建仅为**带宽分流**，不替代官方处置面；「纯社区中继、作者零运营」看似免责，实则失去处置能力、被点名时只剩「下架软件」被动应对——不追求「完全规避」（不可能），追求「可辩护」。

### 中继运营合规与法律风险（决策11/13 详解）
> 前置：作者运营官方中继（**托管地域=境内，决策13**）→ 作者是网络服务提供者（运营者），下列义务成立；社区自建中继 → 部署者为运营者。本文是风险地图，非法律意见，正式运营前建议咨询专业律师。

**1. 资质与备案层**
- **ICP 备案**：域名解析到国内主机必须 ICP 备案（《互联网信息服务管理办法》）；经营性服务（广告/收费）另需 ICP 经营许可证——免费无广告中继走非经营性备案
- **网络安全等级保护**（《网络安全法》第21条）：公共服务一般需定级备案并落实安全措施（常见二级）
- 若落地页被认定为「信息内容服务」，可能触及《网络文化经营许可证》等——盲转管道本身不算，但落地页展示用户内容可能触发

**2. 内容责任层（「牵连」的核心）**
- **避风港 / 中立管道**（《信息网络传播权保护条例》）：自动传输、自动缓存服务对内容不承担赔偿责任——盲转管道（不选择不修改、瞬时转发）恰好符合，是最强防线
- **落地页展示风险**：预览元数据（标题/封面）若被视为「信息存储空间/内容平台」→ 落入通知-删除与违法信息处置义务（《网络信息内容生态治理规定》：发现违法信息即处置、保存记录、报告）——决策9 的元数据最小化即为此
- **刑事红线**：《刑法》第363/364条传播淫秽物品罪——平台「明知」且不处置可构成；盲转 + 端到端加密使「明知」难以成立（技术中立的关键价值）；涉未成年人内容（CSAM，儿童性虐待内容）最严重，收到举报不处置即扩大责任
- **著作权**：版权方通知后须及时断开（撤销会话/下架）——「举报 + 快速撤销」就是可执行形态

**3. 数据合规层**
- **个人信息保护法**：会话级溯源（IP/token/时间）属个人信息 → 需告知用途、留存期限、配合删除请求
- **网络安全法**：网络日志按要求留存（如 6 个月）

**4. 运营落地清单**
1. 域名备案（国内托管必做）
2. 落地页放免责声明 + ToS + 举报入口（举报即撤销）
3. 会话级溯源日志 + 留存期限声明
4. 快速撤销/下架（通知-删除的可执行形态）
5. 端到端加密保持「看不见内容」的技术中立
6. 配合执法（协查流程）
7. 个人 vs 公司主体运营的责任承担不同——正式运营前咨询专业律师

**深链 spike 结论（2026-08-27，基于本仓 wails v3.0.0-alpha.98 源码核验，结论=可行，无需降级）**

- **可行路径（选定方案）**：Wails 3 框架侧「单实例 + URL 事件」+ 构建配置侧「protocols 协议注册」，两者 alpha.98 均已内置：
  - **已运行实例转发**：`application.Options.SingleInstance`（`SingleInstanceOptions{UniqueID, OnSecondInstanceLaunch, ...}`）——Windows 命名互斥体 `wails-app-{UniqueID}-sim` + 隐藏 message-only 窗口，二启进程经 WM_COPYDATA 把 `os.Args`（含深链 URL）转发首实例后自动退出，首实例在 `OnSecondInstanceLaunch` 收 `SecondInstanceData.Args`（wails 源码 `pkg/application/single_instance.go`、`single_instance_windows.go`）
  - **冷启动 URL**：事件 `events.Common.ApplicationLaunchedWithUrl`（`e.Context().URL()`）；Windows/Linux 触发条件=argv 含 `"://"` 的单参数（`application_windows.go:159`、`application_linux_gtk3.go:142`）
  - **协议注册（OS 副作用）**：Wails 运行时不注册协议，走 `build/config.yml` 顶层 `protocols: [{scheme, description}]` → `wails3 task common:update:build-assets` 渲染进三平台构建资产（NSIS/Info.plist/desktop）
  - macOS 二启收 URL 的 #5089 修复（URL 经 Apple Event 不进 argv）已含在 alpha.98；官方示例 `examples/single-instance-url-scheme` 即本场景
  - **版本注意**：官方文档（2026-05 更新）描述的运行时 `application.Options.Protocols` 字段与 `ApplicationOpenedWithURL` 事件名属更新版 API，**alpha.98 无此字段**——以本地源码 API 为准
- **OS 副作用与对治**：
  - **注册表写入点（Windows）**：`Software\Classes\library-squirrel`（默认值=描述）+ `URL Protocol` 空串 + `shell\open\command` = `"exe路径" "%1"`；本项目 NSIS 模板已内置 `CUSTOM_PROTOCOL_ASSOCIATE/UNASSOCIATE` 宏且 `project.nsi` 安装/卸载段已调用——**加 protocols 配置重生成构建资产即通，安装/卸载链零改动**；默认 admin 安装写 HKLM（机器级），per-user 写 HKCU（免管理员）
  - **便携分发补充**（本项目 bin/ 直跑形态）：App 运行时自写 HKCU\Software\Classes（`golang.org/x/sys/windows/registry`，x/sys 已是直接依赖，免管理员）；每次启动幂等重写以自愈 exe 移动后的悬空路径；设置页提供「取消协议注册」清理入口（便携无卸载器）。安装版（HKLM）与便携自注册（HKCU）并存时 HKCU 对当前用户优先——按分发渠道二选一
  - **协议冲突**：本机 `reg query` 只读探查 HKCU/HKLM 均无 `library-squirrel` 键（无冲突）；命名冷僻冲突风险可忽略；运行时写前读 `shell\open\command` 两视图可检测抢注（非本 exe 路径即他软件，记日志）
  - **卸载清理**：NSIS 卸载段 `wails.unassociateCustomProtocols` 自动删键（已就位）；便携自注册键由设置页清理入口承担
- **冷启动与已运行的 URL 传递机制**：冷启动 URL 在 argv → wails 事件（注意事件先于前端就绪，需缓存待前端就绪转发；dev 模式 argv 有附加参数致事件判定不满足，须辅以 argv 前缀扫描兜底）；已运行 → 二启转发 → 首实例回调；附带收益=SingleInstance 顺带根治双开两实例抢 SQLite
- **浏览器 UX**：Chromium/Edge 点深链弹外部协议确认框（「此网站想要打开…」），新版已移除普通「始终允许」勾选（企业策略可恢复）——属一次性可接受摩擦；落地页用真实 `<a>` 点击触发，弹框取消/未装 App 走既有兜底（下载提示+复制令牌手动粘贴）
- **macOS/Linux（简查）**：macOS 经 protocols 配置渲染 Info.plist `CFBundleURLTypes`（须 .app bundle 形态，裸二进制不参与 scheme 路由）；Linux 渲染 desktop `MimeType=x-scheme-handler/library-squirrel` + postinstall 刷数据库，URL 进 argv 同 Windows 路径，单实例走 D-Bus
- **实施要点清单**：① config.yml 加 protocols 并重生成构建资产（注意该命令覆盖构建资产手工改动，先盘点）；② main.go 启用 SingleInstance（UniqueID=`com.lvfeng.library-squirrel`），回调提取 URL→聚焦主窗口→转发前端进拉取流程；③ 订阅 `ApplicationLaunchedWithUrl` + argv 扫描兜底 + URL 缓存待前端就绪；④ **二启早退探针**：本仓 main() 中 `NewApp()`（DB/迁移/捆绑插件安装）先于 `application.New`（单实例检测在其内），深链二启会完整二次初始化才退出——main() 早期扫 argv 深链前缀，确认已有实例时走仅含 SingleInstance 的极简 `application.New` 完成转发退出（首实例冷启动勿走，防自占锁误判 already-running）；⑤ 便携版运行时自注册+幂等重写+设置页清理入口；⑥ 深链 URL 解析校验（scheme/host 白名单=中继域、token 字符集）——恶意深链是新输入面
