**待决策（均已裁决 2026-09-01，用户拍板）**
- 决策1（**键模型**）：中心注册表分配**无含义短 ID**（12 位小写 hex）；注册表 = SDK `identity` 子包具名常量（键值无含义、可读性由常量名承担），**只增不改**。`site_key` = 站点唯一身份（NOT NULL + 唯一索引）；`site_name` 降**纯展示列**（非唯一、创建时取注册表权威名）。
- 决策2（**无历史包袱硬切**）：无迁移、无回填、无名称回落——开发库删库重建；**全部按名匹配路径硬切键直查（五处：duplicate 查重/import 回灌/分享接收/manifest/任务创建主路径）**，名称匹配代码路径删除；manifest `SiteRecord` 加 `siteKey` 必填并**升 SchemaVersion 1→2**（声明7）。
- 决策3（**未注册键拒绝 + 注册渠道一等公民**，2026-09-01 用户终裁）：`AddSite` 键不在编译期内置注册表 → 报错拒绝，**报错文案即渠道指引**；处理未注册站点的最佳方式是**让插件开发者有注册渠道**（不走信任外溢的自声明接受）。渠道形态 = **PR 自助注册**：开发者自行生成强随机键值（24 位小写 hex，杜绝意外碰撞）→ 提 PR 至 SDK `identity` 包加常量 → 维护者合并时查重 → 随 SDK/主程序发布生效（生效时间 = 下次主程序发布，渠道文档写明预期）。`doc/plugin-dev-guide.md` 增「站点注册」章节（步骤化）、规范文档含完整贡献流程。
- 决策4（**本地虚拟站点入注册表**，五版补）：注册表首期收录 **pixiv / bilibili / Local（本地导入虚拟站点）** 三项——localImport 是官方捆绑插件，其 `local` 站点与外部站点同构入表（键分配无差别），解决声明11 断链。
- 决策5（**孤悬名称查询族删除**，五版补）：workSet 按名查询族（声明12）无消费方，随硬切**删除**（DEAD_CODE_CLEANUP——名称去唯一后按名查询本身歧义，孤悬契约不留）；前端 `site/handler.go:96` 的 GetByName 绑定核实消费方后处置（有则改键、无则删）。
- 决策6（非阻塞默认）：`site` 实体 `SiteKey string`（not null + uniqueIndex）、`site_name` 移除 uniqueIndex；无站点作品维持恒判待建（查重永不命中既有作品、必走新建，现状不变）。
- 决策7（**站点级 ID 约定注记 + 零新增键**，2026-09-01 用户终裁）：注册表条目附**站点级 ID 约定注记**（纯 godoc 文档注记，如「pixiv：siteWorkId=illust id、siteTagId=tag id」——同站点多插件读同一条 norm，收敛有锚点），**零新增字段/零新增键**；站点标签/站点作者/作品集板块的 site_tag_id/site_author_id/site_work_set_id 为**既有字段原样沿用**，本方案对这些板块的唯一变更是复合键中站点侧来源从名称升级为 site_key。治理分层写入规范（见「治理分层」节）。

**自曝风险**
- 风险1：注册渠道时延——新站点（含第三方）从 PR 到可用须「合并 + 主程序随 SDK 更新发布」两步；渠道文档（plugin-dev-guide 站点注册章节 + 规范贡献流程）写明生效预期，PR 自助（开发者生成键值、维护者只做查重合并）把维护负担压到最低；开发期仅官方插件、时延为零。
- 风险2：旧开发库遇 NOT NULL 新列 AutoMigrate 可能失败——预期行为（决策2 删库重建），报错即提示重建。
- 风险3：站点侧 ID 稳定性（全族：`site_work_id`/`site_tag_id`/`site_author_id`/`site_work_set_id`）运行时不可校验（原理上限）——治理靠「站点级约定注记 + 插件准入审查」两强锚（见「治理分层」节），规范文档与 plugin-dev-guide 显式言明。
- 风险4：`site_name` 非唯一后同名理论可共存——注册表权威名由作者审定天然去重，插件名不落库，残余仅注册表笔误。
- 风险5（五版补）：**主程序/插件改版窗口**——阶段2 重写 AddSite 语义后，未改版的官方插件（pixivSuite/localImport 均激活时活调 AddSite）会被拒；**官方插件改造已并入阶段2 同窗口完成**（见阶段清单），窗口收敛为单次开发会话内。
- 风险6：任务创建改键（声明10）后，插件 CreateTask 应答须带 `siteKey`（SDK proto `CreateTaskResponse` 加字段）——插件未带键的应答在任务创建即报 `ErrSiteNotFound` 同型错误，失败前置（好事：错误提早暴露）。

## 问题与动机

**现状**：跨库站点身份 = 站点名，**五处**按名匹配（声明3/4/6/10 + manifest 契约声明5）；名称脆弱（撞名误合并、改名断链、无权威）。软件未发布、无存量用户——按中心化身份终态硬切，不建过渡态。

**边界**：只做身份层；传输/发现/撮合不在范围（谱系延后分支：社区基建、BT 被动姿态）。

## 方案设计

### 1. 标识规范（核心定义）

| 层 | 标识 | 形态 | 权威来源 |
|---|---|---|---|
| 站点 | `site_key` | 注册表分配无含义短 ID（12 位小写 hex）；NOT NULL + 唯一索引 | 中心注册表（SDK `identity` 子包，作者审定、PR 贡献、只增不改） |
| 站点名 | `site_name` | 纯展示列（非唯一），创建时取注册表权威名 | 注册表 |
| 作品 | `(site_key, site_work_id)` | 查重键——站点侧从名称升级为键 | 插件产出（须站点侧稳定 ID） |
| tag/作者/作品集 | `(site_key, site_tag_id / site_author_id / site_work_set_id)` | 复合身份——**既有站点侧 ID 原样沿用、零新增键**（决策7：site_tag_id 等为既有字段，本方案对这些板块的唯一变更是站点侧来源从名称升级为 site_key；声明8，三表结构零改动） | 插件产出（同稳定性契约） |
| 无站点作品 | 不纳入 | 恒判待建（查重永不命中既有作品、必走新建） | — |

### 2. 注册表与契约层（SDK）

- **SDK 新增 `identity` 子包**（注册表 + 规范发布主载体）：
  ```go
  // package identity — 站点跨库标识注册表。键值无含义（随机分配、一经发布不可变），
  // 可读性由常量名承担；注册表只增不改；新站点经 PR 贡献、作者合并。
  var (
      // 站点级 ID 约定注记（纯文档注记、零新增字段，决策7）：声明各实体站点侧 ID 的
      // 取值约定——同站点多插件读同一条 norm，ID 收敛有锚点。
      Pixiv     = Site{Key: "s7f3a9c2e1d4", Name: "pixiv", Homepage: "https://www.pixiv.net"} // 约定：siteWorkId=illust id、siteTagId=tag id、siteAuthorId=author id、siteWorkSetId=user id
      Bilibili  = Site{Key: "s2c8b4e6f0a3", Name: "bilibili", Homepage: "https://www.bilibili.com"}
      Local     = Site{Key: "s9e1d5a7c3b2", Name: "local"} // 本地导入虚拟站点（官方捆绑插件）
  )
  // Lookup 按键查注册表条目（主程序校验与创建共用；未注册返回 false）
  func Lookup(key string) (Site, bool)
  ```
- **SDK proto**：`SiteDTO` 加 `siteKey`（主程序侧必填校验；`siteName` 保留但主程序忽略）；**`CreateTaskResponse` 加 `siteKey`**（任务创建主路径改键的契约面，风险6）。

### 3. 主程序实体与创建路径

- `site` 实体：`SiteKey`（not null + uniqueIndex）；`SiteName` 移除 uniqueIndex（纯展示）。
- **`AddSite` 重写**（`plugin_context.go:186-199`）：`siteKey` 经 `identity.Lookup` 校验——未注册 → 报错拒绝（决策3）；已注册 → 按键查重（`GetByKey`），不存在则创建（key + 注册表权威 Name/Homepage，忽略插件名）。
- **任务创建主路径改键**（`task/service.go:787-798`）：`resp.SiteKey` → `GetByKey` → `task.SiteID`，miss 报 `ErrSiteNotFound` 同型错误；`resp.SiteName` 判空校验退役（键必填校验取代）。
- 站点 repository：`GetByKey`/批量按键查替代名称查询族。

### 4. 匹配硬切（五处，删除名称匹配路径）

- **duplicate**（`service.go:144-207`）：查重项 `SiteName` → `SiteKey`；名称映射路径删除，改键批量查。
- **import**（`ingest.go:203-227/600-660`）：`mapExistingSites`/`ensureSites` 改按键 find-or-create（未注册键导入报错）。
- **export/分享 manifest**：`SiteRecord` 加 `siteKey` 必填、`SchemaVersion` 升 **2**（声明7 三处版本门拒绝旧 manifest）。
- **share 接收**（`task_execution.go:315-335`）：名称反解改键反解，查重项喂键。
- **任务创建**（见第3节，声明10）。
- **孤悬名称查询族删除**（决策5）：workSet 按名查询族（声明12 五处）删除；前端 `site/handler.go:96` GetByName 绑定核实消费方后改键或删。
- **site_tag/site_author/site_work_set**：结构零改动（声明8）。

### 5. 规范发布与触达

主轨 = Go 依赖库（SDK `identity` 子包）：常量即引用、编译期即约束、godoc 即规范（声明9 零新增依赖面）。辅轨：主程序校验器自解释报错（未注册键报错含注册指引）、`doc/site-identity-spec.md`（含注册表贡献流程与站点侧 ID 稳定性全族契约）、官方插件示范（AddSite/CreateTask 用 `identity.*` 常量）、模块 README/CLAUDE.md。

### 6. 治理分层（规范须显式言明）

身份体系各层治理强度不同，规范文档须如实分层：

| 层 | 强度 | 机制 |
|---|---|---|
| 站点键分配（site_key） | **强** | 注册表编译期内置 + 未注册拒绝——中心化唯一强保证 |
| 站点侧 ID 忠实性（siteWorkId / site_tag_id / site_author_id / site_work_set_id） | **运行时不可校验**（原理上限——宿主无法验证插件报的 ID 是否站点真正的稳定 ID） | 杠杆三处：①**站点级 ID 约定注记**（注册表条目内每站点一条权威 norm，同站多插件收敛有锚——决策7）；②**插件准入审查**（生态门：插件注册/上架时人工审 ID 提取逻辑，当前生态插件少作者把关，实际最强层）；③宿主格式校验（非空/字符集/长度，弱但便宜，可选） |
| 站点标签/作者/作品集的中心化单位 | **命名空间（站点），非实体** | 实体经复合键**继承**站点键的中心化保证——实体本身（百万级、动态、站点自有数据）不枚举注册（操作不可行且无收益）；**零新增键**（决策7，既有 ID 原样沿用） |
| 本地标签/作者层 | 每库私有，不中心化 | 用户自建分类体系，跨库仅经 site↔local 桥接（现状机制不变） |
