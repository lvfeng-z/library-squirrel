# 插件开发文档总结与排查方案

> 状态：待确认（排查已完成，文档重写方案待定形式后执行）
> 日期：2026-06-25

## 一、背景与目标

插件模块接近正式发布，需要一份**准确、完整、面向插件开发者**的正式开发文档。现状：`doc/ai-assistant/plugin-development.md` 严重过时——它基于**旧的 DLL/plugin.Open 架构**，与当前 **hashicorp/go-plugin 子进程 + 统一 KV API** 严重脱节，多处错误会直接误导开发者。

**目标**：
1. 排查 `plugin-development.md` 与实际代码的所有不一致（已查证，见第二节）。
2. 产出一份稳定的正式插件开发文档（准确反映当前架构）。
3. 清理过时内容，确保文档与 `.claude/rules/plugin.md`、SDK、pixiv 示例一致。

## 二、排查发现（plugin-development.md 的错误清单）

### 2.1 架构层（根本性错误）

| 位置 | 文档描述（错） | 实际 |
|---|---|---|
| 第 5、12 行 | "Go 共享库（.dll/.so）" | **go-plugin 子进程**（`.exe`，主程序通过 hashicorp/go-plugin 启动插件进程） |
| 第 105-128 行 | 入口 `func Activate(ctx pluginsdk.PluginContext)` | pixiv 实际 `Activate(ctx, handler *PixivTaskHandler, browser *PixivSiteBrowser)`——**Activate 签名约定需核实 SDK**（transport/plugin_server.go 的调用方式） |
| 第 281-306 行 | 加载流程 `plugin.Open(dllPath)` → `Lookup("Activate")` | 实际 `Loader.LoadPluginProcess`（启动子进程 + gRPC + Activate RPC） |

### 2.2 PluginContext 接口（文档 145-183 vs `dto/context.go`）

文档接口总览与实际 `PluginContext` 严重不符：

| 文档（错/缺） | 实际 `dto/context.go` |
|---|---|
| 列了 `RegisterSlot` / `UnregisterSlot`（标注废弃） | **已删除**，接口中不存在 |
| 列了 `GetMainWindow()` / `CreateWindow(options)` | **不存在**；实际是 `GetMainWindowHandle() uintptr` |
| 缺 | `GetMainWindowHandle() uintptr` |
| 缺 | `PublishToFrontend` / `SubscribeFrontend` / `UnsubscribeFrontend`（前端通信） |
| 缺 | `GetLogger() Logger` |

### 2.3 plugin.json（文档 39-96）

- **slot 示例结构错**（57-69）：把 `contentType/content/title/icon/order/contributionId` 混在 slot 顶层。实际 `SlotDeclaration` 顶层是 `id/name/description/slotType/order/content`，`content` 内按 slotType 区分（如 siteBrowserList 的 content 是 `{icon, contributionId}`，不是 js/css）。
- **缺 `extensions.settings`**（M3 新增的用户设置声明，文档完全没提）。

### 2.4 content 格式（文档 256-263）

- 文档 `vueSource` = `{vue, js, css}` —— 实际 `{entry: "path.vue"}`（见 plugin.md source 格式表）。
- `content` 中相对路径转换：文档说转 `resource://` —— 实际转 `http://wails.localhost/.../plugin/...`（见 2.5）。

### 2.5 静态资源 URL（文档 91、96、263、326）

- 文档统一用 `resource://plugin/{publicId}/{version}/{relativePath}`。
- **实际是 `http://wails.localhost:{backend-port}/plugin/{id}/{ver}/...`**（`assetserver/router.go` + plugin.md 一致）。`resource://` 协议不存在。

### 2.6 关键文件清单（文档 348-369）

| 文档列出的文件 | 实际 |
|---|---|
| `extension/registrar.go` | **不存在**（已移除） |
| `extension/asset_handler.go` | **不存在** |
| `backend/base/slot.go`、`backend/base/model/extension.go` | 待核实是否还在该路径 |
| 缺 | `extension/plugin_host.go`（go-plugin host 实现） |
| 缺 | `extension/process_group_windows.go` / `process_group_other.go`（子进程分组管理） |
| 缺 | `extension/slot_handler.go`（Slot IPC Handler） |
| 缺 | `extension/task_handler_proxy.go`（gRPC 任务代理） |

### 2.7 加载流程图（文档 281-306）

`plugin.Open/Lookup/Activate` 全错，应为 go-plugin 子进程流程（`LoadPluginProcess` → gRPC 握手 → `Activate` RPC → 注册扩展点）。

### 2.8 更新记录（文档 381-413）

历史变更日志（2026-05-04 ~ 05-06）属于变更历史，按项目规范应在 `doc/plan/`，开发指南不必承载。

### 3.2 文档结构（建议）

```
1. 概述（插件系统能力、两种插件模式）
2. 快速开始（最小可运行插件示例）
3. plugin.json 清单

4. 插件入口 Activate（签名约定、注册扩展点）
5. PluginContext 完整 API（与 dto/context.go 严格一致）

6. 扩展点详解

   - Slot（声明式：5 种 slotType × content 格式）
7. 插件自存信息（统一 KV：明文/加密、settings 读取）
8. 前端通信（PublishToFrontend/SubscribeFrontend 协议）
9. 原生窗口（OpenWindow，Windows WebView2）
10. 静态资源（URL 规约、目录白名单）
11. 打包与发布（build.ps1、dist 结构、安装）
12. 完整示例（以 pixiv 为参考）
13. 最佳实践与陷阱
```
