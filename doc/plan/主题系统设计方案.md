# 主题系统设计方案

> 状态：已完成（阶段 0~5 全部落地）
> 日期：2026-06-23（初稿）/ 2026-06-23（实施完成）

> 实施过程中的关键调整：
> - D3 默认主色最终由 `#007038`（绿）改为 EP 原生蓝 `#409eff` 作为默认主题，原绿色保留为备选主题「森林绿」（`forest-light`）。当前共 4 套主题：默认浅色（蓝）、森林绿、海洋蓝、樱花粉。
> - EP 适配桥接（`ep-bridge.css`）采用「全局 `:root` 一次」而非方案 4.2 示例的「主题文件内」，因桥接关系对所有主题一致。
> - 主题文件只覆盖主色与背景基调；状态色跨主题共用 `:root` 默认值。
> 范围：前端为主（令牌体系 + 切换机制 + 设置页 + 持久化），后端仅 Settings 结构体微调
> 关键倾向（已确认）：
> 1. **不使用 Element Plus 内置变量** —— 自建语义令牌层作为单一真相源
> 2. **先做浅色主题** —— 深色作为后续扩展，机制须向前兼容
> 3. **暂不关注插件前端样式，但预留双方协商机制**
> 4. **支持多套配色** —— 非"浅/深"二档，而是多套命名主题

---

## 一、背景与目标

### 1.1 现状（详见样式扫描结论）
- 样式以 Element Plus 预编译 CSS 为基底，组件以 `<style scoped>` 为主流。
- **几乎不存在设计令牌层**：颜色、字体、圆角、阴影、间距全部硬编码或零散借用 `--el-*`。
- 颜色两套并存：~60 处借用 `--el-*`（较规范）、36 处 hex + 大量 rgb/rgba 硬编码（分散，集中在布局/卡片/标签观感位置）。
- **零主题切换基础**：无 `:root` 变量覆盖、无 dark 模式、无换肤代码。
- 令牌化程度：仅 z-index（`.z-layer-*`）与一处局部变量 `--side-menu-background-color`。

### 1.2 目标
建立一套**令牌驱动**的主题系统，满足：
1. 统一的颜色令牌体系，消除硬编码颜色，全局观感可被集中控制；
2. 运行时切换主题（多套配色），无需重新构建；
3. 主题选择持久化（复用现有 Settings 机制）；
4. 机制向前兼容深色主题（本次不实现，但架构预留）；
5. 预留主程序↔插件的样式协商通道。

## 二、设计原则

### 2.1 不使用 Element Plus 内置变量（落实倾向 1）
**核心：业务代码只认 `--app-*`，绝不直接使用 `var(--el-*)`。**

但这不意味着 Element Plus 组件无法换肤——EP 组件内部硬依赖 `--el-*`。因此采用**令牌映射**架构：

- **语义令牌层 `--app-*`**：项目的"单一真相源"，所有业务/view/组件样式只读写它。
- **EP 适配层**：在每个主题定义中，用 `--app-*` 反向驱动 `--el-*`（如 `--el-color-primary: var(--app-color-primary)`）。这是一次性的"桥接"，集中在一处，业务代码无感知。

> 之所以采用映射而非"完全不碰 `--el-*`"：若不驱动 `--el-*`，则 `el-button(type=primary)`、`el-table` 表头、`el-tag`、`el-input` 聚焦边框等 EP 组件颜色将固定为 EP 默认蓝、无法随主题变化，造成业务区与 EP 组件区观感割裂，违背"主题系统"初衷。映射方案让"不直接使用 EP 变量"这一原则体现在**业务层**，而 EP 适配层是不可避免的底层桥接。

### 2.2 先做浅色（落实倾向 2）
- 本次所有主题定义均为浅色基调，主题 id 采用 `<name>-light` 命名（如 `default-light`）。
- 深色主题 id 将来用 `<name>-dark`，机制（`data-theme` 属性 + 令牌覆盖）完全一致，仅需新增 CSS 定义文件，不改架构。

### 2.3 多套配色（落实倾向 4）
- 主题 = `{ id, name, tokens }`，每套主题完整定义一组 `--app-*` 值。
- 本次实现至少 1 套可用主题（`default-light`，对齐当前观感），并预留 1~2 套浅色变体（如 `ocean-light`、`sakura-light`）的骨架以验证多套机制，实际配色可后置。
- 选择机制以 CSS 文件 + `data-theme` 属性实现（见 3.3）。

### 2.4 插件协商机制（落实倾向 3）
- 本次**不修改**任何插件的前端样式。
- 预留机制：主题令牌以全局 CSS 变量形式存在于 `:root`/`html[data-theme]`，插件 CSS 注入到主文档全局 `<head>`（见 `useSlotSyncListener.ts`），因此**插件只要遵循约定使用 `var(--app-*)`，即可天然跟随主题**，无需 JS 通知。
- 额外预留一个 JS 侧的主题查询能力（store 暴露当前主题 id），供需要感知主题的插件逻辑使用。
- 主题令牌契约（令牌清单 + 语义说明）输出为文档，作为插件开发者参考。

## 三、整体架构

### 3.1 三层模型

```
┌─────────────────────────────────────────────────────────┐
│ 业务层（views / components / 业务样式）                    │
│   只使用 var(--app-*)，禁止 var(--el-*)                    │
└───────────────────────────┬─────────────────────────────┘
                            │ 读取
┌───────────────────────────▼─────────────────────────────┐
│ ① 语义令牌层 --app-*（单一真相源）                         │
│   --app-color-primary / --app-bg-page / --app-text-* /    │
│   --app-border-* / --app-fill-* / --app-radius-* ...      │
└───────────────────────────┬─────────────────────────────┘
                            │ 由主题定义赋值
┌───────────────────────────▼─────────────────────────────┐
│ ② 主题定义层（每套主题一个 CSS 文件）                        │
│   html[data-theme="default-light"] { --app-*: ...; }      │
│   html[data-theme="ocean-light"]      { --app-*: ...; }   │
└───────────────────────────┬─────────────────────────────┘
                            │ 在主题文件内一并桥接
┌───────────────────────────▼─────────────────────────────┐
│ ③ EP 适配层（每个主题文件内）                                │
│   --el-color-primary: var(--app-color-primary); ...       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 切换机制
- 切换主题 = 修改 `<html>` 的 `data-theme` 属性值。
- 纯 CSS 级联，无 JS 遍历 DOM；切换瞬时生效，性能与构建无关。
- 由 Pinia store（`useThemeStore`）封装：读持久化值 → 设属性 → 切换时写持久化。

### 3.3 文件结构

```
frontend/src/styles/theme/
├── tokens.css                  # 语义令牌的 fallback（:root 上的默认浅色值，data-theme 未命中时兜底）
├── theme-default-light.css     # 默认浅色主题（--app-* 赋值 + EP 适配桥接）
├── theme-ocean-light.css       # 浅色变体骨架（预留，配色可后置）
└── index.css                   # 汇总 @import
```

`main.ts` 中引入 `./styles/theme/index.css`（替代/补充现有散装样式 import）。

`frontend/src/store/UseThemeStore.ts` —— 主题状态与切换。
`frontend/src/theme/themes.ts` —— 主题元信息清单（id/name/预览色，供设置页渲染选择器）。

#### 颜色 - 主题色（含 EP 派生档位）
EP 的 primary 在运行时不会由 `--el-color-primary` 自动生成 `light-N`，需在主题文件内显式覆盖全部派生档位。

| 令牌 | 默认浅色值 | 用途 |
|---|---|---|
| `--app-color-primary` | `#007038` | 主色（按钮/链接/选中态） |
| `--app-color-primary-light-3` | `#4d9b74` | primary 浅 3 |
| `--app-color-primary-light-5` | `#80b89c` | primary 浅 5 |
| `--app-color-primary-light-7` | `#b3d4c3` | primary 浅 7 |
| `--app-color-primary-light-8` | `#cce2d7` | primary 浅 8 |
| `--app-color-primary-light-9` | `#e6f1eb` | primary 浅 9（浅底/hover） |

### 4.3 主题状态与切换（`UseThemeStore.ts`）

```ts
import { defineStore } from 'pinia'
import { settingsGetSettings, settingsSaveSettings } from '@renderer/apis/http/wrappers/settings'
import ApiUtil from '@renderer/utils/ApiUtil.ts'
import type { SettingChange } from '@bindings/github.com/library-squirrel/backend/settings/models'
import { THEMES, DEFAULT_THEME_ID, type ThemeId } from '@renderer/theme/themes'

// data-theme 写入 <html>，使 CSS 级联生效
function applyTheme(id: ThemeId) {
  document.documentElement.setAttribute('data-theme', id)
}

export const useThemeStore = defineStore('theme', {
  state: () => ({
    currentThemeId: DEFAULT_THEME_ID as ThemeId,
    initialized: false,
  }),
  getters: {
    currentTheme: (state) => THEMES.find((t) => t.id === state.currentThemeId) ?? THEMES[0],
    themeList: () => THEMES,
  },
  actions: {
    /** 应用启动时从 settings 加载并应用 */
    async load() {
      const resp = await settingsGetSettings()
      if (ApiUtil.check(resp)) {
        const data = ApiUtil.data<{ appearance?: { theme?: string } }>(resp)
        const id = data?.appearance?.theme as ThemeId
        if (id && THEMES.some((t) => t.id === id)) {
          this.currentThemeId = id
        }
      }
      applyTheme(this.currentThemeId)
      this.initialized = true
    },
    /** 切换主题：写 DOM + 持久化 */
    async setTheme(id: ThemeId) {
      if (!THEMES.some((t) => t.id === id)) {
        throw new Error(`主题不存在: ${id}`)
      }
      this.currentThemeId = id
      applyTheme(id)
      const changes: SettingChange[] = [{ path: 'appearance.theme', value: id }]
      await settingsSaveSettings(changes)
    },
  },
})
```

初始化时机：`main.ts` 中 pinia 建立后、`app.mount` 前调用 `useThemeStore().load()`，避免首屏闪烁（FOUC）。或于 `MainLayout` 的 `onBeforeMount` 中调用，但前者更优。

### 4.6 设置页 UI（`Settings.vue`）

- 在锚点导航新增"外观"分区（`#appearanceSettings`），置于"基本设置"之后。
- 主题选择器：卡片式 radio group，每张卡片展示 `swatch` 色板 + 名称；选中即调用 `useThemeStore().setTheme(id)`（即时预览，无需点"保存"）。

### 4.7 插件协商机制（预留，本次仅搭骨架）

1. **契约文档**：将 4.1 令牌清单输出为 `doc/plugin-theme-tokens.md`（或纳入插件开发文档），声明插件可用的 `--app-*` 清单与语义。插件遵循约定使用这些变量，即可自动跟随主题。
2. **JS 侧能力**：`useThemeStore` 暴露 `currentThemeId` getter；并在 `main.ts` 的 `pluginContext`（`__PLUGIN_CTX__`）中预留 `theme: { getCurrent: () => useThemeStore().currentThemeId }`，供需要感知主题 id 的插件逻辑读取。
3. **事件通道（可选预留）**：主题切换时主程序可 `Events.Emit('theme:changed', { id })`，插件按 `plugin:{name}:theme:changed` 约定订阅（复用现有插件↔前端事件机制）。本次仅埋 emit 点，不要求插件实现。
4. 本次**不改动**任何插件前端代码，仅在文档与 ctx 中预留。

## 八、风险与边界

1. **EP primary 派生档位遗漏**：运行时覆盖 `--el-color-primary` 不会自动生成 `light-N`。须在主题文件内**完整覆盖**所有档位（light-3/5/7/8/9、dark-2），否则按钮 hover/active、表格选中底色等会出现档位断层。状态色同理。
2. **首屏闪烁（FOUC）**：须在 `app.mount` 前完成 `data-theme` 写入；`tokens.css` 的 `:root` fallback 保证即便 store 未加载也有合理默认。
3. **插件硬编码颜色不可控**：主题只能保证主程序与"遵循契约的插件"。不遵循的插件（硬编码颜色）将不跟随——这是已知边界，靠契约文档约束，非技术缺陷。
4. **`Settings.vue` 未保存判定**：主题即时持久化，须从 `hasUnsavedChanges` 排除 `appearance`，否则切换主题会误触"是否保存"弹窗。
5. **scoped 样式与全局令牌**：CSS 变量穿透 scoped 无障碍（变量定义在 `:root`/`html`），无需 `:deep()`。
6. **EP 暗色 CSS 未引入**：本方案浅色优先，不引入 `element-plus/theme-chalk/dark/css-vars.css`；将来加深色主题时，由各 `*-dark.css` 自行桥接 `--el-*`，不依赖 EP 官方暗色文件，保持令牌单一真相源。
