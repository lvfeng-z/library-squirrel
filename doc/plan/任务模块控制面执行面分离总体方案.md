**自曝风险**
- 风险1：全库最核心运行时表的拆分 + 内核剥离 + 落盘模式改造三事叠加，触及多轨下载/断点续传/暂停排空（drain：暂停前把在途下载分块收尾，防止半写文件）/替换链（全仓回归风险最高区）——以分期独立回归对冲，任何一期不得与功能开发并行混做。
- 风险2：提交点（rename+建行+挂载）非纯 DB 事务——文件操作与 DB 事务之间存在崩溃窗口，需补偿序列（rename 后 DB 失败→文件移回/清理+软删行复活收窄到提交窗口）；比现状（长下载全程回滚敞口）窗口缩小两个数量级但非零。
- 风险3：GetStoreRelPath 改「运行中查内存规划表、非运行中查已提交行」依赖「重启后无运行中任务」纪律（手动触发、无自动恢复）；若未来出现启动自动恢复，需补规划持久化。
- 风险4：期1 表拆分先行产生过渡期双表读写适配代码（taskManager 内核先适配、期2 才挪走）——两次触内核的代价，已在决策3 中与合并方案权衡；迁移中途失败的回滚预案见决策7。
- 风险5：前端 bindings 全量重生成 + 任务 DTO 组合形态变化，前端适配面大（任务面板/创建表单/详情/多选操作），受 vue-tsc 基线既有错误制约按「改动文件 0 错误」验收。
- 风险6：存量迁移三段（task 行拆两表、payload JSON 展开、task_type 回填）+ 进行中旧形态任务收口（未完成 store 行+最终路径 partial 文件的清理），迁移脚本复杂度集中在期1。

## 一、背景与目标

**背景**：task 表是「作品下载任务」形态的历史遗留——task_type/payload 是后打补丁的泛化，控制面（状态机/树/调度）与作品任务领域数据（插件路由/板块/资源定位）混于一张表；taskManager 内核同时承载控制面与插件下载执行面（model.go 2259 行），策略任务（share-receive）与插件任务双执行路径并存。用户决策（2026-08-28）：先做执行面与控制面分离，详尽设计新任务模块终局，尽可能减少重构后的架构调整。

**目标**：一次定稿四件事的终局形态——(1) 表拆分：核心 task（控制面）+ work_task（作品任务领域）+ 各接入方领域子表，payload JSON 列退役；(2) 执行面外提：插件下载执行面从 taskManager 内核剥离为独立模块的策略实现，内核纯化为纯控制面；(3) 落盘模式（todo#53）：直接落最终路径改为暂存+提交点提交，替换链坍缩；(4) 领域接入收敛：share-receive 子表化迁移、export 以终局形态接入。

## 二、终局架构

### 2.1 模块划分

```
taskManager（控制面，纯化后）
  ├─ actor 循环 / cmdWatcher / 状态机 / WaitingForInput 单点
  ├─ 信号量 + FIFO 队列 / claim / dispatch / 树操作（整树加载/重纳/未启动兄弟守卫）
  ├─ 进度推送 / flushLoop（核心表 status 写）
  ├─ ConfirmReplace 路由（按 task_type 投策略确认通道）
  └─ 快照 / 查询聚合（经核心表 + 注入的领域投影接口）
task（核心实体模块）
  └─ 核心 task 表 CRUD + 建树（CreateBuiltinTask 系列保留）
download（新模块：插件下载执行面）
  ├─ 实现 ExecutionStrategy（task_type = "plugin-download"）
  ├─ work_task 表 repository（板块模式/插件路由/资源定位/continuable/plugin_data）
  ├─ 查重编排（策略内）+ 替换链（提交点）+ 板块组合 + 多轨下载/续传 + 命名解析
  └─ 暂存目录管理 + GetStoreRelPath 规划表（运行中内存态）
share / export / （未来 merge、翻译、查重…）
  └─ 各自领域子表 + 各自 ExecutionStrategy 实现
```

### 2.2 表结构终局

**task（核心表，控制面）**：`id / create_time / update_time / pid(→task.id) / has_child / task_name / status / error_message / task_type`
- 所有任务类型共用；树结构、状态机、策略路由键；不含任何领域字段。

**work_task（作品任务领域，1:1 共享主键）**：`task_id(→task.id) / site_id / site_work_id / url / pending_resource_id(→resource.id) / continuable / plugin_public_id / plugin_extension_id / plugin_data / store_roles / involved_roles / resource_type / include_work_info`
- 归 download 模块 repository，控制面不直查（查询聚合经窄投影接口）。

**share_task（share-receive 领域）**：`task_id / relay_dial / relay_host / token / key_b64 / password_hash / manifest_path / manifest_id`——现 payload JSON 展开（relay_dial=拨号地址，独立持久字段原样落列，不做派生）；schemaVersion 退役（列结构变更此后走命名迁移，天然版本化）。

**export_task（导出领域，期4 建）**：`task_id / work_ids / work_set_ids / output_dir`。

**外键变化**：`resource.task_id` 改指 `work_task.task_id`（决策4）；`work_task.task_id`、`share_task.task_id`、`export_task.task_id` → `task.id`；`task.pid` 自引用保留。

### 2.3 接口契约

- **ExecutionStrategy 不变**（Execute(handle) + StrategyHandle 现有六方法）——已验证承载下载流四要素（产出/循环/进度/恢复）；插件下载执行面成为又一个实现。
- **策略路由统一**：所有任务（含存量插件任务）task_type 非空（决策1），Manager 构造注入的策略表查表执行，查无类型即拒建/拒启。
- **ConfirmReplace 单点化**：插件任务查重确认从「派发前批量预检 + waitingForInputMap」改为策略内 `WaitReplaceConfirm`（share-receive 同构），`batchCheckDuplicates` 与其特例队列退役（决策2）。
- **recordMode 退役**：执行模式唯一源=work_task 行（Redownload 写行、重试/恢复读行），内存 recordMode 机制删除。
- **任务查询聚合**：task 模块查询服务经窄投影接口（如 `WorkTaskProjector`，download 实现、app.go 注入）组合领域字段进 DTO，前端契约一次取全（契约直通）。

### 2.4 任务暂存目录基建（决策6 形态：统一暂存根）

workDir 下单一 `task-staging/{任务ID}/`，全部任务类型（下载/分享接收/导出/未来接入方）共用：

- **目录派生与清扫单点化**：暂存生命周期=任务生命周期（目录名=任务 ID、任务行删除/终态自清、启动孤儿清扫兜底）是任务域通用概念——单点能力（任务模块提供目录派生 + `CleanupOrphanStaging` 启动清扫，share-receive 的 `CleanupOrphanReceiveStaging`（`backend/share/task_execution.go:684`）泛化并轨），未来接入方零新增清扫代码。
- **fsmonitor 白名单单点**：单一目录在监控白名单子树外，一次登记。
- **share-receive 并轨**（期4）：暂存根从 `share-receive/{父任务ID}/` 迁至 `task-staging/{父任务ID}/`，`share_task.manifest_path` 存量路径随迁移重写。
- 对照形态（各业务单列目录）：模块自治但每接入一个新类型重复一份清扫代码与白名单登记——同构重复与「耗时操作收敛进任务模块」方向相悖。

## 五、期3：落盘模式改造（todo#53 兑现）

- **前置规划**：Start 返回 specs 后即解析全部最终路径（命名解析前置），形成 taskId→(spec→最终路径) 内存规划表。
- **GetStoreRelPath 契约**（风险3）：运行中任务查 download 内存规划表；非运行中查已提交 store 行（现状语义）。
- **下载到暂存**：`task-staging/{任务ID}/`（决策6 统一暂存根，2.4 节），多轨流写暂存（暂存名=role+seq 派生键）；暂存文件大小=续传锚（share-receive 同构）；fsmonitor 不感知（白名单子树外）；崩溃残留由启动清扫单点兜底（`CleanupOrphanStaging`，share-receive 先例 `backend/share/task_execution.go:684` 泛化）。
- **提交点**（全部文件暂存完成后）：序列为——(a) 替换场景软删旧 store（现 `softDeleteReplaceTargets` 语义，`SetTerminalRollback` 登记收窄到提交窗口）；(b) 暂存 rename 到最终路径（同卷原子）；(c) 单事务建 persistent_store 行（必然完整）+ resource_store 挂载 + Resource Save + work_task.pending_resource_id。失败补偿序列（风险2）为提交点内逆操作。
- **替换链坍缩**：长下载全程不再有 DB 副作用——下载失败/暂停=丢弃暂存或保留续传，旧 store 一动不动；`restoreReplaceTargets` 复活链敞口从长下载窗口缩至提交窗口。
- **persistent_store 未完成中间态退役**：completed_at=0 族机制（StoreStream/ResumeStream/ResetCompleted/Abort 清理/读取层 404 校验）随调用方消失而删（声明3）；/store/ 404 校验保留为防御。
- 退出标准：替换/非替换 × 成功/失败/暂停/崩溃恢复矩阵全回归；`GetStoreRelPath` 契约测试（图文 document lazy 生成场景）。

## 六、期4：领域接入收敛

- **share-receive 子表化**：payload→share_task 迁移（期1 已建表灌存量，本期 ReceiveExecution 改读子表、payload 写入路径切子表）。
- **export 接入**：export_task 子表 + `ExportExecution`（此前的《导出任务化方案.md》payload 形态废止，执行面设计复用其阶段1/2 已有结论——Collect→Plan→预检→Pack→rename 流程与暂停=恢复重跑语义不变，仅数据源从 payload 换子表）；`StartExport` 建核心行+子表行（事务两表）并启动。
- **merge 接入评估**（耗时操作接入任务模块谱系的后续项，同形态跟进）：独立 plan 另出。
- 退出标准：export 全链可用（建任务/暂停/停止/重试/完成通知）；share-receive 无回归。
