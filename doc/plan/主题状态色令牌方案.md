## 一、背景与根因

### 1.1 现象
1. 任务页（`TaskManage.vue`）任务行的状态标签颜色不受主题控制——切到森林/海洋/樱花，「完成」始终是同一个绿、「失败」始终是同一个红。
2. `SegmentedTag.vue` 的配色（含 main/sub/hover/未选中/关闭图标）不受主题控制。
3. 更深层：当前只有 EP 5 个状态语义色 + 5 个具象 tag 色（blue/green/red/purple/orange），缺少一套能表达「广义状态」（任务/来源/开关/资源）且每主题可独立定义的状态色体系。

### 1.2 根因

**任务页状态标签（`TaskManage.vue:597`）**
```html
<el-tag :type="statusTagTypeMap[getStatus(row)] ?? 'info'">
```
- type 是 EP 5 语义（success/warning/info/primary/danger）。el-tag 渲染时背景取 `--el-color-{type}-light-9`、文字取 `--el-color-{type}`、边框取 `--el-color-{type}-light-8`。
- `ep-bridge.css` 已把 `--el-color-{type}-*` 桥接到 `--app-color-{type}-*`——**桥没问题**。
- 真正缺口：`tokens.css` 的 `:root` 里 success/warning/danger/info 是 EP 默认值；4 个主题文件（default/forest/ocean/sakura）**只覆盖了 primary 和背景**，**没有任何主题覆盖状态色族** → 无论切哪个主题，状态色都停留在 EP 默认那一套。这正是《主题系统设计方案》阶段 4 预留但未落地的部分。

**SegmentedTag（`SegmentedTag.vue:25-35`）**
- colorConfig 大量硬编码 rgb：sub1/sub2/hover/未选中/close 图标全是 `rgb(166.2, 168.6, 173.4, x%)`，main hover 是 `rgb(133.4, 206.2, 97.4, 15%)`，**完全不引用令牌**。
- main 段虽默认引用 `var(--app-tag-green-bg)`，但 `SearchTagColorUtil.ts` 又把 main 覆盖成硬编码 `rgb(245,108,108,25%)` / `rgb(164,158,255,25%)` / `rgb(64,158,255,25%)`；`AutoLoadTagSelect.vue` 自定义标签 hover 也是硬编码 `rgb(230,162,60,15%)`。
- `--app-tag-*` 只有 5 个**具象颜色名**，不是语义状态名，无法表达「广义状态」。

### 1.3 深层缺口
状态色目前散落在三处互不相通的体系：
1. EP 5 语义色（`--app-color-success/...`）—— 给 el-tag/el-button 等 EP 组件
2. 5 个具象 tag 色（`--app-tag-blue/green/red/purple/orange`）—— 给 SegmentedTag 分类
3. 各组件内硬编码 rgb —— 完全脱离主题

三者无统一语义层，导致「同一语义（如『本地』）在不同组件用不同硬编码值」，且都不可主题化。

---

## 二、设计目标

1. 引入**状态语义层**：状态名（completed/failed/local/site/...）→ 颜色，业务只认状态名。
2. **双层令牌**：色族层（每主题整体调）+ 状态别名层（默认引用色族，可个别覆盖），兼顾整体协调与个别精调。
3. **每主题可定义**：切换主题时，所有状态色随之变化；任一主题可独立调整任一状态。
4. **广义可扩展**：覆盖任务/来源/开关/资源四类状态，新增状态只需追加别名。
5. **消除硬编码**：SegmentedTag 全链路（含 SearchTagColorUtil、AutoLoadTagSelect）改用令牌。

---

## 三、令牌架构（双层）

### 3.1 分层模型

```
┌─────────────────────────────────────────────────────────────┐
│ 业务层（views / components）                                  │
│   只使用 var(--app-status-{name}-bg/text/border)             │
│   或 StatusTag 组件传 status key                              │
└───────────────────────┬─────────────────────────────────────┘
                        │ 读取
┌───────────────────────▼─────────────────────────────────────┐
│ Layer 1：状态别名（新增，--app-status-{name}-{bg/text/border}）│
│   默认值 = 引用 Layer 0 色族；主题可个别覆盖                  │
│   name ∈ task-completed / source-local / toggle-enabled ...  │
└───────────────────────┬─────────────────────────────────────┘
                        │ 默认引用 / 可被主题改写指向
┌───────────────────────▼─────────────────────────────────────┐
│ Layer 0：色族（已存在，补全各主题覆盖）                         │
│   语义色族 --app-color-{primary/success/warning/danger/info}  │
│   具象色族 --app-tag-{blue/green/red/purple/orange/neutral}   │
└─────────────────────────────────────────────────────────────┘
```

**关键性质**：状态别名默认 `var()` 引用色族 → 主题只需覆盖色族，所有引用它的状态**自动跟随**；若某主题要让某个状态与众不同，直接覆盖那个别名即可，不影响其他状态。这是「整体调 + 个别精调」兼得的核心。

### 3.2 Layer 0 色族（现状 + 补全）

- **语义色族**（success/warning/danger/info）：`tokens.css` 的 `:root` 已有完整 light-1~9 / dark-2 档位（沿用 EP 默认值）。**本次不做修改**，只让各主题在其 `theme-*.css` 内覆盖。
- **具象色族**（`--app-tag-blue/green/red/purple/orange`）：`tokens.css` 已有 bg/text。**新增 `--app-tag-neutral-bg/text`**，承载 SegmentedTag 的 sub 段/未选中态/关闭图标那套灰（现状硬编码 `rgb(166.2,168.6,173.4)`），统一为中性标签色。

> Layer 0 不引入新色族（除 neutral），复用已有，避免膨胀。

### 3.3 Layer 1 状态别名（新增）

定义在 `tokens.css` 的 `:root`（作为全局默认 = 默认浅色主题的取值）。每个状态含三个分量：`-bg`（浅底）/ `-text`（文字）/ `-border`（边框），对齐 el-tag 浅底深字的渲染范式。

**命名规范**：`--app-status-{类目}-{语义}-{bg|text|border}`，类目前缀避免跨类目撞名。

#### 类目 1：任务状态（task-*）—— 对齐 `TaskStatusEnum`
| 状态别名 | 文案 | 默认色族 |
|---|---|---|
| `task-created` | 已创建 | info |
| `task-processing` | 进行中 | primary |
| `task-waiting` | 等待中 | info（灰，与进行中 primary 蓝 区分） |
| `task-pausing` | 暂停中 | warning |
| `task-paused` | 已暂停 | info |
| `task-stopping` | 停止中 | warning |
| `task-completed` | 完成 | success |
| `task-partly-finished` | 部分完成 | warning（区别于 completed 的 success，体现「未完全」） |
| `task-failed` | 失败 | danger |
| `task-waiting-input` | 等待确认 | warning |

#### 类目 2：来源类型（source-*）—— 作者/标签的 local/site
| 状态别名 | 语义 | 默认色族 |
|---|---|---|
| `source-local` | 本地 | tag-red（沿用现状红 `245,108,108`） |
| `source-site` | 站点 | tag-blue（沿用现状蓝 `64,158,255`） |

> 现状 `SearchTagColorUtil.ts` 中「站点作者」用紫 `164,158,255`。本次归并：站点统一用蓝（`source-site`），紫色退出该场景；如需保留紫作者，作为森林/某主题的个别覆盖。

#### 类目 3：开关/运行态（toggle-*）
| 状态别名 | 语义 | 默认色族 |
|---|---|---|
| `toggle-enabled` | 启用/在线/已连接 | success |
| `toggle-disabled` | 禁用/离线/断开 | info |

#### 类目 4：资源/作品状态（resource-*）
| 状态别名 | 语义 | 默认色族 |
|---|---|---|
| `resource-downloaded` | 已下载/完整 | success |
| `resource-missing` | 缺失 | warning |
| `resource-damaged` | 损坏 | danger |

### 3.4 主题覆盖策略

**默认浅色（default-light）**：状态别名即 `:root` 默认值，不重复定义（与现有 `tokens.css` 作为 default-light 令牌来源的约定一致）。

**forest-light / ocean-light / sakura-light**：在各自 `theme-*.css` 覆盖**色族档位**，所有引用它的状态自动跟随；如需个别状态与众不同，再覆盖该别名。

```css
/* theme-forest-light.css */
html[data-theme="forest-light"] {
  /* 整体把 success 调成森林绿系 → task-completed / toggle-enabled / resource-downloaded 全部跟随 */
  --app-color-success: #4a8c3a;
  --app-color-success-light-8: #d8e8cf;
  --app-color-success-light-9: #eaf3e6;
  --app-color-success-dark-2: #3a6e2e;
  /* warning / danger / info 同理按主题色调各覆盖一套档位 */

  /* 个别精调示例：让「失败」在森林主题下更醒目的深红（可选） */
  /* --app-status-task-failed-text: #b03030; */
}
```

> 最小覆盖集：每个非默认主题至少覆盖 success/warning/danger/info 各自的 light-8/light-9/dark-2 + 主色（共 ~16 个值/主题），即可让全部状态色跟随主题。精修可后置。

## 四、渲染层

### 4.1 新建 `StatusTag.vue`（广义状态渲染）
轻量组件，传 `status` key（如 `task-completed`），据令牌渲染浅底深字标签。

设计要点：
- 组件内不写死颜色，全部 `var(--app-status-{status}-bg/text/border)`。
- 提供默认文案注册表（`status` key → label），也支持 `#default` 插槽自定义。
- 支持 `effect="plain/light"` 风格切换（默认浅底；可扩展实底）。

```vue
<!-- 用法 -->
<StatusTag status="task-completed" />
<StatusTag status="task-failed">失败（自定义文案）</StatusTag>
```

实现倾向：用 `:class="`status-tag--${status}`"` + 每状态一条 class 引用对应令牌；或用 `:style` 注入 CSS 变量（更紧凑，约束 status key 须与令牌后缀一致）。**推荐 class 方案**，约束清晰、IDE 可检索。

> 是否同时建一个 `StatusRegistry.ts`（status key → {label, 默认色族} 集中注册表）由实现时定；好处是文案与色族映射单一真相源，TaskManage 的 statusTextMap 可并入。

### 4.2 el-tag 的取舍
- **任务页（TaskManage）**：当前用 `<el-tag :type=...>`，受限于 5 种 type，无法区分「进行中/等待中/暂停中」（现状都挤 warning/primary）。**推荐迁移到 `StatusTag` + 状态别名**，每个任务状态独立配色——这正是用户「广义状态」诉求。el-tag 在任务页退役。
- **其他纯二值场景**（如 success/warning 提示）可继续用 el-tag；前提是该场景所在主题已覆盖对应色族（4.3 节保证）。

### 4.3 保证 el-tag 跟随主题（无论是否迁移都需做）
即使部分 el-tag 保留，也要让它们跟随主题——即**补齐 forest/ocean/sakura 对 success/warning/danger/info 色族的覆盖**（3.4 节）。否则保留 el-tag 的地方仍不跟随。

### 4.4 SegmentedTag 改造（`SegmentedTag.vue`）
- colorConfig 默认值去硬编码：
  - main 段默认引用通用令牌（`--app-tag-blue-*`），hover 引用同色族深一档。
  - sub1/sub2 段引用 `--app-tag-neutral-*`，hover 引用 neutral 浅档。
  - 未选中（disabled）态引用 neutral 浅档。
  - 关闭图标 color 引用 `--app-tag-neutral-text`。
- 新增能力：支持传 `status` key，自动选对应状态令牌（main 段用 `--app-status-{status}-*`），与 StatusTag 对齐——这样 SegmentedTag 既能做分类多段标签，也能承载状态语义。

### 4.5 SearchTagColorUtil 改造（`SearchTagColorUtil.ts`）
从「设置具体 rgb」改为「设置 status key」：
```ts
// 改造前：segmentedTagItem.mainBackGround = 'rgb(245, 108, 108, 25%)' ...
// 改造后：按来源设置 status key，由 SegmentedTag 据令牌渲染
export function setSearchTagStatus(item: SegmentedTagItem, status: string): void {
  item.status = status  // 'source-local' | 'source-site' | ...
}
```
调用方（`AutoLoadTagSelect.vue` 的 `colorResolver`、`WorkQueryView.vue`、`MainView.vue`）改为传 status key。

### 4.6 AutoLoadTagSelect 自定义标签（`AutoLoadTagSelect.vue:199-203`）
硬编码 `rgb(230,162,60,15%)` hover 改为引用 `--app-tag-orange-*`（或定义 `source-custom` 状态别名引用 orange 色族）。

## 六、实施阶段

每阶段独立可验证、可单独提交。

### 阶段 1：令牌层（无业务影响）
- `tokens.css` 新增 `--app-tag-neutral-*` + Layer 1 状态别名（4 类目全量）。
- 三个非默认主题文件各覆盖 success/warning/danger/info 色族档位。
- **验收**：DevTools 临时改某主题的 `--app-color-success`，所有 success 系状态别名变量值随之变化；切主题时 `--app-status-task-completed-text` 实际计算值变化。

### 阶段 2：StatusTag 组件（新增，不改现有）
- 新建 `StatusTag.vue`（+ 可选 `StatusRegistry.ts`）。
- **验收**：在测试页用 `<StatusTag status="task-completed">完成</StatusTag>` 渲染正确颜色；切主题颜色跟随。

## 八、风险与边界

1. **色族档位遗漏**：非默认主题必须覆盖 success/warning/danger/info 的 light-8/light-9/dark-2（el-tag 边框/底/active 用），漏一个即出现档位断层。
2. **状态别名与色族解耦后的二次覆盖**：主题若同时覆盖色族与某别名，别名覆盖优先（CSS 后定义/特异性）——需在主题文件内注释说明，避免误判「色族没生效」。
3. **SegmentedTag status 字段向后兼容**：`SegmentedTagItem` 新增 `status?` 可选字段，旧调用方不传则回退 main 段默认令牌（`--app-tag-blue-*`），不破坏现有观感。
4. **紫色作者色归并**：D5 若选统一蓝，`SearchTagColorUtil` 现有「站点作者=紫」将变蓝——属可见变更，需在迁移说明里提示。
5. **插件不可控边界**：状态令牌作为 `:root` 全局变量，遵循契约的插件可天然复用；硬编码颜色的插件不跟随——靠 `doc/plugin-theme-tokens.md` 约束，非技术缺陷。
6. **el-tag 残留**：若 D2 选迁移，任务页 el-tag 清零；但全局其他 el-tag 仍依赖 4.3 节的色族覆盖才能跟随主题，需一并落地。
