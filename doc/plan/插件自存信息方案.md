# 插件自存信息方案（实现计划）

> 状态：已完成（M1-M7 全部实施，2026-06-25）
> 日期：2026-06-24
> 涉及仓库：`library-squirrel`（主程序）、`library-squirrel-sdk`、`library-squirrel-plugin-pixiv`

## 一、背景与概念重构

### 1.1 现状的临时性
`plugin.plugin_data` 字段（`entity/plugin.go:22`）是**插件还没有自存能力时**的临时补丁：因 pixiv 插件需要缓存 OAuth 认证信息，而在 `plugin` 表上加的一个 `sql.NullString` 字段，由插件整存整取 JSON。

pixiv 插件（`token_manager.go`）的现状用法：
- `plugin.plugin_data` 存 `{ AccessTokenKey, RefreshTokenKey }` —— 指向加密存储的 **key 索引**（插件内部状态）。
- `secure_storage` 存真正的加密 token 值（通过 `StoreEncryptedValue` 拿到 UUID key，再把 key 存回 plugin_data）。
- token 刷新时 `SetPluginData` **整存整取覆盖**整个 blob。

### 1.2 概念重构
"插件设置"本质上是**插件自存信息的一种**。因此本方案不是"再加一张设置表"，而是建立一个**正式的、统一的插件自存信息（Plugin-Owned Storage）体系**，承载插件持久化的所有自己的数据，并让临时的 `plugin.plugin_data` 与割裂的 `secure_storage` 一并退役。

### 1.3 已敲定的决策
| 决策点 | 选择 |
|---|---|
| 设置 UI 渲染 | Schema 驱动（plugin.json 声明，主程序自动生成表单） |
| 设置入口 | 插件管理页按钮（每插件一个"设置"入口） |
| 自存 API 形态 | **统一 KV API**（GetValue/SetValue/SetValueEncrypted/Delete/GetAll），加密是写入选项 |
| 加密存储 | **单表方案**：`plugin_storage` 统一存储（密文存 value，`encrypted` 标记），`util/crypto` 提供加解密，**废弃 secure_storage 模块** |
| plugin_data 退役 | **彻底迁移**（建方案 + 迁移 pixiv + 移除 plugin_data 字段） |
| 关联键 | `plugin_storage.plugin_id`（关联 Plugin 主键 ID） |
| 设置分组 | **完整支持 group**（schema 字段 + 前端分组渲染一次到位） |
| pixiv 范围 | **仅迁移现有自存数据**（token），不新增用户设置声明 |

## 二、目标与范围

### 2.1 目标
1. 建立**正式的插件自存信息**存储（统一 KV，取代临时 plugin_data）。
2. 支持**用户可配置设置**（plugin.json schema 声明 → 主程序 UI 渲染 → 用户编辑 → 持久化）。
3. **彻底迁移** pixiv 插件到统一 API，**移除** `plugin.plugin_data` 字段、`GetPluginData/SetPluginData` 与 `StoreEncryptedValue/GetDecryptedValue/RemoveEncryptedValue` 接口，**废弃** `secure_storage` 模块。

### 2.2 范围内
- 统一 KV 存储（`plugin_storage` 单表，明文与密文共存）。
- `util/crypto` 加解密能力提取。
- plugin.json `extensions.settings` 声明与解析。
- 前端动态表单引擎 + 插件管理页"设置"入口。
- SDK 统一 API（proto/gen/接口）。
- pixiv token_manager 迁移。
- plugin_data 字段移除、secure_storage 模块废弃、数据迁移。

### 2.3 范围外
- `task.plugin_data`（任务流程中间数据，**不动**）。
- 插件市场、设置导入导出、设置版本迁移。
- 加密密钥的安全加固（硬编码密钥问题另案处理，仅在风险中记录）。

## 四、总体设计

### 4.1 统一概念
插件面对**一个**自存信息存储（KV），写入时声明是否加密。加密只是写入时的一个变换，**存储全部由 `plugin_storage` 单表完成**（加密项 value 存密文，`encrypted` 标记区分），不再有第二张加密表：

```
插件代码 / 用户设置 UI
        │  GetValue / SetValue / SetValueEncrypted / Delete / GetAll
        ▼
   统一 KV API（PluginContext）
        │
        ▼
   plugin_storage 表（plugin_id + key + value + encrypted）
        │
        ├── encrypted=false ──► value 为明文，直接读写
        └── encrypted=true  ──► value 为密文，写入前 Encrypt / 读取后 Decrypt（util/crypto）
```

> 设计取舍：曾考虑"密文存 secure_storage + plugin_storage 存索引"的双表方案，但对加密项构成冗余存储（两表、跨表查询、一致性风险）。单表方案更简洁，加解密由 `util/crypto` 纯函数承担，对插件 SDK 契约完全透明。

### 4.2 统一 KV API（SDK PluginContext）
```go
// 插件自存信息（统一 KV）
GetValue(key string) (string, error)          // 读，加密项自动解密
SetValue(key, value string) error             // 写明文
SetValueEncrypted(key, value string) error    // 写加密（value 经 Encrypt 后存密文）
DeleteValue(key string) error                 // 删
GetAllValues() (map[string]string, error)     // 读全部（含解密）
```
- 插件只在**写入**时分 `SetValue` / `SetValueEncrypted`；读、删、列举对加密项**透明**，统一返回明文。
- 加密的复杂性完全封装在主程序底层，插件无需关心 key 索引、加密细节。

### 4.3 schema 驱动的用户设置
plugin.json 声明哪些 key 是用户可配置 + 元信息，主程序据此渲染表单：
```jsonc
"extensions": {
  "settings": [
    { "key": "downloadQuality", "type": "select", "title": "下载质量",
      "options": [{"label":"原图","value":"original"},{"label":"压缩","value":"compressed"}],
      "default": "original", "description": "默认下载图片质量", "group": "下载", "order": 1 },
    { "key": "apiToken", "type": "string", "title": "API Token",
      "encrypted": true, "description": "第三方 API 凭证", "group": "账号", "order": 2 }
  ]
}
```
- 用户在 UI 改 → 主程序按 schema 的 `encrypted` 调 `SetValue` / `SetValueEncrypted`。
- 插件代码 `GetValue(key)` 热读取用户配置。

## 五、详细设计

### 5.1 数据模型

**新增实体 `PluginStorage`**（统一承载插件自存信息，明文与密文共存于单表）：
```go
// backend/base/model/entity/plugin_storage.go
type PluginStorage struct {
    *model.BaseEntity
    ID         int64  `gorm:"primaryKey;column:id"`
    PluginID   int64  `gorm:"column:plugin_id;uniqueIndex:idx_plugin_key"`
    Key        string `gorm:"column:key;uniqueIndex:idx_plugin_key"`
    Value      string `gorm:"column:value"`         // 明文值 或 密文(base64)
    Encrypted  bool   `gorm:"column:encrypted"`     // true=密文（读取需 Decrypt）
    CreateTime int64  `gorm:"column:create_time"`
    UpdateTime int64  `gorm:"column:update_time"`
}
// TableName: plugin_storage；唯一索引 (plugin_id, key)
// 迁移注册到 backend/migration/migrate.go
```

**加密能力提取**（`backend/util/crypto.go`）：将现 `secureStorage/service.go:188-226` 的 `encrypt/decrypt` 提取为纯函数 `Encrypt/Decrypt`（+ 密钥），与 `util/image.go`、`util/time.go` 风格一致（符合 util 纯函数规则）。`plugin_storage` service 写入加密项时 `Encrypt` 后存 value，读取时按 `encrypted` 标记 `Decrypt`。

**plugin.plugin_data 字段 / secure_storage 模块**：迁移完成后从 `Plugin` 实体移除字段、废弃整个 `secure_storage` 模块（见 5.7）。

### 5.2 SDK 变更（`library-squirrel-sdk`）
1. **proto**（`proto/plugin.proto`）：新增 5 个 RPC
   - `GetValue(key) -> PluginStorageResponse{value}`
   - `SetValue(key, value) -> Empty`
   - `SetValueEncrypted(key, value) -> Empty`
   - `DeleteValue(key) -> Empty`
   - `GetAllValues() -> PluginStorageMapResponse{values: map<string,string>}`
   - 移除 `GetPluginData/SetPluginData` 与 `StoreEncryptedValue/GetDecryptedValue/RemoveEncryptedValue`（统一 API 取代）。
2. **重新生成** gen（`library-squirrel-sdk/gen/`）。
3. **PluginContext 接口**（`dto/context.go`）：加 5 个新方法，移除上述 5 个旧方法。

> SDK 经 go.mod replace 指向本地，改完主程序重新编译即生效。

### 5.3 plugin.json 声明解析
- `backend/base/model/dto/plugin_types.go`：`PluginExtensions` 增 `Settings []SettingDeclaration`。
- 新增 `SettingDeclaration`：`Key/Type/Title/Description/Default/Encrypted/Min/Max/Options/Order/Group`。
- 加载插件时校验（key 唯一、type 合法、default 类型匹配）。
- 通过 `PluginHandler` 暴露给前端（插件详情含 settings 声明）。

### 5.4 后端实现（`backend/plugin`）
1. **repository**：`PluginStorageRepository`（复用 `BaseRepository[PluginStorage]`），按 `plugin_id` 批量查询。
2. **service**：`PluginStorageService`（依赖 `util/crypto`）
   - `GetValue(pluginID, key)`：查 `plugin_storage`，`encrypted=true` 则 `crypto.Decrypt(value)` 返回明文。
   - `SetValue(pluginID, key, value)`：upsert（value=明文, encrypted=false）。
   - `SetValueEncrypted(pluginID, key, value)`：upsert（value=`crypto.Encrypt(value)`, encrypted=true）。
   - `DeleteValue`、`GetAllValues`（批量查 + 批量解密加密项）。
   - 用户设置场景：`GetSettings(publicId)`（合并声明默认值 + 存储值，加密项解密）、`ResetValue`（恢复默认）。
   - 遵循 `SERVICE_DEPENDENCY_VIA_INTERFACE`、`ELIMINATE_N_PLUS_1_QUERY`。
3. **handler**：`PluginSettingHandler`
   - `GetSettings(publicId)`、`SaveSetting(publicId, key, value)`、`ResetSetting(publicId, key)`。
   - `wails3 generate bindings -ts` 生成前端绑定。
4. **HostService 实现**（`plugin/extension/loader.go`）：实现 5 个新 RPC，路由到 `PluginStorageService`（单表，不再依赖 secure_storage）。删除旧 `hostPluginDataProvider`、`hostSecureStorageProvider`。

### 5.5 前端实现（`frontend/src`）
1. **动态表单引擎**（新建 `components/plugin/PluginSettingForm.vue`）：按 schema.type 分发控件
   - `string`→`el-input`；`integer`→`el-input-number`（含 min/max）；`boolean`→`el-switch`；`select`→`el-select`；`encrypted`→密码输入。
   - **分组渲染**：按 setting 的 `group` 字段聚合，同组用 `el-divider`（`content-position="left"`）分隔并显示组名；无 `group` 的归入默认组（不显示分隔标题）；组内按 `order` 排序。
   - 全程用 `--app-*` 主题令牌；校验失败 `throw new Error`（UNIFIED_ERROR_THROW）。
2. **入口**（`PluginManage.vue`）：声明了 settings 的插件行加"设置"按钮 → 打开 `PluginSettingDialog`（基于 `FormDialog`，内嵌 `PluginSettingForm`）。
3. **wrapper**（`apis/http/wrappers/pluginSetting.ts`）：`getSettings/saveSetting/resetSetting`，走 `requireResponse`。
4. **类型**：settings 声明迁移到 `frontend/src/model/model/`。

### 5.6 pixiv 迁移（`library-squirrel-plugin-pixiv`）
> 范围：**仅迁移现有自存数据**（accessToken / refreshToken 两个加密项），**不新增** `extensions.settings` 用户设置声明。
- `token_manager.go`：用 `SetValueEncrypted("accessToken", token)` / `GetValue("accessToken")` 取代"plugin_data 存 key 索引 + secure_storage 存密文"的间接层。
- 移除 `model.PluginData{ AccessTokenKey, RefreshTokenKey }` 中间结构。
- 启动加载改为 `GetValue`（缺失则触发登录流程）。

### 5.7 plugin_data 与 secure_storage 移除
1. pixiv 迁移完成、无插件再依赖旧接口后。
2. **数据迁移脚本**（一次性，提供回退校验）：
   - 存量 `plugin.plugin_data`（pixiv 的 key 索引）→ 解析出 accessTokenKey/refreshTokenKey。
   - 存量 `secure_storage`（按 key 取 token 密文）→ 写入 `plugin_storage.value`（密文, encrypted=true）。
   - 保证 token 不丢失。
3. 从 `entity.Plugin` 移除 `PluginData` 字段；清理 `loader.go:176`、`service.go:376,603`、`status.go:16`、`dto/plugin_dto.go:26` 等引用。
4. 移除 SDK proto 的 `GetPluginData/SetPluginData`、`StoreEncryptedValue/GetDecryptedValue/RemoveEncryptedValue` RPC 与相关字段。
5. **废弃 `secure_storage` 模块**：删除 `backend/secureStorage/`（entity/repo/service/handler）、清理 `app.go` 的 `SecureStorageService/Handler` 注册与 `PluginContextDeps.SecureStorage` 注入、移除 `migration` 的 `SecureStorage` 注册。

## 八、风险与已确认点

1. **跨仓库改动**：SDK + 主程序 + pixiv 三仓库联动，需保证 SDK 先发布、主程序与 pixiv 跟进；replace 指向本地便于联调。
2. **存量数据迁移**：M6 需把 pixiv 现有 `plugin_data`（key 索引）和 `secure_storage`（token 密文）一并迁到 `plugin_storage`，并保证 token 不丢失；建议提供迁移 + 回退校验。
3. **加密密钥硬编码**：从 `secureStorage` 提取到 `util/crypto` 时沿用，存在安全隐患，建议另案加固（不在本期）。
4. **已确认的设计点**：
   - `plugin_storage` 关联用 `plugin_id`（Plugin 主键 ID）。
   - 加密存储采用**单表方案**（密文存 `plugin_storage.value`），`util/crypto` 提供加解密，废弃 `secure_storage` 模块。
   - 用户设置**完整支持 group 分组**（schema 字段 + 前端分组渲染）。
   - pixiv **仅迁移现有自存数据**（token），不新增用户设置声明。
