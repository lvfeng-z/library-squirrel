# 站点主数据注册表投影方案

## 审查摘要

**关键声明**
- 声明1　站点行生产写入方现状 = 两处：插件 AddSite（`backend/plugin/extension/plugin_context.go:178-205`，经 `SiteSaveProvider.Create` 落库）与导入/分享回灌 find-or-create（`backend/import/ingest.go:623-663`）；手动 Save 已于 82335c6 退役。
- 声明2　站点入库绑定插件（用户发现实证）：根 `config.yaml:3-5` 仅声明 pixiv 捆绑包 → 2026-09-02 20:08 首启仅 pixivSuite 激活、site 表仅 pixiv 一行；local/bilibili 行在 20:11 经 InstallFromPath 安装插件后才出现（本日 live-test 会话实测：SQL 断言 + 激活日志行「插件子进程已激活: com.lvfeng.localImport / com.lvfeng.bilibiliSuite」@20:11:25，证据 `.claude/testing/runs/20260902-site-retirement/evidence/log-tail-from-6195.txt` 与报告 01/02 项）。
- 声明3　SDK identity 包仅 `Lookup` 出口、无私有 registry 枚举 API（`library-squirrel-sdk/identity/registry.go:60-71`）——投影同步需要新增 `All()`。
- 声明4　AddSite RPC 唯一作用 = 建站点行：SDK proto → transport → 宿主 `pluginContext.AddSite`（键校验+查重+建行）；插件激活侧调用（三官方插件 activate.go）。投影后整链冗余。
- 声明5　五类 `SiteRefCounter` 接口（`backend/site/service.go:25-50`）仅服务 Delete 前置守卫；test-plugin 不调 AddSite（grep 零命中）。
- 声明6　任务创建路由按 `GetByKey` 回填 SiteID（`backend/site/README.md:23`）——投影后注册键站点行必在，该路径的「站点未找到」分支对注册键成为不可能态。
- 声明7　注册表只增不改 + 键不可变（谱系终裁决策）→ **insert-only 投影完备**：新键只会追加、既有键永不消失，同步无需删除分支。
- 声明8　pb 再生成管线本日已两次使用（SDK 工作区 proto+gen 提交 6445916 即其产物），工作流已验证；buildId 时序纪律（插件仓先提交再 build:plugins）沿用 E 方案第四节。

**裁决记录（2026-09-02，方向与决策1-4 全部落定）**
- 用户裁定方向：站点跟随 SDK 注册表（含未来热更新签名包自动加入），不跟随插件——本方案即为该方向的落地方案。
- 决策1 → **是**：站点 Delete + 五类引用守卫一并退役——投影行删除后下次启动同步复活，删除语义不成立；守卫成死代码。残余面：DB 手改产生的悬空键行失去删除入口（正常路径不可能产生，接受并记录）。
- 决策2 → **是**：导入回灌 find-or-create 收敛为 find-only——投影保证注册键行必在，缺失 = 数据异常应显式报错（契约直通、无静默自愈）。
- 决策3 → **是**：AddSite RPC 从 SDK proto 全链移除（含 pb 再生成）——**前提如实陈述**：AddSite 已随 SDK tag v0.0.5/v0.0.6 发布（eeedf09 引入），删除后旧 tag 编译的插件调用该方法将得 unimplemented 拒绝；现实代价≈零（主仓与三官方插件 go.mod 均 replace 指向本地 SDK、无第三方消费方），接受。
- 决策4 → **接受**：站点选择器/筛选将列出全部注册站点（含零数据站点）——接受为投影语义；「仅有数据站点」过滤属后续 UX 项不入本次。**本决策不涉及选择器数据源变更**——共 **10 个**前端文件消费 `siteQuerySelectItemPage(BySiteName)`（SiteTagManage/SiteAuthorManage/RecycleBin/LocalTagManage/LocalAuthorManage/WorkDialog/WorkDetailDialog/TaskList/SiteTagDialog/SiteAuthorDialog），全部继续查站点表（本地 id 锚点 + 用户改名展示均依赖表；直读内存注册表会丢 id 映射与改名，且形成数据源分叉）。
- 决策5 → **同步失败 = 启动失败（fail-fast）**：投影同步属装配期 DB 操作，错误处理与 DB 初始化/AutoMigrate 同类——报错阻断启动，不做「跳过待下次重试」（静默跳过会令站点表缺行，任务创建/导入报「站点未找到」等衍生异常掩盖根因；insert-only 幂等保证重启后重试安全）。

**自曝风险**
- 风险1　语义迁移：「站点表 = 本库实际使用面」的信号消失——未来「本库用过哪些站点」类需求须经作品/标签数据查询；spec/README 须显式言明新语义。
- 风险2　选择器/筛选出现零数据站点（决策4 承接）。
- 风险3　五类 `CountBySiteId` 仓储实现分布于 work/task/workSet/siteTag/siteAuthor 五模块仓储——退役时须 grep 复核无守卫外消费方（当前检索仅守卫；漏删由编译兜底，误删由该复核防）。
- 风险4　延后节点 D（谱系延后项「中心签名的注册表运行时更新包」）表述需更新（不实施 D）：热更新签名包并入 Lookup → 下次启动投影自动建行——D 的价值随投影落地更具体；未实施 D 前新键仍需「SDK 合并 + 主程序发版」。
- 风险5　AddSite 退役后若未来出现「插件声明服务站点」的新需求（如市场按站点筛插件），须另立声明契约而非复活 AddSite（方向性约束）。

## 背景

E 方案（手动建站退役）落地后，用户首启实测（config.yaml 仅配 pixiv 插件）发现站点表仅 pixiv 一行——**站点入库仍绑定在插件激活的 AddSite 上**。这与身份模型的对称性缺口：注册表是站点身份的唯一权威（中心签发、编译期内置），插件只是内容生产者，站点主数据却由生产者按需声明。用户裁定：**站点主数据跟随注册表走**（含 D 节点热更新签名包落地后自动加入），插件不再承担站点建行职责。

## 设计

### 一、投影同步（核心）

- **SDK**：identity 包新增 `All() []Site`——注册表全量枚举（按注册序稳定输出）；D 节点热更新包未来并入 Lookup 时自然含增量，投影自动跟进。
- **主仓启动同步**：app.go 服务装配后、InstallBundledPlugins 与 LoadPlugins 之前，遍历 `identity.All()`：`GetByKey` 缺失 → `NewSite` 落注册表权威值（Key/Name/Homepage，local 无 Homepage 落 NULL）。**insert-only，绝不更新既有行**——幂等，且用户对展示名（site_name 可改语义）的编辑持久。**同步失败 = 启动失败**（决策5，与装配期 DB 初始化/AutoMigrate 同类 fail-fast）。
- 纯 DB 操作、不依赖 workdir——与 InstallBundled 的 workdir 未配置拒绝（af4edce）无交互。

### 二、AddSite 全链退役（决策3）

- SDK：`proto/plugin.proto` 删 AddSite RPC + pb 再生成；transport/dto 接线删。
- 主仓：`pluginContext.AddSite`、`SiteSaveProvider` 接口（plugin_context.go:32-35）、**`SiteQueryProvider` 接口（:37-40）及其装配（PluginContextDeps.SiteSave/SiteQuery、`app.go` 接线、hostSiteSaveProvider）**——SiteQueryProvider 唯一生产调用是 AddSite 查重（plugin_context.go:186），随 AddSite 一并成死代码、全链删除；`plugin_context_addsite_test.go` 删除——键校验/建行逻辑由投影同步测试替代锚定（未注册键拒绝语义已由 import 侧 E2E + 单测锚定，见 `.claude/testing/runs/20260902-site-retirement/` 05 项）。
- 三插件 activate.go 删 AddSite 块（bilibili 的 task_handler 仍用 `identity.Bilibili` 常量，import 保留）。

### 三、Delete + 守卫退役（决策1）

- `Handler.Delete` 删；service 聚合守卫与五类 `SiteRefCounter` 接口删；五模块仓储 `CountBySiteId` 实现删（实施时 grep 复核无守卫外消费方，风险3）。
- 站点管理页行操作收敛为 查看 / 编辑；站点行生命周期 = 注册表投影（只进不出）。

### 四、导入回灌收敛（决策2）

- `ingest.go` 的 find-or-create 改 find-only：按 `GetByKey` 直查，注册键行缺失（投影下不可能，属 DB 异常）显式报错，不静默自建。`validateSiteKeys` 前门不变。

### 五、文档与谱系同步

- `backend/site/README.md`：职责改「注册表投影 + 展示字段编辑」；写入方封闭为「启动投影同步」单一。
- `doc/site-identity-spec.md` 第四节：站点行写入方表述改为投影同步单一来源；补「站点表=注册表投影，非本库使用面」语义说明（风险1）。
- `.claude/rules/backend.md` Site 概念行、`.claude/rules/plugin.md` SDK 能力表（删 AddSite 行）。
- 谱系 TREE：D 节点（谱系延后项「中心签名的注册表运行时更新包」）表述更新（风险4）；本任务作为新节点挂于谱系「站点管理机制收敛」节点之下。

### 六、随行提交

工作区遗留的 `ingest.go` 未注册键文案修复（「站点手动建站退役与 bilibili 键补迁移」方案 live-test 发现，已修复复验未提交）随本次先行独立提交（fix(import)），不与投影变更混笔。
