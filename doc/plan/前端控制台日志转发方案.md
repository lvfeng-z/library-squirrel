# 前端控制台日志转发方案

> 状态：评审中（已并入用户决策：单独 frontend.log + 仅 dev 开）
> 日期：2026-06-28
> 范围：后端新增 `frontendLog` 模块（handler + service）+ 扩展 `logger` 包支持第二个 logger 实例；前端劫持 `console.*` + 全局错误捕获，经 Wails binding 批量转发
> 隔离：本方案在 worktree `console-log-forward`（分支 `worktree-console-log-forward`，基线 `origin/master`）内实现，不触碰主工作区进行中的多轨重构改动

## 一、背景与目标

前端运行在 WebView 中，`console.*` 与未捕获异常只停留在 DevTools，无法落盘。Wails v3 无“webview console 转发文件”能力，CDP 方案过重。

**目标**：把前端 `console.*` 与未捕获异常转发到后端，落盘到独立的 `log/frontend.log`，便于事后排查。

## 二、设计决策

1. **落盘位置：独立 `log/frontend.log`**（用户决策）。后端 `logger` 包新增第二个 logger 实例 `FrontendLog`，独立 lumberjack，与 `server.log` 物理隔离，互不污染。
2. **仅 dev 开**（用户决策）：**前端用 Vite 原生 `import.meta.env.DEV` 作主开关**。
   - dev server（`wails3 task common:dev:frontend`）下 `import.meta.env.DEV === true` → 劫持 console 并转发。
   - 生产构建（`yarn build`）下为 `false` → 不劫持、不发送。
   - 因 lumberjack **惰性创建文件**（无首次写入则不产生文件），生产环境不会出现 `frontend.log`，满足“生产不开”，且后端无需任何 dev 检测、不改 build tag / Taskfile。
   - 不采用 Wails 内部 `dev` build tag：`wails3 build DEV=true` 是否等价 `-tags dev` 不确定，且官方警告 `dev`/`debug` 为保留 tag 易冲突（[Issue #4438](https://github.com/wailsapp/wails/issues/4438)）。
3. **传输走 Wails binding，前端批量 + 防抖**：`console` 高频，逐条 IPC 会打爆通道。前端缓冲，满 20 条或每 200ms flush，一次性传 `[]FrontendLogEntry`；页面隐藏/卸载前尽力 flush。
4. **仍调用原始 console 方法**：劫持后先序列化入缓冲，再调用原始方法，DevTools 行为不变。
5. **忠实复刻 DevTools Console（用户明确要求）**：只捕获**开发者工具 Console 面板显示的内容**——`console.log/info/warn/error/debug/trace` 全级别劫持（主体，含 Vue/第三方库的 console 调用）+ `window.onerror`（DevTools 的 Uncaught）+ `unhandledrejection`（Uncaught in promise）。**不设** Vue `errorHandler`/`warnHandler`：Vue 渲染错误/警告默认经 `console.error`/`console.warn` 输出，已被 console 劫持覆盖，与 DevTools 一致。**不纳入** HTTP 请求 / Wails IPC 调用（不属于 console 内容）；**不捕获**资源加载 404 等浏览器层错误（不经 console API）。后端 `frontend.log` 用 `DebugLevel` 全量落盘，不受 `config.yaml` 的 `log.level` 过滤。
6. **不再加 `log.collectFrontend` 配置项**：开关已由前端 `import.meta.env.DEV` 承担，后端始终接收。

## 三、技术路径

```
前端 console.* / 全局错误
   │  仅 import.meta.env.DEV 为 true 时劫持
   │  序列化参数(对象 JSON.stringify + 循环引用兜底)
   ▼
缓冲区 ──(满 20 条 / 200ms / 隐藏·卸载 flush)──▶ frontendLogApi.write(entries)
   │ Wails binding (批量)
   ▼
FrontendLogHandler.Write(ctx, []FrontendLogEntry)
   ▼
FrontendLogService.Write → logger.FrontendLog.Xxx(msg, fe_ts=...)
   ▼
log/frontend.log（独立 lumberjack，惰性创建）
```

## 四、详细设计

### 4.1 后端：扩展 `backend/base/logger/` 支持双实例

`logger.go` 新增第二个全局 logger 与独立 writer：

```go
var (
	Log         *zap.SugaredLogger // 后端业务日志 → server.log（控制台+文件）
	FrontendLog *zap.SugaredLogger // 前端转发日志 → frontend.log（仅文件）

	logWriter         io.Closer // server.log 的 lumberjack
	frontendLogWriter io.Closer // frontend.log 的 lumberjack
)
```

`initWithConfig` 内，在现有 server.log core 之后追加：

```go
// frontend.log 写入器（独立 lumberjack；惰性创建文件：无写入则不产生文件，故生产无此文件）
feWriter := &lumberjack.Logger{
	Filename:   filepath.Join(logDir, "frontend.log"),
	MaxSize:    cfg.MaxSize,
	MaxBackups: cfg.MaxBackups,
	MaxAge:     cfg.MaxAge,
	Compress:   cfg.Compress,
}
frontendLogWriter = feWriter
feCore := zapcore.NewCore(
	zapcore.NewJSONEncoder(encoderConfig),
	zapcore.AddSync(feWriter),
	zapcore.DebugLevel, // 前端日志全收，便于 dev 排查
)
FrontendLog = zap.New(feCore).Sugar() // 仅写文件，不回控制台（避免噪音/循环）
```

`Reinit` 关闭两个 writer（释放句柄，避免轮转 rename 失败，与现有 server.log 同理）：

```go
if logWriter != nil { _ = logWriter.Close(); logWriter = nil }
if frontendLogWriter != nil { _ = frontendLogWriter.Close(); frontendLogWriter = nil }
```

`Sync` 同时 flush 两个 logger。

### 4.2 后端：新建 `backend/frontendLog/`

无 DB 依赖，仅 handler + service + DTO。

**`dto.go`**：

```go
package frontendLog

// FrontendLogEntry 前端单条日志
type FrontendLogEntry struct {
	Level     string `json:"level"`     // debug/info/warn/error
	Message   string `json:"message"`   // 序列化后的消息文本
	Timestamp int64  `json:"timestamp"` // 前端时间戳（毫秒）
}
```

**`service.go`**：

```go
package frontendLog

import (
	"context"

	"github.com/library-squirrel/backend/base/logger"
	"go.uber.org/zap"
)

// Service 前端日志收集服务
type Service struct{}

func NewService() *Service { return &Service{} }

// Write 批量写入前端日志到独立的 frontend.log
func (s *Service) Write(ctx context.Context, entries []FrontendLogEntry) error {
	for _, e := range entries {
		ts := zap.Int64("fe_ts", e.Timestamp)
		switch e.Level {
		case "error":
			logger.FrontendLog.Error(e.Message, ts)
		case "warn":
			logger.FrontendLog.Warn(e.Message, ts)
		case "debug":
			logger.FrontendLog.Debug(e.Message, ts)
		default: // info 及未知级别
			logger.FrontendLog.Info(e.Message, ts)
		}
	}
	return nil
}
```

**`handler.go`**：

```go
package frontendLog

import (
	"context"

	"github.com/library-squirrel/backend/base/model"
)

// Handler 前端日志 Handler
type Handler struct {
	svc *Service
}

func NewHandler(svc *Service) *Handler { return &Handler{svc: svc} }

// Write 接收前端批量日志并落盘
func (h *Handler) Write(ctx context.Context, entries []FrontendLogEntry) *model.ApiResponse[any] {
	return model.HandleVoid(h.svc.Write(ctx, entries))
}
```

**注册**：
- `app.go`：`App` 加字段 `FrontendLogService *frontendLog.Service`、`FrontendLogHandler *frontendLog.Handler`；`initBaseServices` 内 `app.FrontendLogService = frontendLog.NewService()`；`initHandlers` 内 `app.FrontendLogHandler = frontendLog.NewHandler(app.FrontendLogService)`。
- `main.go`：`application.Options.Services` 追加 `application.NewService(app.FrontendLogHandler)`。

### 4.3 前端集成

**`frontend/src/apis/http/wrappers/frontendLog.ts`**（新）：封装生成的 binding（写操作 `requireData=false`）。实现时按现有 wrapper（如 `settings.ts`）确认 `requireResponse` 导入路径与 binding 命名空间。

**`frontend/src/utils/ConsoleForward.ts`**（新）：

```ts
import { frontendLogApi, type FrontendLogEntry } from '@renderer/apis/http/wrappers/frontendLog'

const BUFFER_LIMIT = 20
const FLUSH_INTERVAL = 200

let buffer: FrontendLogEntry[] = []
let timer: ReturnType<typeof setInterval> | null = null

// 序列化单个参数：对象尝试 JSON.stringify，循环引用 / 失败兜底为 String
function serializeArg(arg: unknown): string { /* ... */ }

function append(level: FrontendLogEntry['level'], args: unknown[]) {
  buffer.push({ level, message: args.map(serializeArg).join(' '), timestamp: Date.now() })
  if (buffer.length >= BUFFER_LIMIT) flush()
}

function flush() {
  if (timer) { clearInterval(timer); timer = null }
  if (buffer.length === 0) return
  const batch = buffer
  buffer = []
  frontendLogApi.write(batch).catch(() => { /* 静默：日志失败不得影响业务 */ })
}

// 劫持 console（保留原始方法，DevTools 行为不变）
export function setupConsoleForward() {
  const original = { log: console.log, info: console.info, warn: console.warn, error: console.error, debug: console.debug }
  const wrap = (level: FrontendLogEntry['level'], fn: (...a: unknown[]) => void) =>
    (...args: unknown[]) => { append(level, args); fn.apply(console, args) }
  console.log = wrap('info', original.log)
  console.info = wrap('info', original.info)
  console.warn = wrap('warn', original.warn)
  console.error = wrap('error', original.error)
  console.debug = wrap('debug', original.debug)

  timer = setInterval(flush, FLUSH_INTERVAL)

  window.addEventListener('error', (e) => append('error', [e.message, e.filename, `:${e.lineno}:${e.colno}`]))
  window.addEventListener('unhandledrejection', (e) => append('error', ['unhandledrejection', e.reason]))
  document.addEventListener('visibilitychange', () => { if (document.visibilityState === 'hidden') flush() })
  window.addEventListener('beforeunload', flush)
}
```

**`main.ts`**：仅 dev 接入，并在 `createApp` 前调用；Vue 错误处理器接入：

```ts
if (import.meta.env.DEV) {
  setupConsoleForward()   // 尽早劫持 console（createApp 之前），Vue 默认的 console.error/warn 一并被覆盖
}
const app = createApp(App)
```

> 时序：`setupConsoleForward` 在 `createApp` 之前执行，后续所有 `console.*` 均被劫持；binding 由 Wails 在 DOM 就绪前注入，首次 flush 前 binding 已可用（失败则静默丢弃，不影响业务）。

### 4.4 时序

1. `main.go`：`logger.Init()` 最先 → `Log` 与 `FrontendLog` 就绪（`frontend.log` 此时尚未创建，惰性）。
2. `NewApp()` → `initBaseServices` 构造 `FrontendLogService`。
3. `wailsApp` 创建，Services 含 `FrontendLogHandler`。
4. 前端 `main.ts`：`import.meta.env.DEV` 为 true 时 `setupConsoleForward()` → 劫持 → 批量转发 → 首次写入时 `frontend.log` 才被创建。

## 五、限制与边界

1. **循环引用对象**：`serializeArg` 遇循环引用 / 序列化失败回退 `String(arg)`。
2. **IPC 频次**：批量 + 防抖，单次最多 `BUFFER_LIMIT` 条；`flush` 失败静默。
3. **DevTools 行为不变**：保留并调用原始 console 方法。
4. **生产无副作用**：prod 前端 `import.meta.env.DEV=false` 不劫持不发送；`frontend.log` 因 lumberjack 惰性创建而不会产生；后端 `FrontendLogHandler` 在 prod 二进制存在但无调用。
5. **时间戳**：记录前端 `Date.now()`（毫秒）入 `fe_ts`，与后端落盘时间可能微差，仅作参考。
6. **范围**：主窗口前端。插件前端组件运行在主程序 Vue 实例下，其 console 也会被劫持（同源）；如需区分可后续加字段，本期不做。

## 六、实施阶段

- **阶段 1（后端-日志）**：扩展 `backend/base/logger/logger.go` 双实例（`FrontendLog` + 独立 writer + Reinit/Sync 同步管理）。
- **阶段 2（后端-模块）**：新建 `backend/frontendLog/`（dto + service + handler）；`app.go` 注册 service/handler，`main.go` 加 Service。
- **阶段 3（bindings）**：`wails3 generate bindings -ts` 生成 `FrontendLogHandler` 的 TS binding。
- **阶段 4（前端）**：新建 `frontendLog.ts` wrapper、`ConsoleForward.ts`；`main.ts` 在 `import.meta.env.DEV` 下接入 + Vue `errorHandler`。
- **阶段 5（验证）**：`task dev`，前端触发 `console.log/warn/error` 及一次未捕获错误，确认 `log/frontend.log` 出现记录且级别正确、DevTools 控制台仍正常；生产构建（`yarn build`）确认不产生 `frontend.log`（可选验证）。

## 七、可选增强（本期不做）

- 插件前端日志按来源字段区分。
- 前端日志级别过滤（仅转 `warn`/`error`）以进一步降噪。
- source map 还原压缩后行号（生产构建场景，但本期 prod 不收集，无此需求）。
- 若日后要求 prod 二进制彻底移除 handler，再引入自定义 build tag（如 `-tags frontendlog`）+ 改 Taskfile。
