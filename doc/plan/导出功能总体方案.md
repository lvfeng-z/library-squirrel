## 审查摘要

**关键声明（抽查项）：**
- 声明1：task 实体当前**无 type/kind 维度字段**，任务行为完全由 `(plugin_public_id, plugin_extension_id)` → registry → TaskExecutor 决定（`backend/base/model/entity/task.go:10-29`；`backend/taskManager/model.go:137-155`）
- 声明2：TaskExecutor 接口是「下载流」契约——`Start` 返回 `[]*StoreSpec`（带 ReadCloser 文件流），`Pause`/`Resume` 按 StreamOffsets 断点续传；进度按字节累加（`backend/taskManager/model.go:139-155` 接口定义；`model.go:441-442` progressTotal「资源总大小」/progressFinished「已下载字节数」）
- 声明3：作品网格**多选基建已存在**，非「无多选交互」——CardGrid 提供 `checkable`/`checkedIds`/`checkedChange` 契约（`frontend/src/components/common/CardGrid.vue:6-22,24-75`），WorkCard/WorkSetCard 提供 `checkable` prop + `checked` model + 悬停勾选角标（`WorkCard.vue:17,24,77-92`、`WorkSetCard.vue:15,20,80-89`），WorkQueryView 已示范完整接线（`frontend/src/components/common/WorkQueryView.vue:42,57,68-69,246,362`）。**真实缺口**：主页两网格硬编码 `:checkable="false"` 未接线（`WorkGridForMainPage.vue:52,62`、`WorkSetGridForMainPage.vue:43,53`）
- 声明4：localImport 插件按「目录名分类」导入，标签/作者语义靠路径名猜测、无法保真回灌（`E:/code/lvfeng/library-squirrel-plugin-local/path_rule.go:48-74` 的 PathClassifier 按目录层级分类；`scanner.go:104` 的 GroupFilesByParentDir 按父目录分组）
- 声明5：作品集间为**多父 DAG** 层级（`backend/base/model/entity/re_work_set_work_set.go:9-18`）；作品↔作品集关联带 `sort_order`/`site_sort_order` 双轨排序（`backend/base/model/entity/re_work_work_set.go:12-15`）；作品集自带 `cover_work_id` 封面引用（`backend/base/model/entity/work_set.go:27-29`）
- 声明6：作品↔标签关联带 namespace 维度（`backend/base/model/entity/re_work_tag.go:12-17`），site_tag 另存站点侧 namespace
- 声明7：资源↔store 关联为「1 Resource 挂 N typed store」，带 `store_type`/`generation`/`store_seq`（`backend/base/model/entity/resource_store.go:24-31`），文件落盘在 `persistent_store.file_path`（workDir 相对路径）
- 声明8：本仓库已有 store 文件命名规约 `<bas>_<role>_<seq>[_<描述>].<ext>`（`doc/store-naming-convention.md:19-25`），供导出同名消解复用

**已定决策（2026-08-26）：**
- 决策1：**任务模块接入延后**——基本导出功能实现后再议；本次范围**不含**执行面剥离与任务面板接入，导出执行走「异步 + 进度」轻量壳（对齐 longops-task-integration-plan.md 阶段1 的合并异步化先例）。任务接入（含该文档方向锁 C 的阶段2 执行面剥离）记为延后分支
- 决策2：**选择只作用于作品/作品集**——导出交互嵌在主视图，仅作品、作品集两种选择操作；标签/作者是作品的附加数据、不存在「选择」概念，**永远完整连带导出**。成员关系语义：跨选择项的关联保留（选中的作品集与其成员作品的归属）、指向未选作品集的成员关系丢弃（「选择即单位」，见第2节）
- 决策3：**包内按确定性命名的作品目录组织**（非内容哈希平铺）——同输入同输出结构，目录承担人眼可读，manifest 承担保真（见第3节）
- 决策4：**源文件缺失 → 跳过 + manifest 标注缺失**——导出继续，缺失的 store 在 manifest 中标记，回灌时该 store 缺席、其余照常（不做中断报错的严格模式）；导出是首个批量读「全部活行文件」的消费侧，此处置已定
- 决策5：**id 列表透传**——前端把选中的 work/workSet id 列表传给后端收集；万级全选时收集接口分批或设上限保护（边缘场景，不引入后端范围查询的条件上下文复杂度）

**待决策（需用户拍板）：**
- 决策6（不阻塞）：作品目录是否按**作者分组**（`works/<作者>/<作品名>/` vs 默认平铺 `works/<作品名>/`）——默认平铺，可后续加

**自曝风险：**
- 风险1：异步执行壳（goroutine + 进度事件 + 取消）是 V1 生产执行路径，需自建**临时文件清理与崩溃残留兜底**（打包中断遗留的临时 zip 目录）；进任务面板的统一治理（进度/限流/崩溃恢复）因决策1 延后，V1 靠轻量壳承担
- 风险2：多选**跨页选择集合**的内存/状态管理——大库全选时选择集可达万级，跨页保持需 Pinia store 维护 id 集合而非行对象；**后端接收侧形态见决策5**，风险不限于前端
- 风险3：确定性命名的**同名冲突消解**规则（作品目录名/文件名）需定义完备，否则「同输入同输出」不成立、导出结构不可复现
- 风险4：回灌导入排期另做，但 **manifest 契约必须先定稿**——导出格式一旦上线即成为既有产物，不可回灌的导出等于半成品
- 风险5：ZIP 内媒体文件用 store 模式（不压缩）是性能正解，但整包校验（sha256 全算）对大库是额外耗时，需在进度模型里体现
- 风险6：ZIP store 模式（不压缩）**磁盘占用≈源文件+包两倍**——导出前需预检目标盘剩余空间（已绑定阶段3 退出标准）；另导出是**首个批量读「全部活行文件」**的消费侧，RECORD_STATE_TRUTHFUL 既有「记录指向已缺失文件」的悬空窗口会被放大（决策4 的对治对象）

## 一、定位与边界

**导出 ≠ 备份**：backup 模块是「纯文件仓库」，只管把文件收进 `backup/` 保管清单，无业务语义、无元数据（`backend/backup/README.md:8-9` 纯化裁决）。导出是**面向用户的业务功能**：把库中作品（资源文件 + 作品/标签/作者/作品集元数据）打包为可移植产物，是 #51 分享功能的形态基础。

**边界**：
- 导出是业务模块（消费 work/resource/tag/author/workSet 等业务实体），非能力包——不受 MODULE_BOUNDARY_PURITY 纯化约束，可编排业务数据
- 与 localImport 插件的关系：localImport 是「目录→作品」的语义弱导入；导出走「manifest → 作品」的**语义保真**格式，二者是不同档位
- 导入功能本身不在本次范围，但 manifest 契约是本方案的硬约束
- **本次不含任务模块接入**（决策1）：导出以异步 + 进度轻量壳执行

## 二、数据范围（导出什么）

**选择单位（决策2）**：导出选择只作用于作品与作品集，嵌在主视图（作品 tab / 作品集 tab）。语义规则：
- **选作品** → 导出这些作品，标签/作者**完整连带导出**（无选择概念，恒随作品）
- **选作品集** → 导出这些作品集 + 其成员作品（含子作品集，递归闭包）
- **成员关系**：跨选择项的关联保留（选中作品集与其成员作品的归属、成员作品之间的作品集归属）；指向**未选作品集**的成员关系丢弃（选择即单位，不隐式带出未选对象）

每个导出作品需带出：

| 数据 | 来源 | 说明 |
|---|---|---|
| 资源文件 | `persistent_store.file_path` + `resource_store` 活行关联 | 主资源 + 缩略图等全部 store；按 STORE_ASSOCIATION_LIVENESS_FILTER（resource_store 关联按行活性过滤：活行 0..1 + 死行 0..N 按代次，消费侧须判活，见 `.claude/rules/backend.md` 同名规则）只取活行 |
| 作品元数据 | `work` 全字段 | 站点、站点作品ID/名称、作者ID、描述、上传/更新时间、本地作者、lastView |
| 标签关联 | `re_work_tag` + `local_tag`/`site_tag` | 含 namespace 维度、tag 层级（base_local_tag_id）、site_tag 站点侧 namespace；**完整连带导出** |
| 作者关联 | `re_work_author` + `local_author`/`site_author` | 站点作者与本地作者；**完整连带导出** |
| 作品集成员 | `re_work_work_set` | 成员关系 + sort_order/site_sort_order（仅保留跨选择项的关联） |
| 作品集本身 | `work_set` + `re_work_set_work_set` | 作品集层级 DAG、封面引用、双轨排序 |

> 源文件缺失处置见决策4（打包阶段的分支语义）。

## 三、产物形态与 manifest 契约

**ZIP 单包**，内部按**确定性命名的作品目录组织**（决策3）：

```
library-squirrel-export-<时间戳>.zip
├── manifest.json          # 全量元数据（deflate 压缩，体积小）
└── works/
    └── <作品目录名>/           # 确定性命名，作品目录组织
        ├── <文件名>.<ext>      # 保留原 file_name
        └── <文件名>_<role>_<seq>.<ext>   # 同目录同名冲突按 store 命名规约消解（声明8）
```

**确定性命名规则**（风险3 的对治）：
- 作品目录名：`sanitize(siteWorkName)`，为空/冲突时回退 `sanitize(siteWorkId)`，再冲突追加序号 `_2`/`_3`——保证同输入同输出、可复现
- 文件：优先保留 `persistent_store.file_name` 原名；同目录内同名冲突按 `doc/store-naming-convention.md` 的 `<bas>_<role>_<seq>` 消解
- 目录结构承担**人眼可读**，全部语义由 manifest 承担；回灌以 manifest 为主键

**manifest 契约**（回灌硬约束，schema 版本化）：

- `schemaVersion`：int，格式演进用（对齐插件 plugin_data 的版本纪律）
- `meta`：导出时间、来源 app 版本、计数
- `sites[]` / `localAuthors[]` / `siteAuthors[]` / `localTags[]`（含层级引用）/ `siteTags[]`（含 namespace）
- `worksets[]`：全字段 + 层级关系（parent/child 引用）+ 封面引用 + 排序
- `works[]`：work 全字段 + `resources[]`（每个 resource 的 resource_store 挂载：store_type/generation/seq）+ 标签/作者关联（含 namespace）+ 作品集成员关系与排序
- `files[]`：包内相对路径（按第3节确定性规则）+ size + sha256（回灌校验用），被 work 的 store 挂载引用

## 四、入口与交互（主页网格多选接线）

「入口必须醒目」是本待办的硬要求。**多选基建已存在**（声明3：CardGrid 契约 + WorkCard/WorkSetCard 勾选态 + WorkQueryView 接线示范），本方案只需**接线**而非新建：

- **主页接线**：WorkGridForMainPage / WorkSetGridForMainPage 把硬编码 `:checkable="false"` 改为可配置（由 MainView 传 `true`），照 WorkQueryView 的接线模式启用多选
- **选择集合 store**：新建 Pinia store（如 `UseWorkSelectionStore`）维护跨页选中的作品 id 集合与作品集 id 集合（风险2：存 id 集合而非行对象）
- **浮动操作栏**：任一选择非空时主页浮出操作栏——「已选 N 项」+ [导出] primary 按钮 + [清除选择]。导出按钮是首个消费者，操作栏预留未来批量操作位（删除/加入作品集等）
- **明确排除**：侧边栏子菜单、设置页内入口——违背「醒目」要求

## 五、执行形态（本次：异步 + 进度轻量壳）

用户已定任务模块接入**延后**（决策1），本次执行形态为：

- **后台 goroutine**：导出不阻塞 IPC（对齐 longops-task-integration-plan.md 阶段1——合并操作异步化止血——的先例）
- **进度事件**：按「已处理文件数 / 总文件数 + 累计字节」经 Wails 事件通道推送，前端在操作栏/弹窗展示进度条
- **可取消**：前端取消 → 中断打包 → 清理临时文件
- **临时文件治理**（风险1 对治）：打包写临时目录（`os.TempDir()` 或目标盘同级临时名），成功后原子重命名为最终 zip；启动扫描清理残留（对齐 merge 包既有 `ls-merge-` 残留清理先例——`ls-merge-` 是合并临时文件前缀常量，见 `backend/merge/` 的 CleanupResidualTempFiles）

> **延后分支（决策1 后再议）**：任务模块接入——触发 longops-task-integration-plan.md 方向锁 C 的阶段2（下载执行面外提为 `ExecutionStrategy`）+ ExportStrategy + task 加 type 字段 + 面板适配库级叶任务。基本导出验收后再评估是否值得（ZIP 打包无断点续传，「崩溃恢复」对导出只是清临时文件重来）。
