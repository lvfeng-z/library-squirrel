# 插件热重载体系完善方案

## 审查摘要

**关键声明（抽查项）**

- 声明1：热重载链路端到端存在——运行时入口 `app.go` 暴露 Install/Reinstall/Uninstall（`backend/plugin/handler.go:44-69`）；热交换链 = 停旧（`backend/plugin/service.go:544` ReinstallFromPath → `service.go:644` deactivate）→ 装新并立即激活（`service.go:338-353` install → Activate）；前端动态同步（`frontend/src/composables/useSlotSyncListener.ts:493-537`）。
- 声明2：todo#42 根因=注销键位错配。注册事件携带裸 extensionId（`app.go:417` Metadata.ID → `backend/plugin/extension/handler.go:58` Response.ID），注销事件携带复合键 `publicId/extensionId`（`backend/plugin/extension/registry.go:74,89`）；前端 store 以裸 id 注册（`frontend/src/store/SlotRegistryStore.ts:121` 等、`frontend/src/store/HandlerRegistryStore.ts:30`）、以复合键删除（`useSlotSyncListener.ts:525`）→ 全 7 种 kind 的 `Map.delete` 失效；view/replaceView 被 `window.location.reload()` 掩蔽（`useSlotSyncListener.ts:530-535`），resourceViewer 无掩蔽故显形为 todo#42 症状。
- 声明3：前端 CSS 痕迹无换版失效、无注销移除——styleId=`plugin-style-${publicId}` 不含缓存键（`useSlotSyncListener.ts:431`），存在即跳过注入（`:432-435`），全代码库无样式移除调用（grep `removeStyle|plugin-style-` 仅命中注入点）。
- 声明4：卸载清理清单硬编码于 app.go 匿名闭包且不含 taskManager（`app.go:980-984`：loader + 静态资源 + 前端扩展注册三项）。
- 声明5：崩溃清理与显式卸载清理集合不一致——崩溃处理只清 taskHandler/siteBrowser/URL 监听（`backend/plugin/extension/loader.go:481-496`），不触前端扩展注册与静态资源；崩溃检测为惰性（RPC 访问时检查，`loader.go:444-448`）+ keepalive 探活（`loader.go:297`）。
- 声明6：插件进程死亡时任务侧无治理——下载中流断裂转终态失败（`backend/taskManager/model.go:1341-1344`）；CreateWorkInfo/Start 失败经 comboFail 终态失败（`model.go:863-882`、`model.go:904-917`）；优雅暂停基建（softPause + 排空在途数据）已存在（`model.go:1318-1323`）。
- 声明7：`deactivate` 耦合「停止运行时+删除插件文件」（`backend/plugin/service.go:643`），无「只停不删」操作；`SetTrusted(false)` 因此只能改标记等重启（`service.go:592-594`）。
- 声明8：插件数据随重装保留——`plugin_storage` 仅按 key 删除（`backend/plugin/plugin_storage_service.go:80` DeleteValue，无按插件清除）；重装复用同 publicId 记录（`service.go:399`、`service.go:465`）。
- 声明9：任务无自动执行/自动恢复（`backend/taskManager/README.md:38`），暂停后恢复须用户手动触发。
- 声明10：未信任插件在启动扫描与 activatePlugin 入口两处被门控，从不加载（`app.go:316-317`、`app.go:366-367`）。

**决策记录与待决策（需用户拍板）**

- 决策1（已定 2026-08-16）：**运行中有该插件任务的，卸载/重装/更新（换版）一律拦截并显式提醒用户**——不做自动暂停/排空，用户先自行处理任务再操作。stopRuntime 的 PrepareStop 相位由 drain 改为纯否决检查。
- 决策2（已定 2026-08-16）：崩溃路径统一接入参与者清理集合（见『崩溃路径统一』节）。
- 决策3（已定 2026-08-16）：取消信任即时停——`SetTrusted(false)`=即时 stopRuntime（不删文件）。启动/激活路径本就不加载未信任插件（声明10），本决策补齐「运行中转取消信任」缺口；遇运行中任务按决策6 处置（确认后强制停）。
- 决策4（已定 2026-08-16）：**丙**——payload 双字段（`pluginPublicId` + 裸 `frontendExtensionId`，语义对应 manifest 声明层概念），前端摄入点派生复合键作 store 键/路由名，跨引用由同插件 publicId 就地解析；乙出局（终态与丙相同，但把复合键塞进线上契约、与 todo#42 病根「内部 map 键泄漏进事件」同构）。
- 决策5（已定 2026-08-16）：拦截标准统一为「**运行中**」任务，卸载/更新/重装三操作相同；**Paused 任务不拦截**——其随更新存活可续传，随卸载成为僵尸任务的破坏由用户自行承担。
- 决策6（已定 2026-08-16）：取消信任遇运行中任务——确认对话框明示「将失败 N 个运行中任务」，用户确认后强制停。

**自曝风险**

- 风险1：跨版本 Resume（断点续传状态由新旧两代插件进程先后持有）未实测——PluginData 格式由插件 schemaVersion 自管，新版插件对旧续传状态的兼容性无机制保证。决策1 后触达面缩小至两条路径：Paused 任务+更新、启动期捆绑升级遇上次会话 Paused 任务；兜底=Resume 拒绝时任务转失败并提示，不静默不自动迁移。
- 风险2：参与者相位正确性——否决检查必须先于进程停止（PrepareStop → 停进程 → OnStopped 顺序不可乱）；「运行中」的判定需对齐任务状态机（Processing 之外是否含派发中等中间态），标准过窄漏拦、过宽误拦。
- 风险3：键位修复后 reload 掩蔽显形——menu/embed/dialog/siteBrowserList 在不含 view 的插件上此前的残留不可见，修复验证必须覆盖全 7 种 kind，不能只测 resourceViewer。
- 风险4：CSS 注入引入缓存键后，同插件多组件的样式叠加与 scoped 语义（`injectStyle` 的 scopeId 参数）未梳理，存在重复注入或遗漏移除的边界。

## 一、背景与目标

上游任务 E（捆绑插件升级提示流，派生图谱见 `.claude/workflow/active/plugin-identity-version-system/TREE.md`）选定档位③：升级提示的用户答复**当次会话生效**。其前提是热重载体系可靠。核验发现链路端到端存在（声明1），但四处缺口（声明2-4、6）与一处不对称（声明5）。

四缺口共性：**不是能力缺失，是跨模块一致性契约无人拥有**——事件 payload 的 id 语义（声明2）、DOM 痕迹生命周期（声明3）、清理参与者清单（声明4）、任务与停用的协调（声明6）都散落在各处靠约定对齐，约定漂移即漏。

**方向已锁（用户 2026-08-16 认可）：能力分散、契约集中**——编排归发起方（plugin service 生命周期方法，符合 `ORCHESTRATION_BY_CALLER` P0 规则），把三样东西从约定升格为显式契约：参与者清单（注册表）、事件契约（单一拥有者）、前端摄入（对称化）。不建中央 HotReloadManager（违反 ORCHESTRATION_BY_CALLER 与 MODULE_BOUNDARY_PURITY，且漂移发生在契约层而非编排层——todo#42 中 `UnregisterAll` 被正确调用、事件也发出，断在 payload id 语义）。

## 二、方案设计

### 2.1 生命周期参与者注册表（后端，清单集中）

发起方（plugin service）定义接口，提供方实现（`SERVICE_DEPENDENCY_VIA_INTERFACE` 形态）：

```go
// LifecycleParticipant 插件生命周期参与者：凡持有插件运行时痕迹的模块注册为参与者
type LifecycleParticipant interface {
    // PrepareStop 停用/换版前的否决检查（决策1）：如该插件有在途任务则返回 error 拦截本次停用
    PrepareStop(ctx context.Context, pluginPublicId string) error
    // OnStopped 进程已停后的痕迹清理：清注册表、注销静态资源、推送前端注销事件
    OnStopped(ctx context.Context, pluginPublicId string)
}
```

- plugin service 持有参与者注册列表（`RegisterLifecycleParticipant`），替换 `app.go:980-984` 的匿名闭包；现有三项清理（静态资源、前端扩展注册）与 URL 监听清理改为参与者注册。
- loader 保持在编排内作为**进程停止的执行者**（它拥有子进程句柄），不做成参与者——参与者是「被通知方」，进程停止是编排步骤本身。
- taskManager 注册为参与者（PrepareStop=按操作类型检查该插件任务并否决，见 2.4）。
- 效果：审计点收敛为注册表一处；新模块持有插件痕迹时「注册参与者」成为编译可见动作。

### 2.2 生命周期操作拆分（service 层，状态机集中）

`deactivate`（现耦合停止+删文件，声明7）拆为原子操作，生命周期方法由原子操作组合：

| 原子操作 | 内容 |
|---|---|
| `stopRuntime(ctx, publicId)` | 参与者 PrepareStop → loader 停进程（含 Shutdown 优雅关闭，`loader.go:430-433` 已有）→ 参与者 OnStopped |
| `removeFiles(ctx, publicId)` | 删除插件目录文件 |

组合出三个生命周期方法（均运行时可用，即档位③的接入点）：

- `Uninstall`（已有）= stopRuntime + removeFiles + 标记已卸载
- `ReinstallFromPath`（已有，改为内部走 stopRuntime）= stopRuntime + removeFiles + installCore + Activate
- `SetTrusted(false)` 即时停用（决策3）= stopRuntime（不删文件不标记）；遇运行中任务按决策6 处置（确认后强制停）

### 2.3 事件契约统一（todo#42 修复，契约集中）

- 注销/批量注销事件的 payload 与注册事件同源化：`FrontendExtensionUnregisterItem` 改为 `{ pluginPublicId, frontendExtensionId }` 分列，`frontendExtensionId` 与注册事件 Response.ID（裸 extensionId）同语义；payload 结构从 registry 单点生成（`registry.go` 的 Register/Unregister/UnregisterAll 共用一个构造）。
- 前端 `useSlotSyncListener` 保持唯一摄入点：按裸 extensionId 注销两个 store（SlotRegistryStore 六桶 + HandlerRegistryStore 一桶），键位与注册严格对称。
- **定案（决策4·丙）**：注销/批量注销事件的 payload 改为 `{ pluginPublicId, frontendExtensionId: 裸id, kind }`，与注册事件同源化——字段语义对应 manifest 声明层概念（pluginPublicId=哪个插件、frontendExtensionId=其声明的扩展 id）；payload 构造单点化（`registry.go` 的 Register/Unregister/UnregisterAll 共用一个构造）。
- **前端摄入点派生复合键（决策4·丙的核心）**：`useSlotSyncListener` 的 convert 函数统一派生 `slotId = pluginPublicId + "/" + 裸id` 作 store 键与 view 路由名——前端 adopt 后端 registry 内部已验证的复合键约定（`registry.go:42` makeKey），跨插件同名 extension id 碰撞根除。menu→view 跳转由 menu 数据自带的同插件 publicId 就地解析目标复合键（`DynamicSideMenu.vue:93` 路由跳转随之适配）；HandlerRegistry 按 resourceType 查找、不按 slotId 查找，不受影响。
- **对比记录**：甲（统一裸 id）为最小修复但保留既有碰撞隐患，未选；乙（复合键进契约）终态与丙相同，但 `frontendExtensionId` 字段名不副实、跨引用需后端解析期改写、DTO 其他消费者见拼接串，且与 todo#42 病根（内部 map 键泄漏进事件）同构——等于把泄漏合法化，出局。

### 2.4 在途任务拦截（决策1，含决策5/6 分级）

- `stopRuntime` 的 PrepareStop 相位做**纯否决**：taskManager 收到目标插件与操作类型，按分级标准返回错误，错误文案即给用户的显式提醒内容。
- 分级标准：卸载/更新/重装统一拦「运行中」任务（决策5，Paused 不拦截）；取消信任不否决、由确认对话框承担代价告知（决策6）。
- PrepareStop 签名携带操作类型（Uninstall/Update/Untrust）与 force 标志（决策6 确认后强制路径使用）。
- E 档位③的组合方式：提示流征得同意 → 尝试换版 → 被否决则提示「有运行中任务」并引导用户暂停（复用既有任务操作 API）→ 重试换版。F 不内建自动暂停，暂停动作始终由用户发起。
- 跨版本恢复兜底（风险1，决策1 后触达面缩小）：Paused 任务+更新、启动期捆绑升级遇上次会话 Paused 任务两条路径仍可达；新版插件 Resume 拒绝旧状态（schemaVersion 高于支持版本 fail-fast，插件开发规范已有约定）时任务转失败并提示——不静默、不自动迁移。

### 2.5 前端摄入对称化（含 CSS 修复）

- CSS 注入 styleId 引入缓存键：`plugin-style-${publicId}-${cacheKey}`（cacheKey=buildId，资产 URL 已含）；换版时 stopRuntime 触发的批量注销事件先移除旧 style，重装后的注册事件注入新 style，新旧不并存。
- 注销路径按 `pluginPublicId` 移除该插件全部 style 元素（前缀匹配）。
- 全 7 种 kind 的注销验证（风险3）：含无 view 插件（无 reload 掩蔽）场景。

### 2.6 崩溃路径统一（决策2）

`handlePluginCrash`（`loader.go:481-496`）改为调用与显式停用相同的参与者 OnStopped 集合（跳过 PrepareStop——崩溃无法准备）。效果：崩溃后前端扩展注销事件、静态资源清理与显式停用对称，消除声明5 的清理集合分叉。

## 四、测试要点

- 前端：全 7 kind 注销后 store 清空；无 view 插件卸载（无 reload 掩蔽路径）；换版后 CSS/JS 同代（新组件不配旧样式）；**跨插件同名 extension id 并存不互相覆盖**（丙的碰撞根除验证）；menu→view 跳转在复合路由名下正确（含子菜单）。
- 后端：stopRuntime 参与者调用顺序（drain 先于进程停止）；SetTrusted(false) 即时停用；崩溃清理与显式停用清理集合一致。
- 端到端：运行中任务 → 卸载/换版被拦截并显式提醒 → 用户暂停任务 → 换版成功 → 手动恢复续传；Paused 任务 + 更新后恢复；新版 Resume 拒绝旧状态时任务转失败并提示；取消信任即时停用且任务处置符合决策6。

## 五、非目标

- 任务自动恢复（违反「手动触发」原则，声明9）
- 跨版本 PluginData 数据迁移的强制机制（schemaVersion fail-fast 约定已覆盖）
- 完整沙箱、进程内热替换（Go 子进程模型不变）
- 非 bundled 插件网络检查更新（属 E 范畴，本方案只管热重载基建）
