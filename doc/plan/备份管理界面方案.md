# 备份管理界面方案（回收站同组二级菜单）

## 审查摘要

**关键声明（抽查项）**：
- 声明1：侧边栏「一级分组 + children 二级项」是既有模式——标签/作者/站点三组均此形态（frontend/src/composables/useBuiltinMenus.ts:22-46、47-71、88-112），DynamicSideMenu 对 children 零额外改动
- 声明2：回收站现为一级菜单项（order 90，frontend/src/composables/useBuiltinMenus.ts:137-144），对应路由 frontend/src/router/routes.ts:81-86（viewId=recycleBin，组件 frontend/src/views/RecycleBin.vue）
- 声明3：设置页回收站 TTL 分区先例——保留天数输入 + 「启动检查一次 + 每 24 小时」说明文案（frontend/src/views/Settings.vue:572-606）；备份治理保留天数同形态落位
- 声明4：backup 模块当前无 Handler、前端零消费（backend/backup/README.md:24）——「有主/无主」引用状态是业务知识（哪些业务行引用了备份），backup 能力包按 MODULE_BOUNDARY_PURITY 不得感知，数据面须经 backupGovernance 提供
- 声明5：C 方案落地 BackupReferencer 枚举（persistentStore/plugin 各实现 ListReferencedBackupIDs，doc/plan/backup无主备份治理方案.md 3.1 节）——本页面引用状态列复用该枚举，不另起查询通路
- 声明6：状态展示规范——StatusTag 按 status key 渲染、key 与文案集中登记（frontend/src/components/common/StatusTag.vue、frontend/src/constants/StatusRegistry.ts）；有主/无主复用现有 tone 不新增色相

**已裁决（2026-08-21 用户拍板）**：
- 决策1＝一级分组命名「**备份与回收**」（子项：回收站、备份）
- 决策2＝列表**含文件大小列**（逐行 os.Stat，分页 bounded；不参与服务端排序）
- 监视哨联动（2026-08-21 采纳）：页面顶部统计卡片区展示总占用 + 按引用方分组（数量/占用/最老天数，超 90 天观察阈值高亮）——数据来自 C 方案反向对账同源计算（GetBackupStats）

**自曝风险**：
- 风险1：有主备份行不可手动删除（删除仅对无主开放）——用户可能困惑某行为何不可删，行内提示「有主备份由回收站/插件流程管理」
- 风险2：新增 Handler + `wails3 generate bindings -ts` 再生成波及前端类型面（既有流程，无特殊风险，仅工序）
- 风险3：按大小排序需全量 Stat——大小列只展示不排序（决策2 附带约束）
- 风险4：手动「立即巡检」与 24h 定时巡检并发——巡检执行须互斥（单飞锁），避免双跑重复清理
- 风险5：无主状态判定依赖引用方枚举完备（与治理同源结构性风险——未来新增引用方漏登记，GUI 状态与治理同失真，登记义务同受 backend.md 规则约束）

## 一、背景

用户在 C 方案（backup 无主备份治理）审查时提出：为备份模块补 GUI，与回收站放同一个一级菜单下（回收站与备份都变为二级菜单）。C 提供治理后端与引用状态数据面（声明5），本方案是纯消费侧交付。

## 二、设计

### 2.1 菜单与路由

- `useBuiltinMenus.ts`：回收站一级项（order 90）改为**分组项「备份与回收」**（决策1 已裁决）+ children 两项——回收站（order 91，viewId=recycleBin 不变）、备份（order 92，viewId=backupManage，新图标）
- `routes.ts`：新增 `backupManage` 路由（component=views/BackupManage.vue，meta order 92）
- 组件层零改动（声明1 的 children 先例）

### 2.2 IPC 数据面（backupGovernance.Handler，新建）

| 方法 | 作用 |
|---|---|
| `PageBackups(page, pageSize, referenced *bool)` | 分页查保管清单，`referenced` 过滤（nil=全部）；DTO 含 id/fileName/filePath/workdir/createTime/**referenced**/fileSize（os.Stat，决策2） |
| `DeleteBackups(ids)` | 批量删除——**严格守卫**：任一 id ∈ 当前引用集即整体拒绝（错误消息指明有主行）；删除走 backup.DeleteBackup |
| `RunReconciliationNow()` | 手动触发一轮双向对账（与定时巡检互斥，风险4），返回清理统计 |
| `GetBackupStats()` | 占用统计：总占用 / 有主·无主拆分 / 按引用方分组（数量、占用、最老天数，超 90 天高亮——监视哨数据面，C 方案 3.2） |

- DTO 组合遵循 DTO_COMPOSITION_OVER_EMBEDDING（命名字段引用，不嵌实体）
- `wails3 generate bindings -ts` 再生成 + wrapper（frontend/src/apis/http/wrappers/backupGovernance.ts，requireResponse 规范：查询 requireData=true、变更 false）
- 实现注记：① `PageBackups` 的 referenced 过滤把引用 ID 集传入 backup 仓储做 IN/NOT IN——大集合受 SQLite 参数上限约束（旧默认 999），需分块或 int64 字面量拼接（注入安全）；② `GetBackupStats` 全量 Stat 在大库（HDD 数千文件）可达秒级——服务端短 TTL 缓存或异步计算先显旧值

### 2.3 页面（views/BackupManage.vue）

- 布局对齐 RecycleBin.vue 模式（DataTable + 分页 + 操作列）
- 列：文件名 / 保管路径 / 大小 / 保管时间 / 状态（StatusTag：有主→done tone、无主→idle tone；StatusRegistry.ts 登记 backup-referenced / backup-orphaned）/ 操作（删除——仅无主行可用）
- 统计卡片区（页面顶部）：总占用 + 引用方分组摘要（数量/占用/最老天数，超 90 天 tone-warn 高亮）——「回收站保留占 X GB」从隐形容迹变成知情决策
- 工具栏：状态筛选（全部/有主/无主）、「立即巡检」（RunReconciliationNow 后刷新）、「清理全部无主」（danger 确认框 → **仅圈定超保留期的无主，与治理正向判据一致**——防误杀在途还原点/崩溃窗口新孤儿；单行删除不限年龄，页面有保管时间列可判 → DeleteBackups）
- 危险操作按钮 `type="danger"` + tone-fail class（状态色规则）

### 2.4 设置项

- Settings.vue 回收站 TTL 分区旁（声明3 位置）新增「备份治理」：保留天数数字输入（默认 7），经既有 SettingsHandler 读写通道——与 C 方案 settings 段同键（决策2 裁决的可配置保留期）
