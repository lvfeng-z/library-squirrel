- 决策2. 任务创建向导自动接续条件 = 工作目录向导**走完**（非跳过）且结束时工作目录已配置；跳过或走完仍未配置则不接续（常驻横幅兜底）。

**自曝风险（作者没把握 / 可能错的地方）**：

- 风险2. 接续判定依赖「用户在向导输入步保存目录 → `Settings.vue:220` 异步 `refresh()` 已完成」的时序；用户保存后立即点「完成」存在竞态窗口，误判后果为不接续 + 误升横幅（降级可接受），实施时实机锚定。
- 风险3. 向导中心手动重看 workdir-setup 走完也会触发自动接续——以「task-creation 未完成过」为闸门收敛，但重看接续的体验取舍未与用户确认（低风险，跳过成本低）。

## 需求概述

首启引导重构为「先明确警告、再配置、后认识任务创建」的三段独立结构：

1. 首次启动（工作目录未配置且未引导过）时，第一步以居中气泡明确提示「若不配置工作目录，本软件无法正常使用」；
2. 工作目录配置向导（含上述警告步 + 设置页输入框高亮步）与任务创建向导（本地导入/站点下载两个入口步）拆分为两条独立向导；
3. 工作目录向导走完且已配置 → 自动接续任务创建向导；未走完或未配置 → 常驻横幅兜底（既有机制不变）。

## 需求详情

### 功能列表

1. **警告步**：`workdir-setup` 向导首步，无高亮目标（居中气泡，见声明4），标题「重要提示：工作目录」，文案含「若不配置工作目录，本软件无法正常使用」及影响面（资源下载、备份与文件服务均不可用）。
2. **向导拆分**：删除 `first-time` 定义，新增两条：
   - `workdir-setup`「工作目录配置引导」：警告步（route `mainPage`，无 targetKey）→ `settings.workdirInput` 高亮步（保留用户已改的加长版文案，工作区未提交改动合入本方案）；
   - `task-creation`「任务创建引导」：`taskManage.localImportButton`、`taskManage.siteDownloadButton` 两步照搬现文案。
3. **结束原因语义**：向导控制中心区分「走完」（`next` 在最后一步）与「跳过」（`skip`：气泡跳过按钮 / 遮罩关闭 / 向导中心「结束」），暴露 `lastEnded: { tourId, reason }` 供外部编排消费；两者仍同记完成标记（现状语义）。
4. **自动接续**（MainLayout 既有向导结束 watch 处编排）：`lastEnded.tourId === 'workdir-setup' && reason === 'done' && workdirStatus.configured && !isCompleted('task-creation')` → `start('task-creation')`；否则走既有 `onTourEnded()`（升横幅，内部判 configured）。
5. **触发判定键切换**：`applyPulled` 的首启判定从 `tour.completed['first-time']` 改为 `['workdir-setup']`。
6. **存量迁移**（`loadCompleted` 加载时一次性）：`completed['first-time'] === true` 且两新键未标 → 双双置 true、删除 `first-time` 键并持久化一次；幂等（旧键删除后不再命中）。
7. **死代码清理**：删除 `PageUtil.askGotoPage` 中 Settings + extraData 启动 `first-time` 的无生产者分支（声明5）。

### 用户场景

- **全新用户首启**：主页居中警告气泡（明确不可用后果）→ 下一步跳设置页高亮目录输入框 → 用户填写并保存 → 点「完成」→ 自动接任务创建向导（认识两个入口）→ 跳过或走完，横幅不出现（已配置）。
- **跳过警告/向导的用户**：任一步跳过且未配置 → 常驻横幅兜底引导（现状机制）；下次启动因 `workdir-setup` 已标完成不再重弹向导（`wizardAttempted` 会话内防抖照旧）。
- **存量用户（first-time 已完成）**：启动迁移后两新向导均呈已完成，零打扰；向导中心可重置重看。
- **向导中心手动启动**：两条新向导独立可启动/重置；`local-tag-intro` 不受影响。

### 数据模型

- 无数据库实体变更。`settings.tour.completed`（JSON 用户设置内的向导完成标记映射，键=向导 id）发生键演化：`first-time`（退役）→ `workdir-setup` + `task-creation`（新增），迁移规则见功能列表 6。

### API 设计

无新增/变更 IPC。既有复用：`settingsGetSettings`、`settingsSaveSettings`（完成标记持久化与迁移落盘）。

### 边界条件

- **走完但未保存目录**：接续条件判 `workdirStatus.configured === false` → 不接续，`onTourEnded` 升横幅——正确引导（未配置就该挂横幅）。
- **跳过路径**：reason='skip' → 永不接续；未配置则横幅。
- **重复接续**：接续以 `!isCompleted('task-creation')` 为闸门，手动重看 workdir-setup 走完不会反复弹任务向导（风险3）。
- **迁移与持久化竞态**：迁移 persist 只写 `tour.completed` 路径（SettingChange 路径粒度），与向导完成时的 persist 同路径串行（Pinia action 内 await），无覆盖冲突。
- **警告步路由**：首启时当前路由即 `mainPage`，resolveStep 不发生跳转；从向导中心手动启动会先跳主页——与现有向导「启动即跳目标页」行为族一致。
- **旧键残留**：`first-time: false` 形态的残留键无害（loadCompleted 只载入存在的键，迁移只处理 true）。

## 技术方案

### 涉及模块

| 文件 | 改动 |
| --- | --- |
| `frontend/src/tour/definitions.ts` | 删 `first-time`；新增 `workdir-setup`（警告步+输入步）、`task-creation`（两入口步） |
| `frontend/src/store/UseTourCenterStore.ts` | `finish(reason)` 区分走完/跳过；新增 `lastEnded` 状态（start 时清、finish 时写）；`loadCompleted` 存量迁移 |
| `frontend/src/store/UseWorkdirStatusStore.ts` | `applyPulled` 判定键切换 `first-time`→`workdir-setup`；注释同步 |
| `frontend/src/MainLayout.vue` | 向导结束 watch 扩展：接续判定 + 消费 `lastEnded`，否则走 `onTourEnded` |
| `frontend/src/utils/PageUtil.ts` | 删无生产者的 `first-time` 启动分支 |

### 技术要点

- **居中气泡**：`TourStepTarget.targetKey` 留空即居中（声明4），警告步只需 `target: { route: 'mainPage' }`；el-tour 空 target 行为若与文档不符走风险1 备选。
- **结束原因注入点**：`next()` 最后一步调 `finish('done')`、`skip()` 调 `finish('skip')`（含 TourOverlay 遮罩关闭与 TourCenterPanel「结束」两个既有 skip 入口）；`markCompleted` 语义两因共用不变。
- **接续时序**：`finish` 内先写 `lastEnded` 再 `reset()`（isActive 置 idle），MainLayout watch 消费时数据已就位；接续 `start('task-creation')` 使 isActive 回 running，watch 再次进入 true 态，无循环（仅在真变沿触发）。
- **状态新鲜度**：接续判 `workdirStatus.configured`，其新鲜度依赖保存联动 `Settings.vue:220` 的异步 refresh（风险2 竞态窗口，降级路径可接受）。
- **文案**：警告步描述直接使用用户原话语义「若不配置工作目录，本软件无法正常使用——资源下载、备份与文件服务均不可用」；工作目录输入步沿用工作区已改文案（definitions.ts:18 未提交改动）。
