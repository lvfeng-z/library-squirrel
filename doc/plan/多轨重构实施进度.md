### 4.4 transport server 端(`library-squirrel-sdk/transport/plugin_server.go`)
- `Start`/`Resume`:发 WorkResponse chunk → Specs 声明 chunk → 并发读各 reader、按 `role` 发 data chunk → 逐 role EOF chunk
- `streamStoreSpecs`:并发 N goroutine 读 reader,`sync.Mutex` 串行化 `stream.Send`(gRPC server stream 非并发安全),`sync.Once` 捕获首错,`sync.WaitGroup` 等待
- 移除 `GetThumbnail`;`workResponseToProto` 去 resource;加 `storeSpecsToProto`/`protoToTaskResumeParam`/`closeSpecReaders`

### 4.5 传输协议(server→client,**client 端待主程序实现**)
server 端 Start/Resume 流的 chunk 序列:
1. `StreamChunk{WorkResponse}` — 任务级信息(1 条,可选)
2. `StreamChunk{Specs}` — 全部 StoreSpec 元数据(1 条)
3. `StreamChunk{role, Data}` × N — 各轨道数据(并发交错)
4. `StreamChunk{role, Eof}` — 每轨道结束各 1 条
5. `StreamChunk{role, Error}` — 轨道出错时

**主程序 client 端(阶段2 待实现)**:Recv WorkResponse + Specs → 为每个 role 建 `io.Pipe` → 后台 goroutine Recv 循环,按 role 把 Data 写入对应 pipe、Eof 关闭 pipe、Error 关闭 pipe 并传播错误 → 立即返回 `[]*StoreSpec`(每个含 pipe reader + 元数据)。主程序读 reader 时,后台 Recv 持续喂入数据。实现位置:`backend/plugin/extension/`(现有 gRPC client 调用所在)。

## 五、已完成:阶段2 主程序多流化(最高风险)

阶段2 已完成,主程序恢复编译(`CGO_ENABLED=0 go build . ./backend/...` + `go vet` 通过)。实现要点:

### 5.1 plugin/extension client 多流 demux(`task_handler_proxy.go`)
- `Start`/`Resume` 重写为返回 `[]*StoreSpec`:先 Recv `WorkResponse`(可选)+ `Specs`(全部 role 元数据),为每个 role 建 `io.Pipe`,后台 `demuxStream` goroutine 按 `role` 把 `Data` 写入对应 pipe、`Eof`/`Error` 关闭 pipe,立即返回 specs(每个含 pipe reader + 元数据)。
- `Resume` 改用 `TaskResumeParamMessage`(`StreamOffsets` map);`recvSpecsAndDemux` 复用于 Start/Resume。
- 移除 `GetThumbnail`、`grpcStreamReader`(单 reader)、`protoToWorkResponse` 中 `Resource` 映射。

### 5.2 taskManager 多流(`model.go`)
- `streamController{role, generation, format, size, suggestName, continuable, reader, storeWriter, storeId, relPath, written, state}` + `ManagedTask.streams []*streamController`;`streamState`(downloading/completed/paused/failed/canceled)与 `streamResultKind`(OK/paused/canceled/failed)分离。
- `downloadLoop` 每 spec 一个 goroutine 跑 `copyLoop`(read→write→累计);`wg.Wait` 后按 stream 状态聚合:任一 paused → Paused;取消 → Stop 已处理;任一 failed → Failed(保留已完成轨);全部 completed → Finished。进度跨轨汇总(`reportProgress`)。
- `startDownload`:每 spec `StoreStream` + `streamController`,事务内 `saveResource` + `UpdatePendingResourceID`;事务成功后 `abortedByPause` 守卫防 setup 阶段暂停命中事务窗口。
- `saveResource` **双写**:回填旧列(`WorkStoreID`=main / `ThumbnailStoreID`=thumbnail,向后兼容未迁移的 backup/recycleBin/work/search,待阶段6)+ 写 `resource_store` 行(`mountResourceStores`:按 role 删旧插新)。
- `runSectionCombo` 重写:资源板块调 `Start` 取流集合 → `filterSpecsByRoles` 按 storeRoles 过滤 → `startDownload`;**缩略图不再独立板块**,作为 `derived` spec 进流集合;纯 workInfo 走非终态。备份用 `toBackupStoreTypes` 映射 storeRoles。
- **控制面聚合**:`Pause` `close(pauseCh)` 广播 + 插件 Pause 关上游 → 各 stream `handlePause`(drain+Sync+Close+paused);`Stop` cancel + 各 stream abort + `isStopping` 守卫防 EOF 误完成;`prepareForResume` 重建 pauseCh + 关旧 reader。
- `resumeFromPersistedState` 多轨:读 `resource_store` 各轨,按 PersistentStore 状态算 `StreamOffsets`(downloaded 已完成跳过/未完成计偏移/文件缺失 offset=0),`Resume(TaskResumeParam)` 取新 specs,continuable downloaded 用 `ResumeStream` 续接、derived/offset=0 用 `StoreStream` 重建。

### 5.3 接口与依赖
- `TaskExecutor`/`TaskExecutorInterface`:`Start`/`Resume` 返回 `[]*StoreSpec`,`Resume` 取 `*TaskResumeParam`,移除 `GetThumbnail`。
- `TaskDeps`:移除 `ThumbnailStoreWriter`,新增 `ResourceStoreReader`(ListByResourceId)/ `ResourceStoreWriter`(SaveBatch + DeleteByResourceIdAndTypes)。
- `resource_store_repository.go` 新增 `DeleteByResourceIdAndTypes`(事务感知 dbFromCtx)。
- `app.go`:实例化 `ResourceStoreRepository` 并注入 `TaskDeps`。

## 六、已完成:插件升级(pixiv + local)

两个插件 TaskHandler 已升级到新 SDK 接口,`go build` + `go vet` 通过。

**通用改造**:
- `Start` 返回 `[]*StoreSpec`:主资源 `{Role:StoreRoleMain, Generation:GenerationDownloaded, ReadCloser:<下载reader>, Format/Size/SuggestName, Continuable:true}`;缩略图 `{Role:StoreRoleThumbnail, Generation:GenerationDerived, ReadCloser: io.NopCloser(bytes.NewReader(thumbBytes)), Continuable:false}`(无缩略图则不产出)。
- `Resume` 改 `*TaskResumeParam`:仅当 `StreamOffsets[main]` 存在时续传主轨;缩略图(derived)假定已完成不产出。
- 移除 `GetThumbnail`、`ThumbnailResponse`、`TaskResourceDTO`/`WorkResponse.Resource` 引用。
- Resume 契约:插件只返回 StreamOffsets 中存在的 downloaded 轨;main 不在 StreamOffsets = 已完成 → 返回 nil。

**local 插件**(`library-squirrel-plugin-local`):
- `thumbnail.go`:生成器接口与 `generateThumbnail` 改返回 `([]byte, string, error)`,移除 ThumbnailResponse。
- `task_handler.go`:Start 开文件(main downloaded)+ ffmpeg 生成缩略图(thumbnail derived);Resume 重开文件 Seek 到 `StreamOffsets[main]`;移除 GetThumbnail;新增 `boolPtr`/`stripExt`。

**pixiv 插件**(`library-squirrel-plugin-pixiv`):
- `task_handler.go`:Start 用 `pixivRequestFn` 建 RetryReadCloser(main downloaded)+ `fetchThumbnail` 下载 ThumbnailURL(thumbnail derived,失败非致命);Resume 双路径(同进程缓存 reader 探活 / 跨重启新建 + `SetValidBytes(offset)`);移除 GetThumbnail。
- `internal/download/retry_reader.go`:+`SetValidBytes(offset)` 供跨重启续传首请求 Range。

**SDK 附带增强**:`dto/handler_dto.go` +role/generation 契约常量(StoreRoleMain/Thumbnail/...、GenerationDownloaded/Derived),供插件与主程序共用避免魔法字符串。

**设计缺陷修复(Start 透传 storeRoles)**:`Start(task, storeRoles []string)` 把所选 store_type 子集透传给插件,插件(`wantsRole` 助手)**只产出所选 store**(local 不再为未选 thumbnail 跑 ffmpeg、pixiv 不再下载未选缩略图)。根因:多流复用一条 gRPC stream,demux 为每个 role 建 io.Pipe,若插件产出未选 role 且无人消费 → `io.Pipe.Write` 永久阻塞 → 拖死全部轨道(曾致 Redownload 单独 main 时任务卡 Processing)。**Resume 不需要 storeRoles**——其产出完全由 `TaskResumeParam.StreamOffsets` 的 key 集合控制(仅未完成 downloaded 轨入 StreamOffsets,derived 假定已完成不入),故 `TaskResumeParam` 只有 `{Task, StreamOffsets}`。taskManager 仍保留 `filterSpecsByRoles`+`drainUnselectedReaders` 作 Start 路径防御。涉及:proto(StartRequest +storeRoles、TaskResumeParam 不含 storeRoles,reserved 3)、SDK dto/server、主程序 proxy/task_executor/model、两插件 Start。
