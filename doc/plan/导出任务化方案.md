## 审查摘要

**关键声明（抽查项）**
- 声明1：执行面策略机制已落地可用——接口定义 `backend/taskManager/execution_strategy.go:26`（ExecutionStrategy）与 `:69`（StrategyHandle：Task/RunCtx/Finish/Fail/ReportProgress/WaitReplaceConfirm/SetTerminalRollback），策略表 app.go 装配（`app.go:1209-1212`，share-receive 已注册）。
- 声明2：导出执行链现状为 Collect→Plan→磁盘预检→Pack→原子 rename，全在 `backend/export/runner.go:98-173`（Runner.run）；Pack 逐文件循环、每文件开头一个 ctx 取消检查点（`backend/export/packer.go:97-104`）。
- 声明3：内置任务创建后停留 Created、须显式启动（`backend/task/README.md:17`「创建后停留 Created」）；share 先例：建任务后调 `StartTasks`（`backend/share/receive.go:317`）。
- 声明4：发起方经窄接口注入任务创建/启动能力（share 的 BuiltinTaskControl 由 share 模块定义，`backend/share/service.go:59-72`）；export 先于 taskManager 创建（`app.go:901` vs `app.go:1177`），注入须延迟闭包（share 同款时序，`backend/share/service.go:58` 注释）。
- 声明5：前端任务面板已适配内置类型——类型标签映射表 `frontend/src/components/common/TaskList.vue:131-134`（share-host/share-receive 已登记）、操作栏内置类型分支 `frontend/src/components/common/TaskOperationBarActiveV1.vue:104-109`（无板块概念、终态「再次」=重新执行）。
- 声明6：导出前端现状——ExportProgressDialog 承载进度/取消/完成态打开按钮（`frontend/src/components/dialogs/ExportProgressDialog.vue:56,98`），进度链 `MainIpcListener.ts:77` → `useExportProgress.ts`。
- 声明7：临时文件治理现状——目标盘同级 `.zip.tmp`、每次导出前 `sweepStaleTemp(outDir)`、启动清扫工作目录（`backend/export/runner.go:133-144,206-239`）。
- 声明8：进度上报按字节语义（share-receive 先例「进度按字节上报」，`backend/share/README.md:33`；ReportProgress 注释「total/finished 语义与插件任务一致，前端按比值展示」`backend/taskManager/execution_strategy.go:78`）；Pack 进度回调已含 processedBytes/totalBytes（`backend/export/packer.go:38`）。

**待决策（需用户拍板）**
- 决策1（阻塞）：暂停语义取「恢复后全量重跑」——zip 的 central directory 尾写、Go `zip.Writer` 不支持续写已有 zip，手工拼 CD 复杂度与收益不成比例（本地 IO 重打包为分钟级）；代价=暂停恢复后进度回零。替代=真续写（手工维护 zip 条目），不建议。
- 决策2（不阻塞）：完成通知保留 export-events 的 complete 事件（通知带产物路径 + 打开入口），progress 事件退役（进度归任务面板）。替代=事件全退役、产物路径只进任务详情。
- 决策3（不阻塞）：ExportProgressDialog 瘦身为「导出设置确认弹窗」（保留输出目录选择，建任务成功即关闭并提示去任务面板），进度/取消/完成态退役。替代=弹窗全退役、点导出直接弹目录选择器。
- 决策4（不阻塞）：payload 直存 `{schemaVersion, workIDs, workSetIDs, outputDir}`（上限 10000/5000 下 JSON 约 100KB，SQLite 单行可承载）。替代=选中集落盘任务目录再以路径引用（share manifest 先例）。

**自曝风险**
- 风险1：暂停不续传与 share-receive（真续传）语义不一致，用户对「进度回零」可能有预期落差——以任务名/文档说明对冲。
- 风险2：导出长任务占全局信号量槽位（上限来源 `ImportSettings.MaxParallelImport`，`app.go:1178`），大库导出期间挤压下载/导入并发——这正是收敛目的，但属行为变化。
- 风险3：执行面取消返回路径无法区分暂停与停止（契约如此，`execution_strategy.go:20-21`），临时文件在两者下都保留，停止终态后的 `.zip.tmp` 残留依赖「下次导出前 sweep」兜底——残留窗口比现状（取消即清理）变长。
- 风险4：运行中删除导出任务的行为依赖任务模型既有语义（DeleteTask 对运行中任务的处理），本方案不新增处理，需测试锚定实际行为。
- 风险5：前端验收受 vue-tsc 基线既有错误制约，按「改动文件 0 错误」口径验收。

## 一、背景与动机

导出（export）基础功能已实现但走自建「异步轻量壳」（StartExport 起 goroutine + export-events 事件 + CancelExport，`backend/export/runner.go:46-57`），与 merge C 阶段的异步壳同构——耗时操作的控制面正分裂为三种形态（任务面板 / merge 壳 / export 壳）。用户决策（2026-08-28）：尽快将导出接入任务模块，理由是「任务模块的延后已导致导出功能与原任务功能的分离，继续拖延会有更多本应接入的功能产生分离」。

执行面策略机制（ExecutionStrategy）已随 share-receive 落地并全量验证，导出为 IO 打包型操作（产物=文件/循环=打包/进度=字节/恢复=重跑），接入走策略注册、不碰 taskManager 内核（定位重评见 `.claude/workflow/active/longops-task-integration/TREE.md` E 节点）。

## 二、任务建模

- **task_type**：`export`（常量 `TaskTypeExport`，对齐 `share.TaskTypeReceive = "share-receive"` 的命名形态，`backend/share/service.go:53-54`）。
- **粒度**：单任务（pid=NULL、has_child=false 的独立 leaf）。导出是整体动作、产物为单个 ZIP，无法按作品拆子任务独立暂停/续传（对照 share-receive 每作品一子任务：其产物是逐作品独立入库的文件集）。
- **任务名**：`导出（N 项）`，N = 作品数 + 作品集数。
- **payload**（决策4，直存）：`{schemaVersion: 1, workIDs: []int64, workSetIDs: []int64, outputDir: string}`。`outputDir` 存弹窗传入原值（空串 = 执行时取设置默认目录），重试/恢复行为与首次一致。版本自管：高于支持版本 fail-fast 报错（对齐 PLUGIN_DATA_VERSIONING 纪律与 share payload 先例）。
- **无交互、无回滚**：导出不使用 WaitReplaceConfirm（无覆盖确认交互）与 SetTerminalRollback（无软删副作用），执行面只做 Finish/Fail/ReportProgress。

## 三、执行面（backend/export/task_execution.go 新文件，对齐 share/task_execution.go 形态）

`ExportExecution` 实现 `taskManager.ExecutionStrategy`，`Execute(handle)` 流程（自 `Runner.run` 平移，`backend/export/runner.go:98-173`）：

1. 解析 payload（JSON 失败/版本不支持 → `Fail` 用户可读文案）；
2. `Collect(workIDs, workSetIDs)`（幂等读库）；
3. workDir 空校验（→ Fail「工作目录未配置」）；
4. `Plan`（填路径/查源存在性，幂等）；
5. 解析 outDir（payload 值非空则 `MkdirAll`；空则 workDir 根）；
6. `sweepStaleTemp(outDir)` 清残留；
7. 磁盘预检（不足 → Fail 带容量文案）；
8. `Pack` 到 `.zip.tmp`，进度回调转 `handle.ReportProgress(totalBytes, processedBytes)`（字节语义，声明8）；
9. 原子 rename 为最终 zip → `handle.Finish()`。

**错误分流**：错误发生且 `RunCtx.Err() != nil` → 直接 return 不上报终态（控制面接管：暂停→Paused / 停止→Failed「任务被用户停止」，`execution_strategy.go:20-21` 契约）；否则 `Fail(用户可读文案)`（沿用 `ctxErrorMessage` 的取消文案判定思路，但取消路径不上报终态、由控制面落文案）。

**控制语义映射**：
- 暂停：RunCtx 取消 → Pack 文件级检查点退出 → **临时文件保留**（不清理——取消路径无法区分暂停/停止）→ 控制面置 Paused。
- 恢复/重试：重新 Execute 全量重跑（决策1；重跑路径的 sweep 先清自身残留再重写）。
- 停止/失败：控制面置 Failed；`.zip.tmp` 残留由下次导出前 sweep 兜底（风险3）。
- 崩溃：任务行停留运行前状态（重启后手动启动/重试），临时残留由 sweep 兜底——现状机制不变。

## 四、入口与装配

- **Handler.StartExport 改造**：签名不变 `(workIDs, workSetIDs, outputDir)`，语义改为——前置校验（选择非空）→ 序列化 payload → 建任务 → 启动 → 返回 `ExportTaskResult{TaskID int64}`（替代 exportID 字符串）。契约直通：直接改返回类型，不留旧壳兼容。
- **窄接口注入**（ORCHESTRATION_BY_CALLER：发起方定义）：export 侧定义 `TaskLauncher interface { CreateBuiltinTask(ctx, taskType, taskName, payload string) (int64, error); StartTasks(ctx, taskIds []int64) error }`，app.go 以延迟闭包适配器组合 task.Service + taskManager.Manager（share 同款时序处理，声明4）。
- **app.go 策略表**：`map[string]taskManager.ExecutionStrategy{...}` 增加 `export.TaskTypeExport: export.NewExportExecution(...)`（`app.go:1209`）。
- **Runner 退役**：`runner.go` 的 Runner/exportJob/jobs 注册表/Cancel 全删；`run` 主体已平移；`sweepStaleTemp`/`CleanupResidualTempFiles`/`buildExportTargetPath`/`checkDiskSpace` 挪为 ExportExecution 可用（包级函数或其方法）；启动清扫（工作目录）调用点保留接线。
- **Handler.CancelExport 退役**（任务面板停止替代）。
- **emitter 瘦身**（决策2通过则执行）：`ExportEventEmitter` 只留 `PushComplete`（complete 载荷带 taskId + targetPath，供通知与打开入口），`PushProgress` 退役。
