## 一、目标

单轨实施：**声明与执行同步**——每批次表重建挂 FK 子句后，执行开关即处于开启状态（DSN 随批次一落地翻转，此后所有批次 FK 即时生效）。目标效果：三类报错式防线（删除侧漏步骤、写入侧悬空引用、手工误删父行）自各批次落地起生效。

**不用 CASCADE / SET NULL**（既定裁决）：级联代行令删除编排两栖化、静默失效模式、与 fail-fast 风格相斥。外键不覆盖：软删行态过滤、「关联行缺失」类孤儿、跨表行态不变量、文件面一致性。

## 二、机制规则

1. **执行开关**：DSN（backend/database/db.go:29）追加 `_foreign_keys=on`——MaxOpenConns=1 单连接一处全覆盖；不能在事务内切换，DSN 级设置天然规避。
2. **GORM AutoMigrate 不建外键**：实体扁平映射，新库与存量库都经手写迁移补建。
3. **SQLite 无 `ALTER TABLE ADD CONSTRAINT`**：存量表加 FK 须表重建舞步（第四节）。
4. **哨兵判定**：FK 对 NULL 豁免、对 0 不豁免——0 哨兵三列先 NULL 化（批次四，裁决3）。
5. **能力包方向合规**：backup 表自身无业务键；FK 落在业务行侧（persistent_store.backup_id、plugin.backup_id）。
6. **性能**：FK 检查 = 父表主键查找，子列已由既有索引覆盖，热写入路径开销可忽略。

## 四、迁移机制

### 4.1 DDL 来源硬规则

**只以 `sqlite_master.sql` 现表 CREATE 文本为源**，文本注入 FK 子句——禁用实体重建 DDL：实体字段序与表列序会漂移（AutoMigrate 新列尾部 ADD COLUMN vs 实体中置声明），`INSERT SELECT *` 按位对齐，错位且类型兼容时是静默数据损坏。

### 4.2 重建舞步序列

1. `PRAGMA foreign_keys=OFF`——**须在事务外**（事务内为无操作；单连接共享）
2. 舞步可包一个事务：建新表（源 DDL + FK 子句，临时名）→ `INSERT INTO new SELECT * FROM old` → DROP 旧表 → RENAME 为原名
3. **重建全部索引**（旧表索引随表消亡——work/work_set 最重，风险1）
4. `PRAGMA foreign_keys=ON` 恢复（事务外）

RENAME 在 FK OFF 下不改他表 REFERENCES 子句——舞步终名与原名一致，引用照常解析。

### 4.3 幂等标记

SQLite FK 约束无独立命名（`pragma_foreign_key_list` 不含约束名列）——以该视图的 (from 列, 引用表) 对比期望集；新库与存量库同路径补建。

### 4.4 存量清理（各批次伴生步）

执行开启状态下存量悬空行不阻塞读、不阻塞新写入校验，但会阻塞后续父行删除并污染 foreign_key_check 断言——每批次落地时同批执行该批涉及列的悬空清理（`DELETE ... WHERE col IS NOT NULL AND 0 值列同理 ... AND NOT EXISTS (SELECT 1 FROM parent WHERE id = col)` 同构），迁移后 `PRAGMA foreign_key_check` 审计并断言该批表清零。

## 五、cover_work_id 实施详述（裁决2 展开）

**FK**：work_set 重建时挂 `cover_work_id → work(id)` NO ACTION（随批次二）。

**purge 链补步**：`DeleteWorkAndSurroundingData`（backend/work/service.go:488）事务内**首步**增加清封面引用——原生 `UPDATE work_set SET cover_work_id = NULL WHERE cover_work_id = ?`，**必须覆盖已软删集行**（GORM 软删 scope 会排除软删集，而 FK 不分行态，软删集的 cover 引用会拦停 purge）。该函数是 PurgeWork 与 TTL 清理的共同入口，一处覆盖两调用方。

**兜底退役清单**（「默认封面转第一个作品」路径，声明5 锚点）：
- GetCoverWorkId 单集链的判活回退段（backend/workSet/service.go:541 起）
- ListCoverWorkIdsByWorkSetIds 批查的判活兜底（backend/workSet/repository.go:162-164）
- ListMinSortOrderWorkIdsByWorkSetIds 兜底专用查询（backend/workSet/service.go:100；无其他调用方则整方法退役）
- search Phase 2b 的判活后兜底段
- 测试翻转：TestCoverFallbackSkipsDeletedWork（backend/workSet/service_lifecycle_test.go:206-255）退役/改写为「兜底已废弃」的行为锚定
- workSet README 封面节同步

**退役后的行为语义**：
- purge 后：cover 引用被清 → NULL=未设置 → 前端无封面占位（兜底已废弃，不再转投第一个成员）。
- 软删期（作品在回收站）：cover 仍指向软删作品（行存在，FK 合法）→ 封面按该作品解析显示——文件已移 backup/，经 `/store/` 的 backup 服务路径仍可访问（风险3：此链路对作品集封面渲染的覆盖需实机验证；不成立则软删期封面显示空，purge/复原后恢复）。
- 非成员作品的封面（移除成员未清 cover 等）现状即不受兜底覆盖，退役不改变该场景。
