# 续传协议重构方案:Truncate+Write 替代 O_APPEND

> 目标:消除 `O_APPEND` 续传的 TOCTOU 数据损坏风险。
> 核心思路:续传一律 `Truncate(offset)` + `Write`(不用 `O_APPEND`);offset 由主程序 stat 提供(默认),插件可覆盖。

## 协议

**StoreSpec 新增 `ResumeWriteOffset *int64`**(仅 Resume 返回的 spec 使用):

| 值 | 含义 | 主程序行为 |
|---|---|---|
| nil | 插件信任主程序的 offset(StreamOffsets),不知道确切文件大小 | `Truncate(StreamOffsets[role])` + Write |
| 非 nil | 插件知道确切续写位置(可能与主程序不同) | `Truncate(ResumeWriteOffset)` + Write |

**始终 Truncate+Write,不用 O_APPEND。** 两条路径都消除 TOCTOU。

插件推荐返回 nil(信任主程序 stat 的 offset)。仅当插件有更可靠的状态(如自身 validBytes 与 StreamOffsets 不一致)时返回非 nil。

## 改动范围

### SDK
- `dto/handler_dto.go`:StoreSpec + `ResumeWriteOffset *int64`
- `proto/plugin.proto`:StoreSpecMeta + `optional int64 resumeWriteOffset = 7`
- `gen/`:protoc 重生
- `transport/plugin_server.go` + `task_handler_proxy.go`:转换

### 主程序
- `persistentStore/service.go`:`ResumeStream` 改为 `Truncate(offset)` + `O_WRONLY` + `Seek(offset)`(替代 `O_APPEND`)
- `taskManager/model.go` `resumeFromPersistedState`:写入偏移取 `spec.ResumeWriteOffset`(非 nil)或 `streamOffsets[role]`(nil)
- `backend/plugin/extension/task_handler_proxy.go`:proto↔DTO

### 插件
- pixiv/local Resume:返回 nil(信任主程序 offset)——**当前插件无需改动**

## 实施顺序
1. SDK:StoreSpec + proto + gen + transport
2. 主程序:ResumeStream 改 Truncate+Write + resumeFromPersistedState 适配
3. 插件:无需改动(nil = 信任主程序)
4. 验证
