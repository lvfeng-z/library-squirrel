# 分享双机测试·单机替代方案（prod+test 双实例）

## 审查摘要

**目的**：双机环境缺失，用本机两个独立应用实例 + 本地中继模拟双机，跑 K/M/N/L 终审项与分享全链路。

**已核验（带锚点）**：
- 单实例互斥体为固定 ID 阻断双开：`main.go` 原 `const singleInstanceUniqueID` → 已改为按 RootPath 派生 + `LS_INSTANCE_ID` 覆盖（`main.go` `singleInstanceUniqueID()`，净化反斜杠；`deeplink_probe_windows.go` 探针/转发同步改 `()`）。dev 二进制 `bin/library-squirrel.exe` 已重建。
- 双实例共存实测通过（2026-08-31）：`share-recv\library-squirrel.exe`（收件，RootPath=share-recv）与 `bin/library-squirrel.exe`（分享方，RootPath=E:\code 项目根）同时运行不互斥。
- 本地中继：`library-squirrel-relay.exe -config relay-local.json`（`listenAddr: 127.0.0.1:9527`）已启动并监听。
- 收件实例 `share-recv` 就绪：`config/settings.json` 已配 `shareSettings.relayAddress=127.0.0.1:9527`、`workdir=E:\code\lvfeng\share-recv-workdir`。
- 分享方 dev 实例：`config/settings.json` relayAddress 已从 `192.168.5.13:9527` 改为 `127.0.0.1:9527`（备份 `config/settings.json.bak-single-machine-test`）。

**待决策**：测试后 dev 实例 relayAddress 是否还原（当前备份留存，可一键还原）。

**自曝风险**：
- Wails server 模式（`-tags server`）在 Windows 上因 Wails alpha.98 `server`×`windows` 平台文件符号重复**构建失败**——本方案不走 server 模式，用双 GUI 实例替代。
- 深链 HKCU 注册两实例互相覆盖（last-wins）——收件用**粘贴链接**（`ShareReceiveDialog`）规避。
- 后端端口为 Wails 动态分配，双实例实测无冲突；若未来固定端口需配置。
- 测试资源（100MB 大文件等）需用户按清单准备并导入分享方库。

## 角色

| 角色 | 实例 | RootPath | workdir | 说明 |
|---|---|---|---|---|
| 分享方（宿主） | dev 库 `bin/library-squirrel.exe` 或 `wails dev` | `E:\code\lvfeng\library-squirrel` | `D:\LS` | 有真实内容，经本地导入插件入库测试资源 |
| 收件方 | `share-recv\library-squirrel.exe` | `E:\code\lvfeng\share-recv` | `E:\code\lvfeng\share-recv-workdir` | 空库就绪，粘贴链接接收 |
| 中继 | `library-squirrel-relay.exe` | — | — | `127.0.0.1:9527` |

## 前置改动

`main.go`：`singleInstanceUniqueID` 常量 → 函数（RootPath 派生 + `LS_INSTANCE_ID` 环境变量覆盖）。语义：防双开仅针对同 RootPath（同库抢 SQLite），不同库（多库多开、本地双端联调）可并存。`deeplink_probe_windows.go` 两处调用同步改。

## 启动步骤

```bash
# 1. 本地中继（background）
cd /e/code/lvfeng/library-squirrel-relay
./library-squirrel-relay.exe -config relay-local.json

# 2. 分享方（dev 库宿主；RootPath=项目根）
./bin/library-squirrel.exe            # 或 wails dev（开发模式）

# 3. 收件方（复制 exe 到实例目录后运行，RootPath=share-recv）
cp bin/library-squirrel.exe /e/code/lvfeng/share-recv/
cd /e/code/lvfeng/share-recv && ./library-squirrel.exe
```

## 测试流程

1. 分享方发布分享（选择作品/作品集）→ 复制链接（`https://127.0.0.1:9527/s/{token}#k=...`）。
2. 收件方窗口「接收分享」对话框 → 粘贴链接 → 创建 share-receive 父+子任务树 → 逐作品拉取导入。
3. 验证：收件方库出现作品、文件 hash 与源一致、任务树终态；断网/中断重试等按终审项逐项。

## 测试资源清单（用户准备，导入分享方库）

| 资源 | 数量 | 用途 | 说明 |
|---|---|---|---|
| 小 PNG | ≥3 | K1/K3/K4/K5 锁/自指/复原的普通作品 | 也可用 dev 库现有真实作品 |
| **100MB 大文件** | **≥9** | L2 并发流上限 8 压测 | 每文件一个作品（或一作品一 100MB 文件） |
| **同 hash 异名文件对** | ≥1 | M1/M2 替换链触发（确认替换） | 同一文件内容、不同文件名/作品名，各成一个作品 |

经分享方（dev）「本地导入」插件导入 → 形成作品 → 即可发布分享。
