# 站点与作品标识规范（Site Identity Spec）

> 站点跨库身份体系：**site_key 唯一身份 + 站点名纯展示 + 站点侧 ID 复合身份键**。
> 插件开发者据此注册站点、产出稳定站点侧 ID；主程序据此校验站点创建、任务归属、查重、导入与分享接收；导出/分享 manifest 据此携带站点身份。
> 权威实现：SDK `identity` 包（`github.com/lvfeng-z/library-squirrel-sdk/identity`）。本文档为其人类可读说明，注册表条目或键语义改动须同步本文。插件侧上手步骤见 `doc/plugin-dev-guide.md`「站点注册与站点身份」。

## 一、核心定义

| 层 | 标识 | 形态 | 权威来源 |
|---|---|---|---|
| 站点 | `site_key` | 注册表分配的品牌 slug（`^[a-z][a-z0-9-]{1,30}$`，如 `pixiv`）；本库 `site` 表 NOT NULL + 唯一索引 | 中心注册表（SDK `identity` 包，PR 贡献、维护者审定、只增不改） |
| 站点名 | `site_name` | 纯展示列（非唯一）；站点行创建时取注册表权威名，插件自报名被忽略 | 注册表 |
| 作品 | `(site_key, site_work_id)` | 查重与跨库合并的复合键 | 插件产出（须站点侧稳定 ID，见第五节） |
| 站点标签 / 站点作者 / 作品集 | `(site_key, site_tag_id / site_author_id / site_work_set_id)` | 复合身份键——站点侧 ID 为既有字段原样沿用，零新增键 | 插件产出（同稳定性契约） |
| 无站点作品 | 不纳入 | 恒判待建——查重永不命中既有作品，导入/接收必走新建（重复导入会重复建） | — |

- `site_key` 是站点在**所有库、所有版本**中的唯一身份：站点改名、站点行重建，键不变则身份不变。跨库交换（导出/分享）、查重、关联一律按键匹配，**站点名不参与任何身份判定**。
- 复合键的站点侧一律经 `site_key` 解析为本库站点行（`site_key` 唯一索引），再与本库自增 `site_id` 关联——`site_id` 是库内私有主键，永不跨库。
- 站点名理论可同名共存（非唯一列）：权威名由注册表审定者天然去重，残余风险仅注册表笔误，不影响身份正确性。

## 二、注册表（SDK identity 包）

注册表是 SDK `identity` 子包内的一组具名常量——常量即引用（编译期约束）、godoc 即规范：

| 常量 | Key | 权威名 | 主页 |
|---|---|---|---|
| `identity.Pixiv` | `pixiv` | pixiv | `https://www.pixiv.net` |
| `identity.Bilibili` | `bilibili` | bilibili | `https://www.bilibili.com` |
| `identity.Local` | `local` | local | —（本地导入虚拟站点，无主页） |

- **键格式**：品牌 slug——`^[a-z][a-z0-9-]{1,30}$`（小写字母开头，小写字母/数字/连字符，总长 2–31）。键值取站点**官方品牌名的稳定 slug**（如 `pixiv`），不接受变体/近似名（`pixiv2`、`pixiv-official` 一类在合并审查时拒绝）。
- **键与名职责分离**：键是跨库身份（比较键），一经发布**永不跟随站点展示名变化**（品牌更名后键义过时但身份连续，属正确行为）；`Name` 是权威展示名（可随品牌演进而审定更新）。键值与展示名同值时两列并存不是冗余——身份列与展示列职责不同，禁止以「同值」为由合并回按名匹配。
- `Site{Key, Name, Homepage}`：`Key`=唯一身份键；`Name`=权威展示名；`Homepage`=展示主页（虚拟站点为空串）。
- `identity.Lookup(key) (Site, bool)`：按键查条目，未注册（含空键）返回 false——主程序的键校验与站点行创建共用此入口。键按全字符串精确匹配，不解析格式。
- `identity.Local` 是官方捆绑插件 localImport 的落库站点（本地导入虚拟站点），与外部站点同构入表、键分配无差别。
- **插件代码一律引用 `identity.*` 常量，禁止手抄键值字面量**——统一引用防止拼写变体与注册表演进脱节，字面量抄错会静默指向不存在的键而被拒绝（或更糟：指向错误站点）。
- 注册表**只增不改**：已收录条目的键永不重排、永不复用；站点改名只改权威名，键不动。

## 三、站点注册（PR 自助贡献流程）

新站点（注册表未收录的任何站点）在插件首次 `AddSite` 之前须完成注册。流程全程自助，维护者只做查重合并：

1. **选定键值**：取站点**官方品牌名的稳定 slug** 作为键（如 `mysite`），须满足键格式 `^[a-z][a-z0-9-]{1,30}$`（小写字母开头，小写字母/数字/连字符），与站点官方品牌名一致、不与既有条目近似（碰瓷/变体名在合并审查时拒绝）。
2. **提 PR**：向 `github.com/lvfeng-z/library-squirrel-sdk` 的 `identity/registry.go` 常量块增加一个条目，常量名用站点的 PascalCase 标识：
   ```go
   // Mysite <一句话站点说明>。
   //
   // 站点级 ID 约定注记（同站点多插件产出收敛到同一条 norm）：
   //   siteWorkId    = <该站点作品的稳定 ID 是什么>
   //   siteTagId     = <该站点标签的稳定 ID 是什么>
   //   siteAuthorId  = <该站点作者的稳定 ID 是什么>
   //   siteWorkSetId = <该站点作品集的稳定 ID 是什么>
   Mysite = Site{Key: "mysite", Name: "mysite", Homepage: "https://example.com"}
   ```
   **站点级 ID 约定注记**随 PR 一并写明——它是首个接入插件对站点侧 ID 取值口径的权威声明（治理锚点，见第五、六节）。虚拟站点（无真实主页）`Homepage` 留空串。
3. **维护者合并**：合并时查重（键值、常量名不与既有条目冲突，键值与站点官方品牌名一致）后合入。
4. **生效**：注册表随 SDK 发布，主程序随 SDK 更新发布后生效——键校验编译期内置于主程序二进制，主程序不发版则 `AddSite` 恒拒，主程序版本是新站点唯一的生效门（插件升 SDK 可与主程序发版并行，但插件单方更新无效）。新站点从 PR 到可用的时延为「合并 + 下次主程序发布」两步，注册时请预留此窗口（开发期生态仅官方插件、注册与主程序同仓节奏，时延为零）。注册成功的判定：主程序内 `AddSite` 不再报未注册。若未来发版时延成为生态痛点，已记录的延后演进方向为「中心签名的注册表运行时更新包」（维护者签发 + 主程序签名校验，仍是中心签发、非自声明）——当前零需求，不预先建设。

## 四、未注册键的拒绝语义

未注册键在主程序入口被直接拒绝（fail-fast），报错文案即注册渠道指引（指向第三节流程）：

| 入口 | 拒绝点 | 后果 |
|---|---|---|
| 插件 `AddSite` | 键不在编译期内置注册表（`identity.Lookup` miss） | 报错拒绝，该键站点行不落库 |
| zip 导入（manifest 回灌） | manifest `SiteRecord.siteKey` 未注册 | 导入报错终止 |
| 分享接收 | 收件侧走同一 manifest 契约，同上 | 收件报错终止 |

> 上表即站点行写入方的全集：前端手动建站入口已退役——站点行写入方封闭为插件 + 导入两径，注册表校验全覆盖。

任务创建路径同样以键为前提：插件 `Create` 应答必须携带 `siteKey`，主程序按键查本库站点行——键缺失报错、本库无该键站点行（插件未先 `AddSite`）报站点未找到。

已注册键的 `AddSite` 语义：按键查重——本库已有该键站点行则静默跳过；没有则创建，站点名/主页取注册表权威值，插件自报的名称与主页被忽略。

## 五、站点侧 ID 稳定性契约（全族）

复合键的站点侧 ID 全族（`site_work_id` / `site_tag_id` / `site_author_id` / `site_work_set_id`）由插件产出，满足同一契约：

- **必须是站点侧稳定 ID**——站点自身体系中该实体的持久标识（数字 ID、规范 slug、内容哈希等），在同站点的所有插件、所有库、所有时间指向同一实体。
- **禁止**用易变值充当 ID：展示名（可改名）、列表序号（顺序不稳）、URL 临时参数、会话相关 token 等——它们令复合键在重复采集/跨库交换时错位，爆发形态为撞键误合并或查重 miss 重复建。
- 同站点多插件的取值口径收敛到注册表条目的**站点级 ID 约定注记**——各站点当前的权威文本是 `identity/registry.go` 中该常量的 godoc（示例口径：pixiv 的 siteWorkId 取 illust id、siteAuthorId 取作者 user id；具体以 godoc 为准）。
- **运行时不可校验（原理上限）**：宿主只能看到插件报来的字符串，无法验证它是否真是该站点的稳定 ID。这一层的治理不靠运行时校验，靠两处锚点——注册表约定注记（声明口径）+ 插件准入审查（生态门，插件注册/上架时人工审 ID 提取逻辑）；宿主仅能做非空/字符集/长度一类弱格式校验。排查跨库误合并/漏查重问题时，优先核对插件产出与该站点约定注记是否一致。

## 六、治理分层

身份体系各层治理强度不同，须如实分层理解：

| 层 | 强度 | 机制 |
|---|---|---|
| 站点键分配（site_key） | **强** | 注册表编译期内置 + 未注册拒绝——中心化唯一强保证 |
| 站点侧 ID 忠实性（siteWorkId / site_tag_id / site_author_id / site_work_set_id） | **运行时不可校验**（宿主无法验证插件报的 ID 是否站点真正的稳定 ID） | 杠杆三处：①站点级 ID 约定注记（注册表每站点一条权威 norm，同站多插件收敛有锚）；②插件准入审查（生态门，人工审 ID 提取逻辑）；③宿主格式校验（非空/字符集/长度，弱但便宜） |
| 站点标签/作者/作品集的中心化单位 | **命名空间（站点），非实体** | 实体经复合键**继承**站点键的中心化保证——实体本身（百万级、动态、站点自有数据）不枚举注册（不可行且无收益）；站点侧 ID 既有字段原样沿用，零新增键 |
| 本地标签/本地作者层 | 每库私有，不中心化 | 用户自建分类体系，跨库仅经 site↔local 桥接 |

## 七、manifest 契约（导出/分享）

导出与分享的 manifest 以 `SiteRecord` 携带站点身份（契约实现锚 `backend/export/manifest.go`）：

- `SiteRecord.siteKey` **必填**——收件/导入侧按键 find-or-create 本库站点行；未注册键直接报错（第四节）。
- `SiteRecord` 其余站点字段（名称/主页）仅作展示参考，不参与任何匹配。
- manifest `SchemaVersion` 当前为 **2**，版本门为严格相等校验——旧版本（1，站点记录只携带名称）的 manifest 一律拒绝。
