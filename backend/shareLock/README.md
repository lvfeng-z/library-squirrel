# shareLock 模块说明

## 一句话职责

作品锁注册中心：以「作品 ID + 会话引用」两层键的进程内内存表，让"正在被拉取的作品"可被登记、查询与强制放行，供宿主侧替换/删除等操作做并发防护。进程退出状态即消失，无持久化。

## 边界

- 与 `storeRegistry`：同为进程内能力包，但 `storeRegistry` 抑制的是 fsmonitor 事件（键为文件路径），本模块锁定的是作品（键为 workID）。
- 业务中立：只记 workID + 会话引用，不感知分享领域语义、不依赖任何业务实体——"谁在拉取、为何拉取"归调用方（如 share 模块）解释。

## 对外能力（无 Handler，被服务层调用）

| 能力 | 作用 |
| --- | --- |
| `NewShareLockRegistry()` | 创建注册中心（app.go 装配单例） |
| `Register(ctx, workIDs, session)` | 会话开始拉取某批作品时登记引用 |
| `Unregister(ctx, workIDs, session)` | 会话结束/停止时解除本会话引用；未登记组合静默忽略（幂等） |
| `IsLocked(ctx, workID)` | 查询作品是否仍被任一会话持有 |
| `ForceUnlock(ctx, workID)` | 清除作品的全部会话引用（用户知情的强制放行） |
| `ErrWorkLocked` | 守卫命中哨兵错误（「该作品正在被分享拉取中」，errors.Is 可判）——宿主侧防护接线（resource 替换链与 merge overwrite 原轨道置换、recycleBin 复原置换/覆盖转移、work 软删、taskManager 替换确认投递前置）查锁命中时返回，消费方透传前端 |

## 核心概念

- **session（会话引用）**：调用方自定义的会话标识，对注册中心不透明；同一 workID 可被多个会话同时持有。
- **引用集合语义**：每 workID 挂持有会话集合（非计数）——同 (workID, session) 重复登记幂等，单会话解除不误放其他会话，集合清空即解锁。

## 依赖关系

- 依赖：仅标准库（`context`/`errors`/`sync`），无业务模块依赖。
- 被依赖：app.go（装配单例）；宿主侧防护（替换链/回收站查锁，消费方经各自窄接口注入）与分享拉取会话（登记/解除）按需注入。

## 关键设计

- **内存态即语义**：锁的生命周期以进程为界，跨重启自动解除——不持久化是有意设计（重启后无在途拉取，锁无意义）。
- **并发安全**：单 `sync.RWMutex` 保护 `workID → 会话集合` 映射；查询走读锁。
- **不变式**：映射中存在的键其会话集合必非空（`Unregister` 清空集合时同步摘键），`IsLocked` 据此只判键存在。
