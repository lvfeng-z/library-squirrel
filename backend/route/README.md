# route 模块说明

## 一句话职责

插件触发式功能的多候选路由**基座**：把「候选排序 → 逐候选尝试 → 失败二分分发 → 收口两态判定」
四件不变量在单点实现，供各触发面以适配器接入自己固有的候选发现与调用协议。多个消费面若各自
实现同一套路由语义必然漂移，本包是该语义的唯一落点。

## 边界

- 与**各消费面实现包**（task、plugin/extension）：基座只管四个统一不变量；候选怎么发现、怎么
  调用、怎么把调用结果分成三态是**各触发类型固有的协议知识**，归适配器。
- 与 **plugin/extension 域**：本包是纯通用基座，**不感知插件、显选、gRPC、流、任务**等任何协议与
  业务概念；插件相关的一切（激活清单、能力声明、客户端）都在适配器侧。

## 对外接口（无 Handler，供 Go 侧调用）

| 元素 | 作用 |
| --- | --- |
| `Route[C, R](ctx, Adapter[C, R]) (R, error)` | 执行一次路由：零候选返回 `ErrNoCandidates`；候选全部不适配返回 `*AllNotApplicableError`；真失败返回点名并包装原因的错误；首个成功者返回其 `R` |
| `Adapter[C, R]` | 接入契约四方法：`Candidates`（发现候选）、`OrderKey`（候选复合全键，基座按其字典序稳定排序）、`Describe`（点名，用于失败报错与全不适配件清单）、`Invoke`（调用候选并按三态分类） |
| `Outcome` | 单候选调用结果三态：`NotApplicable`（明示不归属，顺延）/ `Failed`（真失败，终止）/ `Succeeded`（成功，首中即胜）——三态为基座既定能力，但当前两个消费面均无不适配生产者（见「核心概念」） |
| `ErrNoCandidates` / `*AllNotApplicableError` | 两类收口错误（`errors.Is` / `errors.As` 判别），调用方据此分报不同文案 |

## 核心概念

- **四不变量**：① 排序——对所有候选按 `OrderKey` 字典序**稳定**排序（键相同的候选保持适配器给出的
  相对序）；② 循环——按序逐个调用；③ 二分分发——`NotApplicable` 记入清单后顺延下一候选，`Failed`
  与未定义态一律按真失败终止并携带 `Describe` 点名，不静默顺延；④ 收口两态——零候选与全不适配
  分报两类错误，不合并成一条笼统文案。
- **显选不进基座**：交互面的「显选候选置首」由适配器折进 `OrderKey`（置首前缀 "0"、其余 "1"）表达，
  基座不含任何显选概念——基座只认「排序键」这一通用原语。
- **三态保留、当前零不适配生产者（有意保留）**：`NotApplicable`（顺延）为基座既定能力，但当前两个消费面
  都不产生不适配——任务创建面 v1 无协议级不适配信号（一切失败皆真失败）；站点作者拉取面改由按插件声明的
  站点归属收窄候选（候选集恒等于归属集，「调用后才知不归属」不复存在）。故 `*AllNotApplicableError`
  收口路径当前不可达，保留供未来带协议级信号的消费面复用。

## 依赖关系

- 依赖：仅标准库（`context`/`errors`/`fmt`/`sort`/`strings`）——纯通用件，无任何项目内依赖。
- 被依赖：`backend/task`（任务创建面适配器 `taskRouteAdapter`）与 `backend/plugin/extension`
  （站点作者拉取面适配器 `siteAuthorFetchAdapter`）——两者当前均只产出 `Failed`/`Succeeded`（无不适配生产者）。

## 关键设计

- **边界护栏（抽象不烂的前提）**：基座**只拥有**排序/循环/二分/收口四件不变量；四件事之外的一切
  ——成功后的落库处理、流式回调细节、作品拉取获取——全留适配器侧。加任何新概念进基座前须先问
  「它是四不变量之一，还是某个消费面的协议细节」。
- **三态分类归接入侧**：哪些错误属「明示不归属」是协议
  知识，基座只消费分类结果、不判别错误内容；当前两消费面均无不适配信号，接入侧恒给 `Failed`/`Succeeded`。
- **泛型双参 `[C, R]`**：候选类型 `C` 与路由结果类型 `R` 均由接入侧决定，基座不预设形态——任务创建面
  的 `R` 是响应对象、站点作者拉取面的 `R` 是空结构体。
